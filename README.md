# DG4000 + SIGLENT SSG + Vaunix + Newport + NI 多设备控制

这是一个面向 RIGOL DG4000、鼎阳 SIGLENT SSG、Vaunix Lab Brick LMS/BLX 信号源、Newport SMC100CC / PR50CC 旋转台与 NI DAQ 的多设备桌面控制程序。首页用于保存和管理多台设备；点击设备卡片后，会打开独立的设备设置窗口，多台设备窗口可同时存在。

**Windows 发行包：** 当前正式版本 [v0.7.25](https://github.com/Rechoncy/Rigol_Generator_GUI/releases/tag/v0.7.25) 提供安装程序 EXE、便携目录 ZIP 和独立 EXE，内置 Python/Qt 与 Python 仪器接口；目标电脑无需安装 Python 或 pip，首次运行无需联网安装依赖。推荐使用安装程序；目录 ZIP 完整解压后，双击其中的 `Lab Control Center.exe` 即可启动。正式附件由对应版本标签构建，实际状态以发布工作流和发行附件 `release-manifest.json` 为准。具体文件、数据迁移、实机驱动及编译方法见 [发行版使用与构建说明](release/README.md)和[0.7.25 发行说明](release/NOTES-0.7.25.md)。

当前源码版本为 **0.7.27 本地修复候选**，完善 DG4000 回读显示：CH1、CH2 各自可在本地选择 Vpp/mVpp，只对已确认的 Vpp 快照进行千倍显示换算；仪器原生 dBm（包括负数）与 Vrms 保留原值和单位。切换只重绘缓存，不访问仪器、不回填编辑参数或保存新控件。本版 60 项针对性、717 项完整源码回归及受控重跑的虚拟自检通过；初次自检的临时配置原子替换异常与验证边界完整记录在[0.7.27 说明](release/NOTES-0.7.27.md)。产物检查以本组实际清单为准；本轮不自动创建标签或 Release，正式下载仍为上面的 v0.7.25。

安装版在发现正式新版后可自动下载、核对大小与 SHA-256，等待设备空闲并正常退出，然后备份用户数据、卸载已登记的旧版、安装新版并核对恢复数据。用户数据位于独立目录，卸载保留数据与升级备份；便携 ZIP 和独立 EXE 继续采用原有手动升级流程。正式附件本地副本使用 `dist/published/v0.7.25/`；原 0.7.25/0.7.26 候选和正式包保留，本轮 0.7.27 候选另行交付，不覆盖旧文件。具体操作见[安装与升级说明](docs/USER_MANUAL_CN.md#45-安装版-exe-与保留数据升级)。

软件图标以波形、采样点和旋转箭头表示信号源、采集与循环扫描。仓库根目录原有的 `Lab Control Center.exe` 是供源码运行的小型启动器，依赖目标电脑的 64 位 Python 3.10+ / PyQt6；它不是上述发行附件。开发者可继续使用它或 `run_app.cmd`。

主分支提交和 PR 会自动运行 Windows 完整回归与虚拟设备自检。检查结果、失败日志及本地复现方法见[自动检查与维护](docs/AUTOMATED_CHECKS_CN.md)。

## 当前已实现

2026-09-09 兼容修复：LMS-802 按 LMS 时间扫频读写，避免误调用 BLX 专用步长接口导致 BAD_PARAMETER；Newport 兼容现场 `SMC_CC - Controller-driver version 3.1.2`，并从 `PR50CC_PN:B2210116_UD:01/10/2021` 提取型号，保留完整标识供显示和记录。更新整个项目后退出厂商控制工具，完全重启本软件再连接。

- 多设备首页：添加、编辑、删除、保存和打开设备。
- 首页设备卡片支持连接和断开；VISA 会话在首页与设置窗口之间共享，关闭设置窗口不会自动断开。
- 添加/编辑设备时自动搜索 VISA 资源或 NI-DAQmx 设备，并通过可编辑下拉框选择；未安装驱动时仍可手动输入。
- 支持 DG4000、鼎阳 SSG、Vaunix LMS/BLX、Newport SMC100CC、NI DAQ 和通用 SCPI 六类设备记录。
- 鼎阳 SSG 基础控制：USB/LAN、频率/功率/RF、仪器原生 STEP/LIST 扫描、独立扫描/点触发、AM/FM/PM/单脉冲、矢量机型命令分支与 IQ 状态回读。使用仪器自己的触发步进，不使用 NI 逐点下发。详见 [鼎阳 SSG 详细使用说明](docs/SIGLENT_SSG_CN.md)和[开发说明与变更记录](docs/SIGLENT_SSG_DEVELOPMENT_CN.md)。SSG3021X / SSG3032X 已加入脉冲 BUS、实际回读及全局触发按钮。已纳入 0.7.0，尚未实机验收。
- Newport PR50CC 循环旋转步进：支持指定初始位置或以启动时当前位置为 P0，提供“使用当前位置 / 移动到 P0”操作。启动保持首点，首个 NI 触发移动到 P1，末点下一触发回跳 P0；运动或稳定期间触发、计数跳增时明确停止，不补跑积压。
- Newport 窗口支持定位、微动、寻机械原点、恢复使能、速度和停止，状态以中文与十六进制码显示；本地状态拒绝会保留可确认的位置，停止未确认时保留占用供显式重试。参数按稳定设备 ID 保存；可由同一旋转任务同时管理 NI 连续模拟采集和计数，保存原始数据与主机观测阶段日志。详见 [Newport 操作说明](docs/NEWPORT_ROTATION_CN.md)。尚未实机验证。
- Newport 扫描页显示实际角度、扫描目标和当前点，提供含绝对角度、相对偏移与执行状态的只读点表；运行中跟随高亮，停止后保留记录，也可读取位置重新预览。
- Vaunix 自动发现：便携 ZIP 和单文件 EXE 内置 Windows x64 `vnx_fmsynth.dll`；源码版也支持主目录或 `lms-sdk` 中的 DLL。枚举真实型号和序列号，并用 `VAUNIX::LMS::<序列号>` 作为稳定资源地址。
- Vaunix 完整控制窗口：当前频率、绝对输出功率、RF、内/外参考、LMS/BLX 扫频、内/外触发、快速脉冲、Chirp、BLX 50 项频率/功率序列、状态位、能力读取和设备非易失设置保存。
- Vaunix 与 NI 联动：频率和功率轴可单独启用，也可同步或笛卡尔组合；首个 NI 边沿下发 P0，随后逐点循环，不设置软件最小触发间隔。
- 本地版本化 JSON 配置和原子写入，防止重复保存同一资源；DG4000、SSG、通用 SCPI 的相同地址也不能跨类型重复新增。旧列表可读取，同地址记录不能同时连接或绕过任务占用。每台设备的可编辑参数自动保存并恢复。
- 首页支持“导出配置 / 导入配置”：一个 JSON 文件保存设备列表、地址、全部设备窗口参数、已保存的单机/跨设备任务和连接恢复列表。导入前校验并自动备份，保留设备 ID；可重新建立备份中的连接，不自动开启输出、移动或运行任务。详见 [配置备份与恢复](docs/CONFIG_BACKUP_CN.md)。
- 后台设备检测；没有安装仪器驱动时，界面仍可正常启动和配置。
- GitHub 软件更新：首页底部手动或自动检查正式 Release，下载对应格式并验证大小与 SHA-256，显示进度、取消和重试；安装版支持下载后自动升级，运行任务时等待，升级前备份数据并在安装后核对恢复。0.7.25 补充 API 限流后的官方清单备用检查与退避，具体状态见本版记录。便携 ZIP/独立 EXE 保留手动迁移方式。
- DG4000 设置窗口：总览、通道与波形、AM/FM/PM/ASK/FSK/PSK/PWM、扫频、脉冲串、触发步进，以及位于“存储与系统”内的双通道负载阻抗和 SCPI 控制台。
- DG4000 “通道与波形”页底部可手动回读 CH1/CH2 的频率、幅度、仪器幅度单位和输出开关，显示回读时间；0.7.27 候选增加各通道的本地 Vpp/mVpp 显示选择，原生 dBm/Vrms 不换算。单位回空的高低电平差兼容仍注明原单位未知，不能据此猜测 dBm。回读结果与待应用编辑值分开，不自动轮询、不修改输出或单位；它是基本波配置快照，不能代替瞬时信号的电气测量。
- 鼎阳 SSG 与 Vaunix LMS/BLX 同样提供独立的频率、绝对功率和 RF 状态回读区；后台手动刷新，失败或断连后旧值失效。项目中的 NI 为采集/计数设备，Newport 为运动控制器；通用 SCPI 未绑定具体型号，不能统一假定其频率/幅度查询命令。各设备回读范围见[使用说明](docs/USER_MANUAL_CN.md#13-各类设备的回读范围)。
- NI 设置窗口：触发输入、计数器、多通道并行模拟电压输入、实时多曲线绘图、连续 CSV/TXT 文本记录、路由和诊断；界面不使用 AO 控制 DG4000。
- 常用数值输入支持单位切换：Hz/kHz/MHz、Vpp/mVpp、V/mV、度/rad、s/ms/us；界面保留小数。DG 类型化幅度命令显式携带 VPP，不受仪器当前 VRMS/dBm 显示单位影响；输出与 PSK 相位校验 0–360°。
- 多轴联合扫描：每个轴独立选择参数、CH1/CH2、单位、起点、步长和点数，可增删及排序。
- 首页“跨设备联动”任务中心：一个 NI 累计触发源可以统一驱动多台 DG4000，每个扫描轴明确选择设备、通道和参数。
- 跨设备任务支持保存、加载和删除，保存内容包含触发配置、扫描轴以及手工修改后的联合点表。
- 跨设备严格顺序屏障：当前联合点的全部设备成功后才增加已完成计数；部分下发失败或途中停止不误计完成。停止前已提交的 VISA 操作不能强制撤回，未开始的后续设备不继续下发。
- 运行期自动保存 CSV 日志，记录触发号、联合点、总耗时、设备耗时、完成偏差和错误；跨设备途中取消以 `partial_stopped` 区分于 `partial_error`。
- DG/Vaunix NI 步进与跨设备停止失败时保留控制器和设备占用，提供“重试停止”；后台启动、监视、写入及 NI 清理全部结束后才允许重新启动或关闭。启动尚在排队时点击停止会保留取消请求，等启动回调结束再清理，旧任务回调不会释放新任务占用。
- 同步联动模式按相同序号组合各轴；笛卡尔模式生成全部参数组合，最后一个轴变化最快。
- DG/Vaunix 循环步进语义：第一个触发应用联合起始点，之后逐点推进，末点后回到起始点。
- 自动生成联合点表，支持正向、反向、零步长和小数步长，也可继续手工增删或编辑点位。可编辑点表与 DG 数值命令保留浮点往返所需数字，避免 100 MHz 附近的微 Hz 差异被固定 12 位有效数字合并；实际仪器分辨率仍按型号。
- 预检重复目标、同步轴点数、联合点总数和过期点表；运行期间锁定扫描配置，防止误改。
- DG/Vaunix 无最小触发间隔模型：`received_count - applied_count` 是有序积压量，不主动丢弃触发；Newport 遇到忙时触发或计数跳增则停止。
- PyVISA 会话：连接/断开、后台命令执行、原始查询和写入、单会话串行化。通用 SCPI 的后台原始命令尚未返回时保留窗口及任务，禁止提前关闭或由首页删除。
- 常用 DG4000 命令已接线：双通道基本波形与输出、调制、扫频、脉冲串和系统命令。
- 完整 SCPI 通道：系统没有屏蔽命令，编程手册中的其他命令可从 SCPI 控制台直接执行。
- NI-DAQmx 累计边沿计数器和双线程联动控制器已实现，频率、幅度、相位、PSK 相位、FSK 频率均可作为步进目标。
- 步进任务具备独立的版本化持久化模型，便于后续在界面中复用任务模板。
- 内置虚拟实验室：自动创建两台虚拟 DG4000、鼎阳 SSG6082A-V、NI、Vaunix BLX-403 和 Newport PR50CC，共六台；无需厂商驱动或实体设备即可体验控制、联动和模拟采集。
- 虚拟 NI 支持单次、批量、连续触发，以及可调正弦、偏置和噪声的多通道模拟输入；虚拟 DG 支持可调 SCPI 延迟、实时状态和积压调试。

没有安装驱动时，硬件操作会给出明确错误，不会假装已经下发命令。当前自动测试使用虚拟设备和协议替身，未验证实体 DG4000、鼎阳 SSG、Vaunix、Newport 或 NI 联动；Vaunix SDK DLL 已在本机完成空设备枚举及隔离 Test Mode 测试。现场仍需验证连接、型号能力、机械稳定时间、PFI 和计数器资源。

## 运行环境

便携发行版使用 Windows 10/11 x64，已包含 Python、PyQt6/Qt、PyVISA、pyserial 和 nidaqmx。日常使用无需安装下列 Python 开发环境；真实仪器所需系统驱动仍需另外安装，详见[驱动说明](release/README.md#4-实机驱动与-python-依赖的区别)。

从源码运行或重新构建时：

- Windows 10/11 x64
- 64 位 Python 3.10 或更高版本
- PyQt6
- DG4000/鼎阳 SSG 实机通信需要 NI-VISA 或其他可用 VISA Backend，以及 Python 包 `PyVISA`；NI 实机控制另需 NI-DAQmx 驱动和 `nidaqmx`。
- Newport 实机控制需要串口驱动和 `pyserial`；安装下述 `.[instrument]` 可同时安装所需 Python 包。
- Vaunix 源码运行需要 Windows x64 `vnx_fmsynth.dll`，可放在项目主目录或仓库内 `lms-sdk-*`，也可通过 `VAUNIX_LMS_DLL` 指定绝对路径。0.7.15 构建脚本将此 DLL 内置到便携 ZIP 和单文件 EXE，实际携带情况以发行清单为准。

> NI 设备资源名以 NI MAX 中显示的名称为准，例如 `Dev1`。软件不依赖用户口述的具体 USB 型号来猜测设备能力，连接后将读取驱动报告的真实产品类型。

## 安装与启动

### 使用安装程序 EXE

从 [v0.7.25 GitHub Release](https://github.com/Rechoncy/Rigol_Generator_GUI/releases/tag/v0.7.25) 下载 `Lab-Control-Center-0.7.25-windows-x64-setup.exe`，正式附件本地副本目录为 `dist/published/v0.7.25/`，内含 Python/Qt 和 Python 仪器接口。安装默认仅针对当前 Windows 用户，程序位于 `%LOCALAPPDATA%\Programs\LabControlCenter`，数据位于 `%LOCALAPPDATA%\RigolGeneratorControl\data`。目标电脑无需安装 Python；真实设备的 VISA、NI-DAQmx、串口或 USB 驱动仍需准备。

安装版首页提供“下载后自动安装（空闲时）”，也可关闭后点击“安装更新”。升级不会强制终止实验：存在扫描、采集、后台通信或未确认清理时，先保留程序与任务；只有正常关闭被接受后才启动安装程序。卸载保留独立用户数据和备份，恢复失败或同名文件内容冲突时保留现场，不能把失败当作升级成功。旧便携版迁移步骤见[使用说明](docs/USER_MANUAL_CN.md#45-安装版-exe-与保留数据升级)。

旧版的更新能力不同：0.7.20 没有联网更新入口，0.7.21 只能提示并打开发布页，0.7.22 可自动下载便携 ZIP 或独立 EXE。首次改用安装版仍需手动运行 Setup，并在向导选择旧版实际使用的 `data/` 或自定义数据目录；已经安装的 0.7.23 及后续安装版才支持后续正式新版自动安装。

### 使用便携发行版

从 [v0.7.25 GitHub Release](https://github.com/Rechoncy/Rigol_Generator_GUI/releases/tag/v0.7.25) 下载便携文件和校验清单。正式发行由版本标签对应的提交构建，生成与验收状态以同组附件 `release-manifest.json` 为准。本地保存的正式发行附件目录为 `dist/published/v0.7.25/`；自行构建的输出目录为 `dist/release/`。本版文件为：

- `Lab-Control-Center-0.7.25-windows-x64-portable.zip`：完整解压后运行 `Lab Control Center.exe`，保留 `_internal/`。
- `Lab-Control-Center-0.7.25-windows-x64.exe`：单文件启动，内置运行时临时解压，持久化配置保存在 EXE 旁 `data/`。

两种格式默认使用 EXE 旁的 `data/`；`--data-dir` 和 `RIGOL_GUI_DATA_DIR` 可以覆盖。迁移时复制程序与 `data/`，用户另选位置的采集文件需一并迁移。旧源码版 AppData 配置不会自动迁移，可用首页“导出配置 / 导入配置”。详见[便携迁移与升级](release/README.md#3-保存迁移与升级)。

### 从源码运行

Windows 迁移源码到其他电脑时，复制整个项目文件夹后双击根目录旧启动器 `Lab Control Center.exe` 或新版快捷方式。启动器依次检查 `LAB_CONTROL_PYTHON`、项目内 runtime/python/.venv/venv 环境、PATH、Python Launcher、注册表及常见 Conda 环境。可用环境必须安装 PyQt6；仪器控制所需 Python 包及 NI-DAQmx/VISA 驱动仍需在目标电脑安装。使用不常见位置的 Python 时，可在该电脑设置 `LAB_CONTROL_PYTHON` 为 `python.exe` 完整路径，无需修改快捷方式。

启动失败会显示错误说明，并保存日志至 `%LOCALAPPDATA%\RigolGeneratorControl\logs\launcher-*.log`。`run_app.cmd` 也使用相同的环境发现与日志流程。启动器源码为 `tools/windows_launcher.cs`，Windows 上运行 `tools/build_windows_launcher.ps1` 可用系统 .NET Framework 编译器重建 EXE，不需要额外安装编译工具。

在项目目录执行：

```powershell
python -m pip install -e .
python -m rigol_control
```

需要实机控制依赖时：

```powershell
python -m pip install -e ".[instrument]"
```

也可以不安装项目，直接从源码启动：

```powershell
$env:PYTHONPATH = "src"
python -m rigol_control
```

源码运行的设备列表默认保存在 `%APPDATA%\RigolGeneratorControl\devices.json`，各设备参数按稳定设备 ID 自动保存在同目录的 `device_parameters.json`；编译发行版默认改为 EXE 旁的 `data/`。参数修改后约 500 ms 自动落盘，关闭窗口前还会强制保存；重新打开时只恢复界面，不会自动向实体仪器下发。开发和测试时可指定独立目录：

```powershell
python -m rigol_control --data-dir .\runtime-data
```

也可以直接双击或在终端中运行（不依赖 PowerShell 脚本执行策略）：

```powershell
.\run_app.cmd
```

## 首次实机配置

1. 在 NI MAX 中确认 DG4000 的 VISA 资源地址可以执行 `*IDN?`，并记下 NI 采集卡设备名（例如 `Dev1`）。
2. 首页分别添加一台 `RIGOL DG4000` 和一台 `NI 数据采集卡`。NI 资源地址填写设备名，而不是 USB 产品描述。
3. 在首页设备卡片点击“连接”，或打开 DG4000 卡片后在“总览”页连接。成功后设置窗口会显示 `*IDN?` 返回值；两处复用同一个 VISA 会话。类型化设置命令使用 5 秒 VISA 超时，只有发生实际 I/O 错误时才自动重建会话并重发当前幂等设置一次；正常下发和 NI 触发路径不增加固定间隔，手动原始命令不会自动重发。
4. 在“通道与波形”等页面配置普通输出；在“存储与系统 → 输出负载阻抗”设置 CH1/CH2 负载，默认均为 50 Ω，也支持高阻、75 Ω、600 Ω及 1–10000 Ω 自定义值，对应 `:OUTP<n>:LOAD`。负载只在点击其应用按钮时下发，修改波形不会重写它。编程手册的任意其他功能可在同页 SCPI 控制台执行。
5. 进入“触发步进”，配置 NI 设备、计数器、PFI 和边沿；为轴 1 选择参数、通道、单位、起点、步长和点数，需要联动其他参数时点击“增加扫描轴”。
6. 选择“同步联动”或“组合扫描”，通过预检后点击“生成联合点表”；表格仍可手工输入小数和非等间隔值。
7. 点击“启动联动”。第一个外部边沿到达前不会下发；第一个边沿到达后才批量写入联合点 1，随后逐点推进并永久循环。
8. 如需独立测量模拟信号，在 NI“模拟输入”页选择实际 `ai` 通道、端接方式、量程和采样率；该采集任务不参与触发步进，也不通过 AO 修改发生器。

## Vaunix LMS/BLX 实机配置

1. 使用发行清单确认内置 DLL 的 0.7.25 安装版、便携 ZIP 或单文件 EXE 时，直接使用内置 SDK 1.15 DLL。源码运行可将 Windows x64 `vnx_fmsynth.dll` 放在项目主目录，或保留仓库 SDK 目录；也可通过 `VAUNIX_LMS_DLL` 指定 DLL。
2. 插入 Vaunix Lab Brick 后，在首页添加 `Vaunix LMS/BLX`；资源下拉框会显示型号、序列号和 `VAUNIX::LMS::<序列号>`。资源身份使用序列号，不依赖 DLL 每次枚举得到的临时设备句柄。首页后台探测只枚举设备，不调用 `fnLMS_InitDevice` 或 `fnLMS_CloseDevice`，不会抢占或关闭正式控制会话。
3. 连接后先在“总览”核对型号、序列号、SDK 版本、频率/功率范围以及 BLX 序列、快速脉冲、Chirp 能力；不支持的功能按钮会被禁用。
4. “射频输出”使用 Hz/GHz 与绝对 dBm；DLL 功率参数以 0.25 dB 为编码单位，但仪器实际功率分辨率为 0.5 dB，软件会拒绝不在 0.5 dB 网格上的输出、序列和扫描值。先保持 RF 关闭，应用低风险参数后再开 RF。
5. “扫频与 Chirp”覆盖 LMS 扫频时间、BLX 点驻留/空闲、方向、重复、双向和外部触发；“脉冲调制”与“BLX 序列”按连接型号能力使用。
6. “NI 触发步进”选择已连接 NI、计数器、PFI 与边沿，配置频率/功率轴并生成循环点表。第一个边沿才下发起点，随后按点表循环；快速边沿按累计计数有序补发。
7. 软件自动保存 Vaunix 界面参数，但重启或重开窗口只恢复界面，不自动写硬件、开启 RF 或启动任务。“状态与存储”的保存按钮会写设备非易失存储，使用前需单独确认。

Vaunix DLL 属于进程级共享 USB 状态，软件对资源搜索、探测、回读和设置使用同一个全局串行锁。正常命令不增加等待；普通幂等设置/读取和停止类命令的 `BAD_HID_IO` 保留最多两次重试。NI 触发点设置、开始扫频、非 STOP 的序列控制和保存设备设置不自动重试，避免未知接受状态下重复执行。持续 USB 错误、`DEVICE_NOT_READY` 或 `INVALID_DEVID` 会释放失效会话，保留具体函数名与状态码；重新连接时按序列号重新发现设备，不直接复用旧句柄。即使关闭失败也会清理本地连接标志。设备回读会检查 CONNECTED/OPENED 位；首页连接状态读取短锁缓存，不等待 SDK 长调用，也不据此证明 USB 仍可达。界面闲置时不持续轮询 USB，拔线状态在下次操作或回读时确认。Vaunix NI 任务发生断开/重连后旧写入器失效，须停止并重新布防。

## NI 模拟输入与数据保存

- 连接 NI 后自动读取驱动报告的模拟输入物理通道；采集端口使用带复选框的可多选下拉列表，支持全选、清空和已选通道摘要。
- 所有勾选通道加入同一个 NI-DAQmx 连续任务，共享硬件采样时钟并行采集；实时图按通道显示独立曲线，文本按通道生成独立电压列。
- 使用 NI-DAQmx 硬件采样时钟连续采集，支持默认、RSE、NRSE、差分和伪差分端接方式。
- 实时波形最多缓存最近 50000 点，并按可调 X 轴时基显示最近窗口；X 轴支持 s/ms/µs 每格，Y 轴可选自动缩放或手动 V/mV 每格及中心值。采集控制器按用户设置保留最多 5000000 点/通道。
- 绘图按像素宽度保留每个区间的峰谷包络，避免高采样率数据堆叠成色块；坐标缩放和显示抽稀只影响画面，不改变连续 CSV/TXT 的原始样本。
- 默认启用连续文本记录：每读取一个 NI 数据块就立即追加到 CSV/TXT 并刷新文件，无需等到停止采集。
- 达到内存上限后只丢弃最早的绘图缓存，并在“保留 / 丢弃”指标中明确计数；已经写入磁盘的完整文本不会被截断。
- 连续文件使用 UTF-8 BOM，包含格式版本、采样率、首样本序号、连续样本序号、时间和各通道电压列；界面同时显示已写入点数和保存路径。
- 0.7.16 的“已写入文本”只在整块写入并成功刷新后增加。写入或刷新失败会明确报告采集错误；失败块可能在文件中留下部分内容，不自动补写或重放，需停止完成后检查文件并选择新路径重新采集。
- “导出缓存 CSV”仅用于另存当前保留窗口，不代表完整连续记录；软件不再提供波形 PNG 保存入口。
- 软件会阻止同一 NI 设备被独立计数、模拟采集和联动任务相互抢占。Newport 旋转任务可在同一个租约内管理 counter 与连续 AI，由 DAQmx 验证资源组合；其他独立任务路径仍互斥。
- NI 独立模拟采集在后台停止。读取线程或 NI/文件清理未结束时保留控制器和设备占用；停止失败可重试，确认清理完成前不能重启采集、关闭窗口或切换到其他 NI 任务。
- 独立 NI 计数和 Newport 旋转联动同样保留清理失败的 NI 任务及设备租约，显式重试完成后再释放；旋转任务显示“重试停止 / 清理”。

若 NI-DAQmx 关闭报错后原生任务句柄已丢失，软件显示“原生清理未确认”并继续保留占用；此时反复点击停止不能确认清理成功。需结束本次实验，在 NI MAX/驱动层核对资源后重新启动软件，不能通过新建同卡任务绕过。

## 联动时序原则

以下首触发与积压规则适用于 DG/Vaunix；SCPI 批次和跨设备细节适用于 DG4000。Newport 支持指定 P0 或使用启动时当前位置，开始扫描保持首点，首触发移动到 P1，末点下一触发回跳 P0；忙时触发或累计跳增时停止，详见 Newport 操作说明。

假设联合点表为 `P0, P1, ... Pn`，每个 `P` 可以包含频率、幅度、相位等多条命令：

- 收到触发 1：下发并保持 `P0`。
- 收到触发 2：下发 `P1`。
- 收到触发 `n+1`：下发 `Pn`。
- 收到触发 `n+2`：重新下发 `P0`，持续循环。
- NI 硬件计数器记录收到的触发总数；DG4000 写入线程记录完成下发的总数。
- 同一联合点的多条 SCPI 命令在同一个受锁批次中按扫描轴顺序写入，其他窗口命令不会插入批次中间；仪器仍是顺序解析，并非电气意义上的绝对同时更新。
- 跨设备任务先按设备拆分联合点，再依次提交设备内命令批次；全部设备完成后才跨过点级屏障并增加完成计数。
- 若某台设备失败，前面设备可能已经改变输出，系统无法通过 SCPI 提供真正事务回滚；任务会标记“部分下发失败”并停止。若 CSV 也写入失败，错误同时保留设备执行情况和日志错误，不将磁盘失败当作尚未写仪器，也不自动重放。
- 跨设备途中停止时，当前正在执行的 VISA 调用须等待返回，之后不再启动剩余设备；尚未全部完成的点记为 `partial_stopped`，不增加完成计数。停止任务不等于关闭仪器输出。
- 停止等待超时或 NI 清理失败不是已停止。保留窗口和设备占用，待后台返回后点击“重试停止”；确认停止完成后，才重新连接、布防或关闭。
- 不设置最小触发间隔。控制器读取的是硬件累计计数，因此两次软件读取之间出现多个边沿时会看到计数跳变，并逐个补齐所有序号；读取周期不是触发死区，也不会合并序列点。
- 若触发速度高于 VISA/SCPI 的实际下发速度，差值形成有序积压；参数仍按触发顺序补发，但物理生效时刻会相对触发滞后。积压不会凭空提高 DG4000 的 SCPI 吞吐量。

触发步进的目标命令包括：

| 参数 | SCPI 模板 |
|---|---|
| 输出频率 | `:SOUR1:FREQ <value>` |
| 输出幅度 | `:SOUR1:VOLT <value>VPP` |
| 输出相位 | `:SOUR1:PHAS <value>` |
| PSK 调制相位 | `:SOUR1:MOD:PSK:PHAS <value>` |
| FSK 跳跃频率 | `:SOUR1:MOD:FSK:FREQ <value>` |

项目内的 `DG4000_ProgrammingGuide_CN.chm` 与 `lms-sdk-*` 中的 Vaunix Windows API PDF 都是原始厂商手册，程序只读取其规范，不会修改这些文件。
