## 2. 项目边界

### 2.1 当前目标

- 在一个首页中保存、连接和管理多台 DG4000、鼎阳 SIGLENT SSG、Vaunix LMS/BLX、Newport SMC100CC / PR50CC、NI DAQ 与通用 SCPI 设备。
- 为每台设备打开独立设置窗口，通过连接管理器共享已建立的设备连接。
- 覆盖 DG4000 常用功能，并保留原始 SCPI 控制台作为完整手册命令入口。
- 通过鼎阳自身的 STEP/LIST 和两级触发执行扫描；支持扫描与允许的调制并用，以及 SSG3021X / SSG3032X 脉冲 BUS。
- 使用 NI 硬件累计边沿计数触发 DG4000 参数步进，不使用 NI AO 电压控制信号发生器。
- 支持频率、幅度、相位、PSK 相位和 FSK 频率的单机或跨设备多轴循环扫描。
- 支持 NI 多通道硬件定时模拟输入、实时绘图和连续 CSV/TXT 文本记录。
- 通过 Vaunix Windows SDK 1.15 完整控制 LMS/BLX，并用 NI 累计边沿驱动频率和绝对功率联合扫描。
- 用 NI 外部触发推进 Newport PR50CC 小角度循环扫描，保持首点并在末点下一触发回跳；可在同一任务内记录连续模拟输入。
- 通过版本化配置包迁移设备、参数、保存任务和连接恢复列表，导入不自动开启输出或运动。
- 提供带软件图标的 Windows 启动器，随整个项目目录迁移并发现目标电脑的 Python 环境。
- 在无硬件、无 PyVISA、无 NI-DAQmx 的环境中提供可重复的虚拟联调路径。

### 2.2 非目标和边界

- 软件命令屏障不等于多台仪器的电气同时更新。微秒级同步需要公共硬件触发和仪器端预装载能力。
- `:OUTP<n>:LOAD` 是外部负载匹配/幅度校准设置，不会把 DG4000 输出级的固有源阻抗物理改成任意数值。
- 独立触发和模拟采集窗口仍互斥；新增 Newport 旋转任务可作为同一个租约所有者，在内部管理同卡 counter 与可选连续 AI，启动时由 DAQmx 验证资源组合。
- 当前跨设备模式不提供事务回滚。后续设备失败时，先前设备可能已经更新。
- 当前软件不以 NI AO 代替 VISA/SCPI 参数下发。

## 3. 运行架构

```text
PyQt6 UI
  ├─ 设备中心 / 单设备窗口 / 跨设备任务窗口
  ├─ DeviceConnectionManager（共享连接与设备租约）
  ├─ 任务控制器（触发、跨设备、旋转扫描、模拟采集）
  ├─ 类型化驱动（DG4000、SIGLENT SSG、Vaunix LMS/BLX、Newport、NI counter、NI analog）
  └─ PyVISA / vnx_fmsynth.dll / pyserial / NI-DAQmx / VirtualLab

Windows 启动：Lab Control Center.exe -> tools/launch_app.py -> 本目录 src

本地数据目录
  ├─ devices.json
  ├─ device_parameters.json
  ├─ step_tasks.json
  ├─ linkage_tasks.json
  ├─ run_logs/*.csv
  └─ 用户指定的模拟输入 CSV/TXT

配置迁移：四个配置文件 + 连接恢复列表 -> 带校验和的 JSON 配置包
旋转任务目录：config.json（含点表）/ rotation.csv / 可选原始 AI CSV
```

UI 线程只负责控件状态和提交后台工作。VISA 写入、NI 计数监视和模拟采集均不能在 UI 线程中执行长时间阻塞操作。所有回调到界面的状态必须通过既有提交/信号路径处理。

## 5. 关键运行流程

### 5.1 设备连接与共享

1. 首页从 `DeviceRepository` 读取设备记录。
2. `DeviceConnectionManager.connect()` 按设备类型选择 PyVISA、Vaunix DLL、Newport 串口、NI 探测或虚拟实验室。
3. SCPI 会话以 device ID 缓存，首页和设置窗口通过同一 manager 获取同一会话。
4. 关闭设置窗口不自动断开设备；显式断开或应用退出才释放会话。
5. 设备被任务租约占用时禁止断开或被另一个任务复用。

### 5.2 DG4000 / Vaunix 单设备触发步进

```text
NI 硬件累计计数 -> monitor thread 更新 received_count
                     |
                     v
writer thread 在 applied_count < received_count 时逐个补发
                     |
                     v
触发 1 -> P0，触发 2 -> P1，...，末点后回到 P0
```

监视周期仅决定软件多久读取一次累计计数，不是去抖间隔，也不是触发死区。若两次读取之间发生多个边沿，计数会跳增，写入线程按序补齐每个触发。`backlog = received_count - applied_count`。当 VISA 下发比触发慢时允许积压；积压不改变次序，但物理生效时间会滞后。

### 5.3 跨设备联动

每个扫描目标使用 `设备 ID + 通道 + 参数` 唯一标识。联合点先按设备分组，再按设备首次出现在扫描轴中的顺序串行下发。每台设备内部使用一个受锁 SCPI 批次；只有本联合点的所有设备成功后才增加 `applied_count`。部分失败会写入日志并停止任务，不把该点误记为完成。

当前 `STRICT_SERIAL` 模式重视确定性和可追踪性，不宣称电气同步。运行日志记录触发号、点号、开始/结束 UTC、总耗时、跨设备完成偏差、每设备结果和错误。

### 5.4 NI 多通道连续模拟输入

1. 连接后枚举真实 `ai` 通道，界面用带复选框的下拉列表多选。
2. 所有勾选通道加入同一个 NI-DAQmx 连续任务，共享硬件采样时钟。
3. 读取线程每获得一个 `AnalogInputBlock`，先校验通道、采样率和连续样本序号。
4. 启用连续记录时，数据块立即追加到 CSV/TXT 并在每块后刷新。
5. 绘图和统计只保留用户指定的有限样本窗口；旧显示点可丢弃，磁盘文件不截断。
6. 停止、错误和窗口关闭路径必须关闭 reader 与文件句柄。

### 5.5 Vaunix LMS/BLX 与 NI 联动

1. `locate_vaunix_dll()` 依次检查 `VAUNIX_LMS_DLL`、项目目录、驱动目录和本地 `lms-sdk-*` x64 路径。
2. `VaunixLmsApi.enumerate_devices()` 返回临时 SDK 句柄、型号、序列号和状态；持久化资源只使用 `VAUNIX::LMS::<serial>`。
3. 连接时重新枚举并按序列号匹配，初始化后读取频率/功率范围、快速脉冲、Chirp、BLX 能力和 SDK 版本。
4. 普通控制经类型化方法下发；频率从 Hz 编码为 10 Hz 无符号单位。绝对功率先校验为 0.5 dB 网格，再按 DLL 的 0.25 dB 编码转换为有符号整数。
5. NI 联动复用 `TriggerStepController` 的累计计数、首触发 P0 和有序积压契约；在 Vaunix 驱动内把频率轴映射为 `SetFrequencyEx`，功率轴映射为绝对 `SetPowerLevel`。
6. 启动时原子租用 Vaunix 与 NI；停止、错误和关闭窗口释放。设备端 BLX 序列与软件 NI 逐点联动不得同时运行。

### 5.6 Newport 旋转扫描与可选采集

1. 启动要求 READY；默认读取当前位置为 P0，也可指定初始角度。指定模式需先显式移动到 P0，启动时复核容差与连续稳定；开始扫描不自动归零或移动到其他起点。
2. 首个 NI 边沿移动到 P1，后续边沿依次推进；到达末点后保持，下一边沿绝对定位回 P0，继续循环。
3. READY、位置回读容差和连续稳定时间共同确定到位。运动或稳定期间触发、计数跳增/回退、超时及设备故障会停止任务，不按 DG/Vaunix 的积压规则补跑。
4. 同一任务租用 Newport 与 NI，在内部管理 counter 与可选连续 AI。原始采集数据独立写盘；阶段日志时间为主机观测时间，不能视为逐样本的硬件角度标签。

### 5.7 配置迁移与启动器更新

导出前读取已打开窗口的最新参数；导入先校验版本、校验和、设备与任务引用，再备份并替换四个配置文件。导入恢复连接时不应用参数或启动任务；运行中的任务和后台硬件操作会阻止导入。重启时先恢复未完成的导入事务，再初始化仓库。

迁移时保留整个项目文件夹，并在目标电脑安装运行依赖；旧快捷方式通过 `create_shortcut.cmd` 重建。EXE 直接启动同目录源码，后续 Python 驱动修复同步源码并完全重启即可生效；修改 C# 启动器后才需重编 EXE。

### 5.8 鼎阳原生扫描、调制与 BUS

1. 连接读取身份和实际状态，不应用保存参数、不打开 RF。
2. 扫描 OFF 时配置调制，再准备 STEP/LIST；检查型号、有效点、闭环/IQ 条件，上传并回读参数和完整列表。
3. 启用时再次准备并核对；由仪器处理扫描触发和点触发。单次模式额外执行一次，软件不依赖 NI 逐点下发。
4. 脉冲 BUS 配置先关闭 PULM，验证 BUS 被接受后再启用；触发按钮重新检查实际源/模式/PULM/MOD，仅发一次全局 `*TRG`。
5. 停止扫描与 RF 关闭独立。通信失败置 unknown，已知型号保留租约；重连查询并确认 OFF 后释放。
6. 参数、列表和 BUS 选择随原有设备参数及归档保存，恢复只改变 UI。

完整命令、状态和错误处理见[SSG 开发说明](SIGLENT_SSG_DEVELOPMENT_CN.md)。

## 6. 设计决策记录

### ADR-001：NI 只提供触发和采集，不用 AO 控制 DG4000

状态：已采纳。DG4000 参数必须经 VISA/SCPI 下发。原因是 AO 电压不能完整表达 DG4000 的频率、调制和系统功能，也会引入额外标定关系。

### ADR-002：采用硬件累计计数而非软件边沿事件队列

状态：已采纳。累计计数能保留两次软件读取之间发生的多个边沿。若计数回退，控制器进入错误状态，因为无法再证明触发序号连续。

### ADR-003：不设置软件最小触发间隔

状态：已采纳。系统不主动节流或合并边沿，超出 DG4000 SCPI 吞吐的触发形成可观测积压。实验设计者应根据可接受延迟控制触发速率。

### ADR-004：DG4000 / Vaunix 第一个触发才应用 P0

状态：已采纳，适用于 DG4000 / Vaunix。任务启动仅准备计数器和线程，不预先写入起始点。第一个有效边沿写 P0，随后逐点推进并永久循环。Newport 使用 ADR-015 的保持首点语义。

### ADR-005：跨设备采用点级完成屏障

状态：已采纳。一个点的所有设备成功才提交完成计数。当前实现严格串行，以获得稳定顺序和清晰故障证据。

### ADR-006：磁盘完整流与绘图缓存分离

状态：已采纳。连续 CSV/TXT 是完整实验记录，有限内存只服务实时显示。达到内存上限不允许停止文件写入或改写样本序号。

### ADR-007：设备资源使用显式租约

状态：已采纳。单设备触发、跨设备任务、NI 独立计数和 NI 模拟采集不能静默争抢同一资源。启动应原子获取所需设备，任何停止/异常路径都要释放。

### ADR-008：模拟输入端口采用复选下拉框

状态：已采纳。它在有限空间中支持逐路选择、全选、清空和摘要，同时保证所有通道进入同一硬件定时任务。

### ADR-009：负载阻抗放在“存储与系统”，默认 50 Ω

状态：已采纳，自 0.5.4 起生效。CH1/CH2 界面和虚拟设备默认均为 50 Ω。负载使用独立的 `:OUTP<n>:LOAD` 操作，支持逐通道或同时应用；“通道与波形”批次不再包含 LOAD，避免修改频率、幅度或波形时意外覆盖已经确认的负载。旧的 `configure_channel()` 保留兼容，新的 UI 使用 `configure_waveform_output()`。

### ADR-010：总览状态必须来自共享连接和设备状态，不使用创建时静态文本

状态：已采纳。设备总览保存所有指标标签引用，并由共享 `DeviceConnectionManager` 的状态转换更新。DG4000 连接后异步查询 `:OUTP1?` 和 `:OUTP2?`；界面下发输出命令成功后立即更新对应通道。连接、断开、设备增删和 NI 列表变化会同步到已经打开的设置窗口。读取失败时通道显示“未知”，不得继续显示可能过期的“关闭”。

### ADR-011：设备参数按稳定设备 ID 自动保存，恢复时不自动下发

状态：已采纳。每个设备窗口以 500 ms 周期比较当前参数快照，仅在变化时原子写入 `device_parameters.json`，关闭窗口前再次强制保存。通用控件保存基准数值、显示单位、下拉选择、多选通道、开关和文本；DG 单设备触发扫描额外保存动态扫描轴、顺序及手工点表。重新打开窗口时先恢复界面，再允许用户主动应用或启动任务；恢复过程绝不自动发送 SCPI、启动 NI 任务或改变实体输出。设备删除时同时删除对应参数快照，避免孤立配置误用。

### ADR-012：Vaunix 使用序列号作为资源身份，SDK 句柄只在连接期使用

状态：已采纳，自 0.6.0 起生效。Vaunix `DEVID` 由 DLL 枚举产生，其顺序可能随 USB 插拔变化，不能写入 `devices.json`。资源统一编码为 `VAUNIX::LMS::<serial>`；每次连接重新枚举并按序列号匹配。这样设备参数、窗口和任务租约始终绑定同一台物理设备。

### ADR-013：Vaunix 型号能力来自运行时查询，不以型号字符串硬编码

状态：已采纳。连接后读取频率/功率范围、快速脉冲和 Chirp 能力；BLX 序列能力只由 BLX 系列身份启用。UI 首次显示宽范围编辑器，连接后收紧量程并禁用不支持按钮，驱动层继续做最终校验。虚拟设备选择全功能 BLX-403，用于覆盖所有页面，而非冒充任意实机型号。

### ADR-014：DG4000 频率总上限由 `*IDN?` 型号决定

状态：已采纳，自 2026-08-15 起生效。未连接状态使用全系列最高 200 MHz，确保 DG4202 保存值和预配置不会被原先固定的 160 MHz 截断；连接后从身份字符串提取型号并套用 DG4062=60 MHz、DG4102=100 MHz、DG4162=160 MHz、DG4202=200 MHz。同一能力对象同时约束 CH1/CH2 基本频率、FSK 跳跃频率、原生扫频起止值、单机触发点和跨设备联合点。UI 范围用于即时反馈，驱动层校验是最终类型化命令边界；原始 SCPI 控制台仍不解析命令，以保留型号/固件特有功能。未知型号暂用家族最高值并在界面说明，不能冒充已经识别。

### ADR-015：Newport 保持首点，机械忙时触发明确停止

状态：已采纳。支持当前位置或指定初始角度作为 P0，首边沿移动到 P1，末点下一边沿回到 P0；每次运动后必须满足到位与稳定条件才能接受下一边沿。指定起点时先显式定位，扫描启动只做位置与稳定检查。用户目标触发为 3 Hz、3.3 V，步长绝对值小于 1°，但这些输入不保证实机能在每个周期内完成运动；遇到忙时边沿或累计跳增时停止并记录原因，不补跑积压。该约定是 ADR-002/003 的旋转任务专用处理，DG/Vaunix 行为保持不变。

### ADR-016：控制器版本、旋转台型号和完整标识分别保留

状态：已采纳。VE 用于控制器版本识别，兼容现场 `SMC_CC - Controller-driver version 3.1.2`；ID? 首个下划线前的型号段需匹配 PR50CC。`stage_identifier` 保留包括 PN/UD 的完整标识用于显示和记录，避免将 `PR50CC_PN:B2210116_UD:01/10/2021` 误判为其他型号。错误控制器和相似但不同的型号仍拒绝连接。

### ADR-017：鼎阳使用原生扫描及独立的两级触发

状态：已采纳。用户明确仪器具有触发步进能力，故预装 STEP/LIST 并使用扫描/点触发，不复用 NI 累计计数与软件积压。扫描配置不自动关闭调制；组合按型号与功能条件校验。扫描开关和当前点不足以证明单次完成。

### ADR-018：脉冲 BUS 按型号开放，先回读后启用

状态：已采纳。官方 3000X 用户手册确认 BUS，补齐原软件缺项；普通 6000A 仍保持未开放。BUS 配置回读失败不退回 AUTO，触发前检查仪器实际设置。`*TRG` 为全局事件，不声称只触发脉冲，且失败不自动重发。

### ADR-019：SSG 未知状态不作为停止

状态：已采纳。已知型号通信失效时关闭会话以隔离旧回复，并保留扫描占用；重连不重放输出或启动。确认扫描 OFF 后释放租约。停止与 RF 关闭可排队，但不能打断正在执行的通信。

## 7. DG4000 命令约定

### 7.1 DG4000 SCPI

| 功能 | 命令模板 | 备注 |
|---|---|---|
| 函数 | `:SOUR<n>:FUNC <func>` | SIN/SQU/RAMP/PULS/NOIS/USER |
| 频率 | `:SOUR<n>:FREQ <Hz>` | 内部基准单位为 Hz |
| 幅度 | `:SOUR<n>:VOLT <Vpp>` | 内部基准单位为 Vpp |
| 偏置 | `:SOUR<n>:VOLT:OFFS <V>` | 核对幅度与偏置组合限制 |
| 相位 | `:SOUR<n>:PHAS <deg>` | 内部基准单位为度 |
| 输出 | `:OUTP<n> ON/OFF` | 上电前进行安全检查 |
| 负载 | `:OUTP<n>:LOAD <1..10000\|INFINITY>` | 0.5.4 起独立显式下发，默认 50 Ω |
| PSK 相位 | `:SOUR<n>:MOD:PSK:PHAS <deg>` | 开始步进前先正确配置 PSK |
| FSK 跳频 | `:SOUR<n>:MOD:FSK:FREQ <Hz>` | 开始步进前先正确配置 FSK |

所有数值先由 `units.py` 转为基准单位。类型化 API 只覆盖高频操作；原始 `write()` 和 `query()` 必须保持可用，以覆盖编程手册中型号/固件特有的全部命令。

### 7.2 Vaunix Windows SDK 约定

| 功能 | SDK 调用 | 内部/界面单位 |
|---|---|---|
| 当前频率 | `fnLMS_SetFrequencyEx` / `GetFrequencyEx` | DLL 为 10 Hz；内部 Hz，界面 Hz/kHz/MHz/GHz |
| 绝对功率 | `fnLMS_SetPowerLevel` / `GetAbsPowerLevel` | DLL 编码为 0.25 dB；仪器分辨率和界面步长为 0.5 dB |
| RF 与参考 | `SetRFOn` / `SetUseInternalRef` | 布尔状态 |
| 扫频 | Start/End/Step、SweepTime 或 Dwell/Idle、Direction/Mode/Type/Trigger/Start | LMS 使用总时间，BLX 使用驻留/空闲 |
| 脉冲 | `SetFastPulsedOutput` / `SetUseExternalPulseMod` | 秒；内部选件按能力启用，外部输入独立尝试并保留 DLL 错误 |
| Chirp | Mode/Length/Repeat/ExternalTrigger | 秒；受型号能力限制 |
| BLX 序列 | Element/Start/Count/Dwell/Idle/StartSequence | 最多 50 项，可独立控制频率/功率 |
| 状态与保存 | `GetDeviceStatus` / `SaveSettings` | 保存写设备非易失存储，需用户确认 |

SDK 返回状态必须统一经过 `_check_set_status()`；读取型函数不能把合法的负功率值误判为错误。功率换算保留 `dBm / 0.25 dB` 的 API 编码，但 `_power_units()` 必须先拒绝非 0.5 dB 网格，不能把可编码值误认为硬件可实现值。版本号按 `0xMMmm` 打包，SDK 1.15 表示为 `0x010F`，显示时必须解码为 `1.15`。

## 8. 持久化和输出文件

默认数据目录为 `%APPDATA%\RigolGeneratorControl`，也可用 `--data-dir` 或 `RIGOL_GUI_DATA_DIR` 覆盖。

| 文件 | 版本/格式 | 用途 |
|---|---|---|
| `devices.json` | schema 1 | 设备 ID、类型、名称、资源、连接方式和时间戳 |
| `device_parameters.json` | schema 1 | 按设备 ID 保存全部可编辑控件、单位、通道选择、动态扫描轴和手工点表 |
| `step_tasks.json` | schema 1 | 单设备触发配置、扫描轴和显式点表 |
| `linkage_tasks.json` | schema 1 | NI 触发源、跨设备扫描轴、模式、设备顺序和点表 |
| `run_logs/*.csv` | CSV | 每个跨设备触发的点级和设备级执行证据 |
| 用户选择的 `.csv`/`.txt` | Continuous Analog Input CSV v2 | 完整连续样本、时间和各通道电压 |
| 用户导出的配置包 `.json` | `rigol-control-configuration` schema 1 | 四个配置文件、连接恢复列表及 SHA-256 校验 |
| `.config-import-pending.json` | 导入恢复日志 | 导入被中断后恢复旧配置；由程序管理 |
| 旋转任务 `config.json` / `rotation.csv` | JSON / CSV | 点表、完整设备身份、阶段、触发和完成记录；可附原始 AI CSV |

JSON 保存采用临时文件写入后替换，避免正常保存中途留下半文件。新增必填字段时不要直接破坏旧文件；应提升 `SCHEMA_VERSION`、实现明确迁移或给出可操作错误。

连续模拟输入文件使用 UTF-8 BOM，前五行包含格式、创建时间、采样率、首样本序号和连续记录标记，第六行为 `sample_index, elapsed_s, <channel...>`。通道顺序必须与任务创建顺序一致。

关键回归契约：

- SSG 准备扫描保持 OFF、不改变 RF/MOD；列表完整回读后才能启用。
- SSG3021X 不收到 -V 专用命令；BUS 被拒绝或忽略时不启用脉冲、不回退 AUTO、不发送触发。
- SSG 触发失败不重发；已知型号状态未知时保留占用，重连后确认停止再释放。

- 启动任务前 DG 不应自动收到 P0。
- DG/Vaunix 第一个触发应用 P0，点表结束后循环回 P0。
- DG/Vaunix 快速触发形成积压且最终按序追平。
- Newport 启动保持 P0，首触发移至 P1，末点下一触发回跳；指定起点未就位时不能启动 NI/AI 或隐式移动，忙时触发、计数跳增和超时必须停止。
- Newport 连接接受现场 SMC_CC 版本和带 PN/UD 的 PR50CC 标识；连接/状态刷新不发送运动命令，错误型号继续拒绝。
- 跨设备部分失败不增加完成计数。
- 同一资源不能被两个运行任务占用。
- 多通道采集文件每行列数一致，样本序号无间断。
- 绘图缓存丢弃旧点时连续文本仍完整增长。
- CH1/CH2 负载控件默认 50 Ω；应用波形不得改变已经单独设置的负载。
- DG 与 NI 连接后总览必须显示“已连接”；DG 输出查询和下发后 CH1/CH2 指标必须与真实状态一致。
- DG 窗口先打开、随后添加或连接 NI 时，触发步进下拉框必须动态出现该设备并显示连接状态。
- Vaunix 自动发现必须始终保留虚拟资源；实机资源必须使用序列号而不是 SDK `DEVID`。
- Vaunix 首个 NI 触发应用频率/功率 P0，计数跳变必须完整补发且末点循环。
- Vaunix `-7.5 dBm` 必须编码为 `-30`；`-7.25 dBm` 虽能形成整数编码，但必须在驱动、BLX 序列和 NI 点表预检中被拒绝。
- 不支持快速脉冲、Chirp 或 BLX 序列的型号不得强行下发相关命令。
- LMS 不调用 BLX 的 FrequencyStep / DwellTime / IdleTime；总览回读只依赖基础输出状态。
- 配置恢复保留稳定 ID，损坏包不写入，失败可恢复；导入不自动下发参数、开启输出或移动。
- Windows 启动器在旧目录失效后仍使用新目录源码，不依赖开发机 Python 地址。

## 11. 实机验收清单

1. 在 NI MAX 中确认 DG4000 VISA 资源、NI 设备名、计数器、PFI 和 AI 通道。
2. 对 DG4000 执行 `*IDN?` 和 `:SYST:ERR?`，记录型号与固件。
3. 在输出关闭状态下设置 CH1/CH2 负载，确认默认 50 Ω、75 Ω、高阻和一个自定义值。
4. 修改频率/幅度后再次查询 LOAD，确认没有被波形应用覆盖。
5. 用低风险幅度验证 CH1/CH2 波形、调制、扫频和脉冲串。
6. 用慢速外部触发验证 DG 首边沿 P0、循环顺序和停止行为。
7. 逐步提高触发速率，记录积压、平均下发时延和可接受上限。
8. 跨两台 DG 验证设备顺序、点级屏障、运行 CSV 和断线错误。
9. NI AI 先以低采样率验证四通道，再提高到目标速率并检查文件增长和 CPU/磁盘占用。
10. 长时间采集后检查文件末尾样本序号、列数、停止时关闭状态和可读性。
11. 用本地 x64 SDK 搜索 Vaunix，核对型号、序列号、SDK 1.15、频率/功率范围与能力位。
12. 保持 RF 关闭，验证频率、绝对功率、参考、扫频、脉冲/Chirp/BLX 序列的设置和回读；不支持功能应禁用。
13. 用 NI 单步及批量触发验证 Vaunix 频率/功率同步和组合扫描、首触发 P0、循环、积压与停止释放。
14. 关闭厂商串口工具后连接 Newport，保存 VE / ID? 原始回复，确认 PR50CC、READY、当前位置和速度；先完成只读连接验收。
15. 按 `docs/NEWPORT_ROTATION_CN.md` 验证小角度移动、首点保持、逐点稳定和末点下一触发回跳，再确认 3 Hz 连续扫描能完成运动及稳定；忙时触发必须停止。
16. 在 DAQmx/NI MAX 核对用户所称 USB6364 的实际产品型号、计数器/PFI 和 3.3 V 电气规格；验证同任务 counter + AI 的资源组合与原始数据记录。

17. 按[鼎阳实机验收表](SIGLENT_SSG_CN.md#13-虚拟设备与实机验收)记录 SSG3021X 身份、固件、STEP/LIST、两级触发、脉冲 BUS 与调制并用；用实际波形确认一次触发行为，验证断线和重连不重放。

## 14. 发布和变更管理

建议分支名使用 `codex/<feature>` 或团队约定的功能分支。每次发布按以下顺序执行：

1. 确认工作区只包含本次改动，不覆盖他人未提交内容。
2. 修改实现，并同步虚拟设备和测试。
3. 更新 `pyproject.toml`、`src/rigol_control/__init__.py`、首页版本文本和 PDF 构建脚本中的版本号。
4. 更新 README、用户手册和本开发日志。
5. 运行全量 unittest、无界面 smoke test 和 `git diff --check`。
6. 重拍自动截图，重建 PDF，并逐页目视检查乱码、溢出、截断和错误截图。
7. 在有硬件条件时执行第 11 节验收；无硬件发布必须明确标注实机未验证。
8. 检查 `git diff` 后再提交，提交信息说明用户可见变化与关键兼容决策。
9. 推送功能分支，经审查后合并 main；合并后再次确认 GitHub 默认分支内容和发布产物。

版本号使用语义化意图：补丁版本用于兼容修复和局部 UI/行为完善；次版本用于新增显著功能；主版本用于不兼容的数据、协议或工作流变化。

## 16. 故障定位顺序

### DG4000 无法连接

1. 在 NI MAX/VISA 工具中执行 `*IDN?`。
2. 检查资源地址是否与软件保存值完全一致。
3. 检查 VISA backend、USB/LAN 防火墙和设备远程控制状态。
4. 使用“存储与系统”中的 `:SYST:ERR?` 读取错误队列。

### 负载显示或幅度不符合预期

1. 确认在“存储与系统”点击了对应 CH 的应用按钮。
2. 用 `:OUTP1:LOAD?` / `:OUTP2:LOAD?` 查询仪器当前值。
3. 区分 50 Ω 负载匹配设置与高阻测量端实际终端。
4. 检查示波器输入阻抗、线缆终端和幅度单位。

### 触发收到但 DG 更新滞后

1. 查看 received、applied 和 backlog。
2. 检查一次联合点包含的命令数和设备数。
3. 用虚拟 DG 延迟复现吞吐瓶颈。
4. 降低触发速率或采用仪器端序列；不要用软件最小间隔掩盖积压。

### NI 模拟输入停止或文本不增长

1. 检查设备是否被触发/联动任务租约占用。
2. 在 NI MAX 验证通道、端接方式、量程和采样率。
3. 检查保存目录写权限和磁盘空间。
4. 查看错误状态是否报告样本序号不连续、通道变化或采样率变化。

### Vaunix 搜不到或功能不匹配

1. 确认使用 64 位 Python 与 SDK `x64\Release\vnx_fmsynth.dll`，或设置 `VAUNIX_LMS_DLL` 为明确绝对路径。
2. 运行发现测试确认至少返回 `SIM::VAUNIX_LMS::1`；实机未出现时关闭厂商示例程序并重新插拔 USB。
3. 核对资源中的序列号，而不是记录 SDK 临时 `DEVID`。
4. 连接后查看总览范围和能力；快速脉冲、Chirp、BLX 序列只能按驱动真实报告使用。
5. 功率使用绝对 dBm，不能把 `GetPowerLevel` 的相对衰减语义混入 UI；当前回读使用 `GetAbsPowerLevel`。
6. LMS-802 的 `GetFrequencyStepEx` 报 BAD_PARAMETER 时确认已更新 LMS/BLX 能力分流版本；LMS 只使用扫频时间，总览不依赖 BLX 步长读取。保留其他接口的具体错误码，不笼统忽略 BAD_PARAMETER。

### Newport 已响应但无法识别或扫描停止

1. 关闭 Newport 原软件，核对 COM 端口和控制器地址；保留报错中的 VE 与 ID? 完整回复。
2. 当前识别支持 `SMC_CC - Controller-driver version 3.1.2` 和 `PR50CC_PN:B2210116_UD:01/10/2021`。若相同回包仍被拒绝，先确认启动的项目目录已更新 `src/rigol_control/drivers/newport_smc100.py` 并完全重启。
3. 控制器版本与旋转台身份分别验证；不要为连接成功而跳过 PR50CC 型号检查或写入其他型号配置。
4. 扫描前确认 READY，检查运行目录的 `rotation.csv` 区分忙时触发、累计跳增、超时、限位与设备错误；降低频率或调整步长/稳定参数后重新验收。

### 鼎阳扫描或脉冲 BUS 不符合预期

1. 保存完整 `*IDN?`、固件和错误，核对普通 SSG3021X 分支，勿改名称冒充支持型号。
2. 分别确认 RF、MOD、扫描开关和实际脉冲源/触发，编辑框不代表仪器已接受。
3. 扫描检查 SINGLE 是否执行及两级触发；脉冲检查内部源、BUS、PULM=1、MOD=1。
4. BUS 回读为 AUTO 或 ESR 报错时，视作未成功应用，不反复自动触发；`*ESR?` 读后清除。
5. 失联不代表停止，重连只读状态，必要时面板关闭 RF；确认扫描 OFF 后再释放占用。
6. 具体查询、接口和操作顺序见[鼎阳故障处理](SIGLENT_SSG_CN.md#12-诊断与故障处理)。

### Windows 迁移后快捷方式无法启动

1. 确认复制了整个项目目录，包含 EXE、`src`、`tools`；从该目录运行 `create_shortcut.cmd` 重建旧链接。
2. 直接运行 `Lab Control Center.exe`，读取弹窗和 `%LOCALAPPDATA%\RigolGeneratorControl\logs\launcher-*.log`。
3. 确认目标电脑具备 64 位 Python 3.10+、PyQt6 和所需仪器依赖；自定义解释器位置可用 `LAB_CONTROL_PYTHON` 指定。启动器不自动安装依赖。
