# DG4000 + NI 触发、CH2 隔离及停止恢复核对

主体核对版本：0.7.15（2026-10-23）；只读回读补充：0.7.17 / 0.7.19（2026-10-27）。用户场景为 DG4000 + NI 单参数触发步进；补查扩展到 Vaunix、同地址设备别名、任务回调交接及日志失败。第 2、3 节保留 0.7.12 的优化与模拟基准，第 6 节保留 0.7.13 的停止约定，第 7 节保留 0.7.14 补查，第 8 节记录 0.7.15 参数语义、精度及预检修复，第 10 节记录新增回读边界，第 11 节记录共享连接快速重连后的缓存失效，不将历史结果改写为新的性能测试。

## 1. 触发到下发的实际路径

NI 硬件累计边沿 → 监视线程读取累计数 → 通知写线程 → 按触发序号取点 → 向指定通道写参数 → 写入成功返回后计完成 → UI 读取最新显示。

首个触发应用 P0，以后循环。累计数跳增时每个触发仍按序下发，没有人为最小触发间隔、跳点或只追最新值。两个线程保持检测与 VISA 串行写入分工；界面不会参与决定下一个点。

“完成”表示主机 VISA write 已返回，不代表仪器模拟输出已达到精度或已经稳定。软件没有每点执行 OPC、错误队列查询或物理输出测量，不能将计数差/界面时间视为仪器内部时标。

## 2. 瓶颈与优化

| 环节 | 原行为 | 0.7.12 |
|---|---|---|
| 计数等待 | Event.wait(0.002)，本机实际约 15.5 ms | Windows CPython ≥3.11 使用高分辨率 sleep，请求切片最多 5 ms；本机约 2.24 ms |
| 单参数 | 每点一次 VISA write | 仍为一次，不声称合包能缩短此通信本身 |
| 多参数 | 每个参数一次 write | 点内所有已验证参数组成一条绝对头 SCPI 消息 |
| UI | 每次计数/下发都排队 Qt signal 与文字更新 | 后台仅覆盖最新快照，主线程约 20 Hz 显示 |
| 预检查 | 无通道耦合检查 | NI 启动前一次检查，不放到逐点路径 |
| 错误恢复 | 点设置可能自动重连重发 | 点失败停止、保持未完成；不会在未知接受状态下重放 |

没有修改全局系统计时分辨率或忙等。其他平台及源码 Python 3.10 保留 Event.wait；便携包内置 Python 3.13。操作系统仍可能延迟调度，硬件通信慢于触发时依旧会形成积压。

UI 合并仅影响显示次数；控制器其他观察者仍逐点收到结果；跨设备 CSV 在文件写入正常时逐点保留记录。界面文字不是完整逐点日志，CSV 写入失败后的本点执行情况按第 7.4 节处理。0.7.13 为控制器快照增加递增 revision，并结合任务会话和累计计数过滤迟到快照，避免旧的 RUNNING 覆盖新错误，或把已显示的接收/完成数写回较小值。

## 3. 0.7.12 本机基准（不含实机）

环境为 Windows 11、CPython 3.13.15。原始样本保存在 `dist/verification/0.7.12/`，未连接 NI 或 DG4000。

| 指标 | 原流程均值 | 优化后均值 |
|---|---:|---:|
| 请求 2 ms 的等待调用耗时，150 次 | 15.505 ms | 2.241 ms |
| 单触发至 write 入口，40 次 | 6.928 ms | 1.380 ms |
| 单触发至 write 返回，40 次 | 12.073 ms | 6.705 ms |
| 1 参数点下发，30 次 | 5.269 ms | 5.308 ms |
| 4 参数点下发，30 次 | 20.951 ms | 5.240 ms |
| 8 参数点下发，30 次 | 41.845 ms | 5.380 ms |

下发基准在内存后端为每次 write 模拟固定 5 ms 开销，单触发基准使用真实控制器/驱动/会话加模拟累计计数器。等待调用耗时不是触发延迟；模拟通信不是 USB/LAN 实测。不得按此表推算仪器最高触发速率或模拟输出稳定时间。

## 4. CH2 对 CH1 的核对结果

1. 普通波形、调制及 NI 五类步进参数原来均使用显式 SOUR2/OUTP2，未发现直接写成 CH1。新回归在 CH1 预置非默认状态后分别测试 CH2 频率、幅度、相位、PSK 相位、FSK 频率各 100 个累计边沿，CH1 全状态保持。
2. 原生扫频和脉冲串页面原来固定 SOUR1，确实有误控 CH1 的风险。现在两组各有明确 CH1/CH2 选择，分别持久化；点击后固定目标，异步排队期间修改选择不会改变已提交命令。
3. DG4000 原生耦合可把基准通道的频率/相位/幅度改变带到另一路。仅发送 SOUR2 并不足以保证隔离。0.7.12 在 typed 配置和每次任务布防前查询总耦合，只有确认三项关闭才继续，不自动修改全局开关。
4. 原始控制台可复位或打开全局耦合。现在提交和后台执行时均检查设备租约，并使用 SCPI 事务锁，避免排队命令插入扫描。先停止任务，再执行手动操作。

任务内每个命令都带完整绝对头，如 `:SOUR2:FREQ 2000;:SOUR2:PHAS 90`，分号后不继承另一通道上下文。不发送复位、双通道同相位初始化、输出开关或无关 CH1 参数。显式单通道 OFF 不依赖耦合查询，但界面任务租约仍要求先停止扫描。

## 5. 使用与现场验收

1. 确认旧任务已经停止并退出旧程序，打开 v0.7.15。保留配置或导入，核对各轴的设备、CH2、参数和单位，不以其他页面当前通道推断扫描轴。
2. 仪器上关闭频率、相位、幅度耦合，先保持输出关闭，核对 CH1 已有参数。开启耦合或查询失败时软件会拒绝布防；不会替用户发送全局 COUP OFF。
3. 布防不会提前下发 P0。逐个给 NI 外部边沿，确认首触发 P0、按序循环、CH1 回读不变，再用示波器/频率计确认实际输出稳定性。
4. 查看接收、完成和积压。显示约 50 ms 更新，显示平滑度不能作为硬件延迟；触发过快仍会积压，应按实测吞吐调整触发速率。
5. 保持运行期间仪器面板和其他应用不修改全局耦合、通道波形或状态。软件租约只保护本进程，布防前查询不能持续防止外部改动。外部更改后先停止、重新核对并重新布防，以刷新耦合与波形快照。
6. 确认停止完成后再切换手动设置或执行原始命令。看到“重试停止”时后台或 NI 清理仍未完成，保留窗口和占用，等待后重试。通信失败可能意味着点已部分接受；检查仪器状态后重新布防，软件不会自行重放旧触发。

## 6. 0.7.13 停止与异常边界

### 6.1 停止完成的判据

点击停止只提交取消请求；不代表厂商驱动已经停止执行。完成状态由共享生命周期管理器确认：启动预检查已经返回、监视和写入线程已经退出、NI 计数任务已经关闭，三部分都完成才有 `is_quiescent=true`。错误状态本身不能替代这个判据。

等待超时或 NI 清理失败时，UI 保留原控制器和设备租约，显示“等待停止 / 重试停止”，禁用重新启动并阻止窗口关闭。原调用结束或清理条件恢复后，重试停止可完成剩余清理并释放占用。已执行的 VISA 调用不可强制撤回，停止请求不承诺固定响应时间；停止任务不会自动关闭仪器输出。

### 6.2 启动期间取消

预检查和 NI 打开在后台执行。取消发生在预检查阶段时，返回后不再打开计数任务；取消发生在 NI 启动阶段时，返回后清理计数任务，不创建新的写入线程。取消等待同样在后台完成。

Qt 线程池回调进入 Python 时可能表现为 `_DummyThread`，不能通过 `Thread.join()` 等待它。生命周期使用自己的 Condition 和启动完成标志等待预检查退出，常规监视/写入线程仍等待实际退出。启动已经请求取消后，不因迟到的成功回调恢复任务。

### 6.3 连接重建后重新布防

DG 专用任务写入器保存布防时 SCPI 会话的 `connection_generation`，并在每次下发前、同一事务锁中检查。断开或恢复连接后代次变化，原耦合预检查不再有效，旧写入器会在发送点命令前拒绝。须完成旧任务停止、核对实际仪器状态并重新布防；不能仅凭重新连接成功继续原积压。

这项检查保护本程序中的会话变化，不持续监控其他软件或仪器面板对耦合的修改。保持第 5 节的现场操作约束。

### 6.4 跨设备途中停止与记录

严格顺序模式在下一台设备下发前检查停止请求。例如 DG-A 正在写入、DG-B 尚未开始时点击停止，DG-A 的当前调用仍须等待返回，随后不再写 DG-B。若联合点尚未全部成功，则记录 `partial_stopped`，保留已执行设备的耗时与结果，不增加 `applied_count`；通信失败继续使用 `partial_error`。

若本点全部设备已经成功返回，则可记为 complete；其他未开始的积压点不再发送。任何已被仪器接受的部分都不会被软件回滚，恢复实验前需核对各仪器的实际状态。

### 6.5 输入和快照校验

计数轮询周期须是正的有限数值，拒绝 NaN、Infinity 和非正数。跨设备顺序须包含合法、唯一且与参与写入器一致的设备 ID，空顺序或重复 ID 在运行前拒绝，避免漏发或重复执行。快照 revision、任务会话及计数共同约束显示顺序；状态显示的合并不会删掉控制器执行或 CSV 逐点记录。

## 7. 0.7.14 任务交接、资源别名与日志补查

### 7.1 排队启动与停止回调

DG/Vaunix 启动操作尚未在线程池执行、仍在预检查或等待回调时，点击停止只登记取消。等对应启动 CallTask 确认完成后才派发停止任务，避免先清理后又执行旧启动的次序错误。启动完成、错误和停止完成回调均绑定提交时的 controller/task 身份；迟到的旧回调不能清空新控制器或释放新租约。

Vaunix 手动操作在提交与后台执行时双重检查占用，再以设备事务锁执行；任务开始后，先前排队的手动命令也不能插入点下发。缓存连接状态单独使用短锁，首页不会为读取缓存而等待 SDK 的长调用；缓存不代替 USB 实际状态确认。

### 7.2 相同地址不能通过不同类型绕过占用

DG4000、SSG 和通用 SCPI 对同一规范化 VISA 资源地址使用共同占用身份。旧设备列表仍可读取，但同地址的多条记录不能同时建立连接，任务租约也覆盖这些别名；新保存拒绝跨 SCPI 类型重复地址。规范化只处理已支持的地址形式、大小写和首尾空白，不自动证明不同 USB/LAN 地址属于同一实体仪器。

连接或断开进入资源保留状态后，其他记录不能趁通信尚未完成时连接、手动下发或启动同资源 NI 任务。活动租约/连接过渡未结束时 close_all 拒绝清理，不能从全局退出绕过占用。

首页编辑/删除必须尊重设置窗口的 close() 返回值。窗口因任务未结束而拒绝关闭时，继续保留设备记录、窗口跟踪和占用；停止完成后再执行编辑或删除。通用 SCPI 的后台原始命令尚未返回时同样拒绝关闭并保留 CallTask。

SSG 自身窗口的首次连接和必要关断恢复保留精确到当前记录的授权。该授权不允许首页或同地址别名替运行中的扫描重连，不削弱跨记录占用保护；现场恢复后先确认状态，再按要求重新布防。

### 7.3 Vaunix 触发和命令重试

真实与虚拟 Vaunix 的 prepare_trigger 都返回绑定 connection_generation 的写入器。断开/重连后旧 writer 在实际 SDK 设置前拒绝执行，须完成停止再重新布防。点内参数整体验证后才写入，拒绝空点、通道 2、非频率/功率参数及越界值。

触发点的 setter 失败不自动重试；即使 SDK 返回传输错误，也不能排除仪器已经接受参数。开始扫频 StartSweep(True)、非 STOP 的 StartSequence 控制和 SaveSettings 同样只调用一次。普通幂等 setter、读取与 STOP 保留原来的短暂传输错误重试。这里不承诺点内多个 SDK 设置具有原子回滚能力。

### 7.4 CSV 失败不能抹去已经执行的点

跨设备完成设备调用后，先发布真实 device_results；本点全成功才更新 applied_count，然后写 CSV。日志失败即停止后续点，但不把已成功写入的本点改回未执行，也不清除部分结果或原设备错误。日志错误中会说明本点全部完成、部分失败或途中停止的情况；禁止据此自动重放。

CSV 可能缺少失败时那一条记录。用户应保留界面中的设备结果与错误，并核对仪器实际状态；完成计数表示设备调用返回，不表示日志已可靠写盘。已有空 CSV 首次写入会补齐表头。

## 8. 0.7.15 参数语义、精度和整批预检

### 8.1 幅度单位、相位与浮点往返

DG 基本波幅度、NI 幅度点和 ASK 键控幅度的类型化命令都显式携带 `VPP`，例如 `:SOUR2:VOLT 2VPP`。仪器当前 VRMS/dBm 单位不会改变这些命令的幅度含义；原始控制台按用户原文发送，需自行注明单位。基本输出相位和 PSK 相位统一校验为 0–360°（含端点），不隐式折返。

`finite_number` 和 DG、跨设备、Vaunix 可编辑点表采用最短浮点往返格式。`100000000.000001` 与 `100000000.000002` Hz 两点在显示、读取和 DG SCPI 序列化中保持不同，不再被固定 12 位有效数字合并。JSON 格式不变；该修复不提供任意精度或提高硬件分辨率。Vaunix 继续按 SDK 10 Hz 频率单位、0.25 dB 功率编码及仪器 0.5 dB 功率网格处理。

### 8.2 按型号与实际波形校验频率

四个已知型号的周期波形频率上限如下，最小频率均为 1 μHz：

| 波形上限（MHz） | DG4062 | DG4102 | DG4162 | DG4202 |
|---|---:|---:|---:|---:|
| SINE | 60 | 100 | 160 | 200 |
| SQUARE | 25 | 40 | 50 | 60 |
| RAMP | 1 | 3 | 4 | 5 |
| PULSE | 15 | 25 | 40 | 50 |
| USER | 15 | 25 | 40 | 50 |

基本波应用按已知型号及所选波形校验，不将单一 DG4162 示例推广到全系列。噪声带宽不是 `FREQ` 的设置上限；未知型号不具备完整规格校验保证。依据为 [RIGOL DG4000 四型号规格表](https://beyondmeasure.rigoltech.com/acton/attachment/1579/f-0168/0/-/-/-/-/file.pdf)、[RIGOL DG4000 数据表](https://int.rigol.com/ind/Images/DG4000_Datasheet_tcm13-3344.pdf)及[官方产品表](https://www.rigolna.com/products/waveform-generators/dg4000/)。

每次 `prepare_trigger` 在 NI 计数开始前执行一次总耦合查询，并对 CH1/CH2 各执行一次 `FUNC?`。任务保存实际波形快照，逐点按其校验输出频率；点内仍为零查询、一次写入，不提前下发 P0。仪器面板或其他软件改变波形/耦合后必须停止并重新布防；连接代次变化也使旧快照失效。

### 8.3 手动恢复身份与虚拟状态锁

手动操作自动恢复连接后核对型号与序列号。任一变化会阻止继续发送旧配置；须核对资源、重新读取身份确认当前设备，或断开后重连，再应用设置或布防。显式单通道 OFF 仍免耦合查询，但同样拒绝恢复后的身份错配。

`VirtualScpiSession` 的连接/身份缓存改用独立短锁。`manager.info` 读取缓存不再与手动 transaction 反向取锁，消除由此导致的冻结；实际命令仍受会话事务锁保护。

### 8.4 Vaunix 整批预检与派发失败

真实/虚拟 Vaunix 输出、扫频和完整序列在首次 SDK 设置前完成全部输入、编码、时间和量化检查。完整序列的第二行或后续行无效时不会先写第一行；扫频也检查 10 Hz 转换后的方向及非零步长。这只保证软件可发现的输入错误零写入，通信失败仍可能部分执行，没有事务回滚。

`QThreadPool` 异常拒绝入队时，启动路径回滚本次占用并恢复界面；停止路径保留 controller 和 lease，供用户重试停止。派发失败不会自动重发仪器命令。

## 9. 实现和验证入口

- `drivers/dg4000.py` / `units.py`：耦合及波形预检、显式 VPP、相位/频率范围、最短浮点往返、恢复身份核对、绝对通道任务写入器。
- `poll_waiter.py` / `trigger.py` / `linkage.py`：等待策略、累计边沿、全部设备预检查后启动 NI、跨设备 `partial_stopped`。
- `controller_lifecycle.py`：启动完成标志、后台停止、线程退出与 NI 清理判据；停止失败保持可重试状态。
- `ui/device_windows.py` / `ui/vaunix_window.py`：原生页面通道选择、手动操作双重检查、启动/停止 CallTask 身份交接。
- `connections.py` / `repository.py` / `ui/main_window.py`：跨 SCPI 类型资源身份、连接过渡保留、重复保存校验、拒绝关闭后的记录保留。
- `drivers/vaunix_lms.py`：真实/虚拟连接代次、单次触发点写入、非幂等命令重试边界与短锁状态缓存。
- `ui/snapshot_bridge.py`：合并 UI 显示，任务会话、revision、终态及计数保护。

## 10. 0.7.17 专用只读回读

“通道与波形”页底部的回读区分别显示 CH1、CH2 的频率、幅度、实际幅度单位和输出开关，完成后记录回读时间。结果不回填待应用编辑框，也不加入设备参数持久化。

“总览”和回读区均提供“回读频率 / 幅度”按钮；前者跳转到“仪器频率与幅度回读 · 手动快照”并执行一次读取。驱动 `read_output_parameters(channels=(1, 2))` 返回 `DG4000OutputReadback` 元组；每通道通过 `VOLT:UNIT?` 前后校验配合 `FREQ?`、`VOLT?` 和 `OUTP?`，单位变化、无效回复或连接代次变化时整组结果作废。

专用回读不下发任何设置，不改变通道、负载、耦合或幅度单位；因此不需要先关闭耦合来读取。幅度按仪器实际 Vpp、Vrms 或 dBm 单位显示，不假设 50 Ω 负载或特定波形来转换。输出关闭时显示的频率/幅度属于配置参数。

读回使用后台任务和共享 SCPI 事务，CH1、CH2 的查询顺序执行，不能解释为两个通道的同时电气采样。专用入口可在 NI 触发/联动运行中手动查询一次，会占用一次通信时段；不启用周期轮询，也不改变每点一次写入、零逐点查询的触发路径。其他手动设置和原始控制台仍受运行任务的占用保护。

回读失败不自动恢复连接或重放设置，避免连接代次变化破坏运行写入器。失败或断连后回读值失效并显示未知；不能把一次成功回读后的静态显示当作持续实时测量。原生扫频、FSK 和其他调制的瞬时输出仍需独立测量手段，载波/基本波频率查询不提供这类电气时标。

本轮回读的源码、虚拟设备与冻结产物实际验收见[0.7.17 说明](../release/NOTES-0.7.17.md)，不沿用第 9 节的历史测试数量。

## 11. 0.7.19 已完成快照的连接代次检查

快速断开和重连可能发生在两次界面状态同步之间，连接布尔值最终仍为“已连接”。只检查这个布尔值会保留上一连接已经完成的频率、幅度、输出状态及回读时间；旧有排队和迟到结果检查不能使这类已显示缓存失效。

界面现在同时检查回读快照所属连接代次，发现变化即清空两通道和旧时间。开始新连接上的手动回读时记录其所属代次，后续同步观察到同一连接时保留该新请求；真正旧连接的排队请求和迟到结果仍会丢弃。此检查使用短状态锁下的缓存，不调用 VISA 或新增自动查询，也不改变输出、任务写入器、身份核对和占用。

最小复现、针对性回归及本版源码/冻结验收记录见[0.7.19 说明](../release/NOTES-0.7.19.md)。本轮未操作实体仪器，不提供实机时延或输出稳定性结论。
