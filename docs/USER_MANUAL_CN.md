# DG4000 + Vaunix + NI 多设备联动控制软件使用说明

版本：0.6.0
更新日期：2026-09-09（含未发布 Newport 扩展与 LMS-802 兼容修复）
适用范围：RIGOL DG4000 系列、Vaunix Lab Brick LMS/BLX、带模拟输入/边沿计数能力的 NI DAQ、内置虚拟实验室

本软件用于统一管理多台 DG4000、Vaunix LMS/BLX、NI DAQ 和通用 SCPI 仪器。NI 设备可以独立检测外部触发、累计计数和采集模拟电压，但不使用 AO 电压控制发生器。每次检测到新的累计触发后，软件通过 VISA/SCPI 向 DG4000、或通过 Vaunix USB DLL 向 LMS/BLX 下发下一组参数；模拟输入数据在采集过程中逐块写入 CSV/TXT 文本，实时曲线只用于监视。

## 1. 软件能力概览

新增 Newport SMC100CC / PR50CC 循环旋转步进，详见 [Newport 操作说明](NEWPORT_ROTATION_CN.md)。旋转任务启动保持 P0、首触发 P1、末点下一触发回 P0；运动/稳定期间触发报错停止，不补跑积压。可由同一任务同时运行 NI counter 与连续 AI。本章下文的首触发 P0、积压补发及独立采集限制适用于原有 DG/Vaunix 任务，不适用于此旋转控制器。

- 多设备首页：添加、保存、编辑、删除、搜索、连接和断开设备。
- 独立设置窗口：点击设备后打开新窗口，多台设备可同时操作。
- DG4000 控制：双通道基本波形、输出负载阻抗、调制、扫频、脉冲串、系统命令和原始 SCPI 控制台。
- Vaunix 控制：频率、绝对输出功率、RF、参考源、LMS/BLX 扫频、外部触发、快速脉冲、Chirp、BLX 50 项频率/功率序列、状态与非易失设置保存。
- NI 控制：设备识别、PFI 端子、边沿方向、硬件累计计数器、模拟电压输入、实时绘图、数据保存和诊断。
- 单位切换：常用频率、电压、角度和时间输入可选择显示单位并输入小数，下发前自动换算为 SCPI 基准单位。
- 多轴触发步进：频率、幅度、输出相位、PSK 相位和 FSK 跳跃频率可组成一个联合扫描点。
- 跨设备任务中心：一个 NI 触发源可驱动多台 DG4000，每个扫描轴分别选择设备、通道、参数和单位。
- Vaunix 专用 NI 联动：频率和功率轴可以分别启用，并支持同步联动或笛卡尔组合扫描。
- 任务与证据：跨设备配置和手工点表可以保存、加载、删除；运行过程自动保存逐点 CSV 日志。
- 扫描方式：同步联动按相同序号组合各轴；组合扫描生成笛卡尔积。
- 循环规则：第一个触发应用联合点表第一个点，末点后回到第一个点持续循环。
- 无软件最小触发间隔：硬件累计触发数跳变时，所有缺失序号都会进入有序积压并逐项补发。
- 虚拟实验室：无 DG4000、Vaunix、NI 设备或厂商驱动时也可体验全部主要流程、设备联动和多通道模拟采集。

### 1.1 系统数据流

1. 外部信号或虚拟控制台产生触发。
2. NI 硬件计数器或虚拟计数器保存累计边沿数。
3. 监视线程读取累计数并更新 `received_count`。
4. 协调线程按序号选择联合点；DG4000 使用 VISA/SCPI 受锁批次，Vaunix 使用 `vnx_fmsynth.dll` 类型化调用。
5. 全部设备成功跨过点级完成屏障后才更新 `applied_count`，两者差值就是待处理积压。

### 1.2 重要边界

- 首个点不会在任务启动时预先发送，必须收到第一个触发后才发送。
- 不主动丢弃触发，不把多个触发合并成一次参数变化。
- 不设置固定等待时间，也不设置最小触发间隔。
- 同一联合点的多条命令不会被其他窗口命令插入，但 DG4000 仍按顺序解析，不承诺电气意义上的绝对同时生效。
- 多台 DG4000 的软件下发不承诺物理同步；当前严格顺序模式强调可复现性。微秒级同步需要预装载序列和公共硬件触发。
- 某台设备失败时任务会停止，失败联合点不会增加完成计数；此前成功设备可能已经改变输出，SCPI 无法提供真正事务回滚。
- 如果触发速度高于 DG4000 SCPI 或 Vaunix USB 命令的实际吞吐能力，物理生效时间会落后于触发时间。
- 停止任务时尚未下发的积压不会继续发送；重新启动后计数和序列从头开始。
- 模拟输入是独立采集任务，不会改变首触发和步进循环语义。当前版本用设备占用锁阻止模拟采集、独立计数和联动任务争用同一 NI。

## 2. 安全与使用前检查

### 2.1 实机电气连接

- 外部触发源接 NI 的 PFI 输入端子。
- NI 与外部触发源必须有可靠参考地。
- DG4000 通过 USB、LAN、GPIB 或串口 VISA 接收软件命令。
- Vaunix LMS/BLX 通过 USB 连接，软件直接调用 Windows `vnx_fmsynth.dll`，不使用 VISA 资源。
- 不要把 NI AO 接到 DG4000 参数控制端。
- 触发联动本身不需要把 DG4000 输出回接到 NI；如需使用新增的模拟采集功能，可将待测模拟信号接到所选 `ai` 通道。
- 确认 PFI 输入电平符合具体 NI 型号的电气规范。
- 确认模拟输入接法、端接方式和量程符合具体 NI 型号及信号源的电气规范。

### 2.2 软件安全

- 首次实机测试时关闭 DG4000 输出，只验证连接和参数读取。
- 首次 Vaunix 实机测试同样保持 RF 关闭，先核对型号能力、频率和绝对功率回读。
- 开启输出前检查幅度、偏置、负载和外部电路耐压。
- 编辑已连接设备的资源地址时，软件会先释放旧连接。
- 关闭程序时会自动停止虚拟连续触发并释放全部连接。

## 3. 安装与启动

### 3.1 基础环境

- Windows 10 或 Windows 11。
- Python 3.10 或更高版本。
- PyQt6。
- 仅使用虚拟实验室时，不需要 PyVISA、NI-VISA 或 NI-DAQmx。
- Vaunix 实机需要与 Python 位数一致的 Windows x64 `vnx_fmsynth.dll`；虚拟 Vaunix 不需要 DLL。

### 3.2 安装图形界面

```powershell
cd E:\Github_Project\Rigol_Generator_GUI
python -m pip install -e .
python -m rigol_control
```

也可以直接运行：

```powershell
.\run_app.cmd
```

### 3.3 安装实机依赖

先安装 NI-VISA 或兼容 VISA Backend，以及 NI-DAQmx 系统驱动。然后安装 Python 包：

```powershell
python -m pip install -e ".[instrument]"
```

在 NI MAX 中确认：

1. DG4000 VISA 资源可见，并能执行 `*IDN?`。
2. NI 设备名可见，例如 `Dev1`。
3. 计划使用的计数器、PFI 和模拟输入通道没有被其他任务占用。
4. 设备确实报告所需 `ai` 通道和采样率；软件不会仅凭型号名称猜测能力。

Vaunix SDK 不通过 NI MAX 管理。程序按以下顺序寻找 DLL：环境变量 `VAUNIX_LMS_DLL`、项目根目录、程序驱动目录，以及项目内 `lms-sdk-*\LMS_Windows_SDK_*\x64\Release\vnx_fmsynth.dll`。使用 64 位 Python 时必须加载 x64 DLL。连接前可在 PowerShell 中显式指定：

```powershell
$env:VAUNIX_LMS_DLL = "C:\path\to\vnx_fmsynth.dll"
```

## 4. 设备中心

<!-- SCREENSHOT: 01-device-center.png | 图 1 设备中心中的虚拟 DG4000、Vaunix 和 NI 均已连接 -->

### 4.1 首页结构

- “刷新状态”只检测设备是否可用，不会保持连接。
- “虚拟实验室”创建并连接一套内置模拟设备。
- “添加设备”打开设备搜索和保存窗口。
- 每张卡片提供连接、断开、打开设置、编辑和删除。
- “可用”表示探测成功但没有保持会话；“已连接”表示会话已由连接管理器保留。

### 4.2 设备配置文件

设备名称、类型、资源地址和连接方式保存在本机 JSON 文件中，默认位置为：

```text
%APPDATA%\RigolGeneratorControl\devices.json
```

首页只显示“设备列表已自动保存在本机”，鼠标悬停时显示完整路径。该文件不是采集数据，也不包含 DG4000 输出波形。

### 4.3 连接生命周期

- 首页和设置窗口共享同一 VISA 会话。
- 关闭设置窗口不会断开设备。
- 点击断开、删除设备或退出软件时释放连接。
- 为避免启动后意外控制仪器，连接状态不会跨程序重启自动恢复。

## 5. 添加和搜索设备

<!-- SCREENSHOT: 02-add-device-discovery.png | 图 2 资源地址为可编辑下拉框，虚拟设备无需驱动即可发现 -->

### 5.1 自动搜索

- DG4000 和通用 SCPI 使用 VISA 资源管理器枚举资源。
- NI DAQ 使用 NI-DAQmx 枚举 `Dev1` 等设备名。
- Vaunix LMS/BLX 直接使用 `vnx_fmsynth.dll` 枚举 USB 设备，显示真实型号和序列号；保存资源为 `VAUNIX::LMS::<序列号>`，不会保存本次枚举的临时句柄。
- 软件根据资源前缀自动匹配 USB VISA、TCP/IP VISA、GPIB VISA 或串口 VISA。
- 下拉项可以显示产品说明，但保存时只写入真实资源名。
- “重新搜索”在设备插拔或 NI MAX 配置改变后重新枚举。

### 5.2 手动输入

资源框始终可编辑。驱动未安装、网络设备不支持自动发现或特殊 VISA Backend 未枚举时，可以手动输入：

```text
USB0::0x1AB1::...::INSTR
TCPIP0::192.168.1.88::INSTR
Dev1
VAUNIX::LMS::4030123
```

### 5.3 内置虚拟资源

```text
SIM::DG4000::1
SIM::DG4000::2
SIM::NI_DAQ::1
SIM::VAUNIX_LMS::1
```

它们不依赖厂商驱动，适合功能体验、界面开发、演示、回归测试和触发积压调试。

## 6. 虚拟实验室快速体验

### 6.1 一键创建

1. 启动软件。
2. 点击首页“虚拟实验室”。
3. 等待“虚拟 DG4162”“虚拟 DG4162-B”“虚拟 NI USB-6363”“虚拟 Vaunix BLX-403”和“虚拟 Newport PR50CC”五张卡片显示“已连接”。
4. 单机功能可以打开设备设置；跨设备功能点击首页“跨设备联动”。

如果虚拟设备已经存在，再次点击不会重复创建，只会重新加载并连接。

### 6.2 验证普通 DG4000 控制

<!-- SCREENSHOT: 03-virtual-dg-overview.png | 图 3 虚拟 DG4000 总览会实时显示两个通道和 SCPI 命令数 -->

1. 打开虚拟 DG4000 的“通道与波形”。
2. 选择 CH1，设置波形、频率、幅度、偏置和相位；分别切换 kHz/MHz、Vpp/mVpp、V/mV 或度/rad，确认显示值会换算且物理值保持不变。
3. 勾选“启用通道输出”。
4. 点击“应用到 CH1”。
5. 进入“存储与系统”，确认 CH1/CH2 负载默认选中 50 Ω；可改为高阻、75 Ω、600 Ω或自定义值，再单独应用或同时应用两个通道。
6. 回到总览，检查“虚拟 DG4000 实时状态”。

### 6.3 启动虚拟触发联动

1. 在虚拟 DG4000 窗口进入“触发步进”。
2. NI 计数设备选择虚拟 NI，并确认 PFI、计数器和边沿。
3. 轴 1 选择“输出频率”、CH1、kHz，设置起点 `1`、步长 `1`、点数 `4`。
4. 点击“增加扫描轴”，轴 2 选择“输出幅度”、CH1、Vpp，设置起点 `1`、步长 `0.1`、点数 `4`。
5. 选择“同步联动（同序号）”，确认预检显示 4 个联合点、每触发 2 条 SCPI。
6. 点击“生成联合点表”；需要非等间隔序列时仍可直接编辑表格或增删联合点。
7. 点击“启动联动”，再在虚拟 NI 总览中发送单次或批量触发。

### 6.3.1 双 DG 跨设备联动

1. 点击首页“跨设备联动”。
2. 选择虚拟 NI、`ctr0`、`PFI0` 和上升沿。
3. 轴 1 选择第一台虚拟 DG、CH1、输出频率、kHz，起点 `1`、步长 `1`、点数 `4`。
4. 增加轴 2，选择第二台虚拟 DG、CH1、输出幅度、Vpp，起点 `0.5`、步长 `0.25`、点数 `4`。
5. 生成点表并保存任务；点表第一行明确标注“起始点（第一个触发）”。
6. 点击“启动联动”，再点击“虚拟触发 +1”或“虚拟触发 +10”。
7. 检查接收数、完成数、积压、当前点、设备耗时和完成偏差；CSV 日志路径显示在窗口底部。

### 6.4 单次、批量和连续触发

- 单次：每次增加一个累计触发，适合核对首点和逐点顺序。
- 批量：一次增加多个累计触发，适合验证软件不会丢失两次读取之间的触发。
- 连续：按设定毫秒周期自动发送，适合长期运行和界面监视。
- “累计发送”是虚拟 NI 自创建以来的总数；触发任务只统计启动后的增量。

### 6.5 调试积压

虚拟 DG4000 的“模拟下发延迟”范围为 0 至 2000 ms。增大该值相当于降低 VISA/SCPI 吞吐速度。

1. 设置模拟延迟为 80 ms。
2. 启动触发任务。
3. 从虚拟 NI 批量发送 12 次触发。
4. 观察“收到 12、已下发较少、积压大于 0”。
5. 停止发送并等待，最终“已下发 12、积压 0”。

### 6.6 体验虚拟模拟输入

1. 打开虚拟 NI 的“模拟输入”页。
2. 在“采集”选项卡展开“采集端口”下拉列表，勾选 `ai0` 至 `ai3`，也可以点击“全选”；下拉框收起后显示已选通道摘要。
3. 在同一选项卡设置共享采样率、量程、每次读取点数和内存保留上限。
4. 在“虚拟源”选项卡设置正弦频率、峰值幅度、直流偏置和噪声峰值。
5. 点击“开始采集”，观察实时波形、每通道总点数、采集时长和最近数据块统计。
6. 保持默认勾选“采集时连续写入 CSV/TXT 文本”，确认保存路径后点击“开始采集”。
7. 观察“已写入文本”持续增加；点击“停止”后文件关闭，完整样本仍保留在磁盘中。“导出缓存 CSV”只用于另存当前绘图窗口。

### 6.7 体验虚拟 Vaunix 全功能与 NI 联动

1. 打开“虚拟 Vaunix BLX-403”，总览会显示虚拟型号、序列号、SDK 1.15、500 MHz 至 40 GHz、-40 至 +10 dBm，以及 BLX 序列、快速脉冲和 Chirp 能力。
2. 在“射频输出”设置频率、绝对功率、RF 和内/外参考；虚拟设备按真实 DLL 的 10 Hz 频率单位、0.25 dB 功率编码和 0.5 dB 实际功率分辨率保存状态。
3. 在“扫频与 Chirp”配置起点、终点、步长、BLX 驻留/空闲、方向、重复、双向和外部触发；LMS 型号连接时界面改用总扫频时间。“BLX 频率步长”在 LMS-802 等 LMS 型号上禁用，不参与读写；这不影响“NI 触发步进”页面的频率步长。
4. 在“脉冲调制”配置快速内部脉冲与外部脉冲输入；在“BLX 序列”编辑最多 50 项频率/功率，并测试一次、重复、暂停、继续和停止。
5. 进入“NI 触发步进”，选择虚拟 NI。频率和功率轴可以只开一个，也可以同时启用；同步模式要求点数一致，组合模式生成笛卡尔积。
6. 生成循环点表并启动，点击“虚拟触发 +1”或“+10”。第一个触发应用 P0，随后逐点推进并循环；收到数大于完成数时，差值按顺序积压，不设置软件最小间隔。

## 7. DG4000 设置窗口

### 7.1 总览

显示 VISA 资源、连接方式、`*IDN?` 身份信息、通道状态和虚拟实时状态。实机“连接设备”会建立并保留 VISA 会话，“执行自检”发送 `*TST?`。

### 7.2 通道与波形

支持 CH1 和 CH2：

- 正弦波、方波、锯齿波、脉冲、噪声和任意波。
- 频率、幅度、直流偏置和初相位。
- 频率支持 Hz/kHz/MHz，幅度支持 Vpp/mVpp，偏置支持 V/mV，相位支持度/rad。
- 输出开启和关闭。

未连接时，频率编辑器按 DG4000 全系列最高 200 MHz 开放，避免尚未识别型号时把 DG4202 错误限制在 160 MHz。连接后软件从 `*IDN?` 自动识别型号并更新 CH1/CH2、FSK 跳跃频率、扫频起止频率和触发扫描轴范围：DG4062 为 60 MHz、DG4102 为 100 MHz、DG4162 为 160 MHz、DG4202 为 200 MHz。恢复值高于当前型号上限时界面会收紧到上限；类型化下发和单机/跨设备点表启动前还会再次校验。这里采用型号标称最高输出频率作为总上限，具体波形、幅度、负载和固件可能有更低限制，最终仍以仪器编程手册和错误队列为准。

应用基本波形时，软件在一个受锁批次中按顺序下发函数、频率、幅度、偏置、相位和输出状态，不再隐式写入 `:OUTP<n>:LOAD`。因此修改频率或波形不会覆盖已经设置的负载阻抗。

### 7.3 调制

提供 AM、FM、PM、ASK、FSK、PSK 和 PWM 页面，可选择 CH1/CH2、内部/外部调制源、内部波形、调制频率及对应参数。调制频率、频偏、键控幅度、调制相位和脉宽偏移使用与物理量匹配的单位选择器。

对于本项目的触发步进：

- PSK 相位目标写入 `:SOUR<n>:MOD:PSK:PHAS <value>`。
- FSK 频率目标写入 `:SOUR<n>:MOD:FSK:FREQ <value>`。
- 开始步进前应先配置载波并启用相应调制模式。

### 7.4 扫频和脉冲串

扫频支持线性、对数和步进间隔，设置起始频率、终止频率、时间和触发源。脉冲串支持 N 周期、无限和门控模式，设置周期数、内部周期和起始相位。频率、时间和角度均可切换单位。

### 7.5 存储、系统与 SCPI 控制台

本页集中管理 CH1/CH2 输出负载阻抗。两个通道的界面默认值均为 50 Ω，并支持高阻、75 Ω、600 Ω和 1 至 10000 Ω 自定义整数值；既可逐通道应用，也可一次应用两个通道。负载命令独立于波形命令，仅在点击对应应用按钮时下发。

根据项目内 DG4000 编程手册，负载命令为 `:OUTP<n>:LOAD <value>`，接受 `INFINITY` 或 1 至 10000 Ω 的整数。它用于告诉仪器外部实际负载，以校准显示和输出幅度；不等同于把输出级固有源阻抗物理改成任意值。连接实物前仍须核对终端方式、实际负载和幅度，仪器返回错误时应读取错误队列。

本页还提供保存状态、调用状态、恢复默认、读取错误队列和原始 SCPI 控制台。控制台不会限制命令集合，因此编程手册中的型号或固件特有命令仍然可达。

查询命令以 `?` 结尾，例如：

```text
*IDN?
:SYST:ERR?
:SOUR1:FREQ?
```

写命令示例：

```text
:SOUR1:FREQ 1000
:SOUR1:VOLT 2.0
:OUTP1 ON
```

## 8. NI 设置窗口

### 8.1 连接含义

NI 设备不是 SCPI 仪器。“连接”表示 NI-DAQmx 能成功识别设备并读取产品类型、序列号和模拟输入物理通道，不代表已经持续占用计数器或 ADC。实际任务在点击“开始计数”、启动 DG4000 联动或点击“开始采集”时创建。

### 8.2 触发输入

- 选择 PFI 输入端子。
- 选择上升沿或下降沿。
- 可选 NI 硬件数字滤波。
- 软件不通过定时轮询单个脉冲，而是读取硬件累计边沿数。

### 8.3 计数器

选择 `ctr0` 至设备支持的最大计数器。独立计数页面可验证接线，联动任务会创建自己的累计计数器对象。若出现资源占用错误，关闭 NI MAX 测试面板和其他使用相同计数器的程序。

### 8.4 路由和诊断

路由页面记录建议接线。诊断页面检查 Python 包、系统驱动、设备名和端子能力。最终可用计数器数量以 NI-DAQmx 对实际型号的报告为准。

### 8.5 模拟输入配置

“模拟输入”页连接后自动枚举 NI-DAQmx 报告的 `ai` 物理通道。配置项包括：

- 并行通道：“采集端口”是带复选框的可多选下拉列表。展开后逐路勾选，或使用“全选/清空”；收起后显示已选数量和端口摘要，下方显示“已勾选 N / 总数 路”。
- 采集方式：全部勾选通道加入同一个 NI-DAQmx 连续采集任务，共享同一硬件采样时钟和采样率；每次读取返回各通道同样数量的对齐样本。设备是同步采样还是多路复用采样取决于具体 NI 型号。
- 端接方式：设备默认、RSE、NRSE、DIFF 差分和伪差分。必须根据实际接线和设备手册选择。
- 采样率：界面支持 Hz/kHz/MHz，小数会在创建任务前换算为 Hz；若硬件将请求值校正到可实现时钟，时间轴和 CSV 使用 NI-DAQmx 回读的实际采样率。
- 输入量程：上下限可分别使用 V 或 mV；下限必须小于上限。
- 每次读取点数：一次从 NI-DAQmx 缓冲区读取的每通道样本数，会影响界面更新频率。
- 内存保留上限：范围为 1000 至 5000000 点/通道。达到上限后自动丢弃最早数据，并显示累计丢弃点数，避免无限占用内存。
- 连续文本记录：默认启用。可选择 `.csv` 或 `.txt` 路径；若文件已存在，软件自动增加序号，不覆盖历史记录。

采集任务使用 NI-DAQmx 硬件采样时钟和连续采样模式。软件上限不是设备能力承诺；可用通道、总采样率、量程、端接方式和与计数任务的并行能力，始终以实际硬件和 NI-DAQmx 错误报告为准。

### 8.6 实时绘图与连续文本记录

- 实时图最多显示最近 50000 点，通道使用不同颜色；数据多于横向像素时按像素保留最小值和最大值，避免窄脉冲在抽点中消失。
- 指标显示通道数、每通道累计点数、采集时长、保留/丢弃点数以及已经写入文本的点数；下方显示最近数据块的最小值、最大值和 RMS。
- 点击“开始采集”前，软件打开连续记录文件。每读取一个 NI 数据块，就按样本顺序追加写入并刷新文件，因此运行期间文件会持续增长，异常退出前已刷新完成的数据仍可读取。
- 连续文件使用 UTF-8 BOM，包含格式版本、UTC 创建时间、实际采样率、首样本序号、连续记录标记，以及 `sample_index`、`elapsed_s` 和各通道电压列。
- 多通道文件中每个采样时刻占一行，每个勾选通道占一个独立电压列；列名使用 NI-DAQmx 物理通道名。实时图为各通道分配不同颜色并在图例中显示 `ai` 名称。
- 内存保留上限只约束实时绘图缓存。即使“丢弃点数”持续增加，磁盘文本仍保存从首点开始的完整连续序列；软件检测到样本序号跳变、通道变化或采样率变化时会停止并报告错误，避免静默生成伪连续文件。
- “导出缓存 CSV”是辅助功能，只保存当前仍在内存中的最近窗口。软件不保存波形图片；曲线用于实时查看，不替代原始文本。
- 触发联动和模拟输入相互独立；模拟输入不改变触发计数，也不会通过 AO 向 DG4000 写电压。

## 9. Vaunix LMS/BLX 设置窗口

### 9.1 自动检测、连接与能力识别

添加设备时选择 `Vaunix LMS/BLX`。软件加载 Windows SDK 后调用设备枚举、型号、序列号和状态接口；列表中使用 `VAUNIX::LMS::<序列号>`，连接时再次按序列号匹配，因此即使 USB 插拔后临时设备句柄顺序改变，也不会误连其他设备。虚拟资源 `SIM::VAUNIX_LMS::1` 始终可选。

连接后总览读取并显示：型号、序列号、SDK 版本、最小/最大频率、最小/最大绝对功率、快速脉冲、Chirp、BLX 序列能力，以及连接、打开、PLL、扫频和选件状态位。不支持的快速脉冲、Chirp 或 BLX 序列操作会被禁用，驱动层仍会二次拒绝不合法调用。

### 9.2 射频输出

- 当前频率支持 Hz、kHz、MHz、GHz 小数输入，DLL 内部使用 10 Hz 单位。
- 功率输入是绝对 dBm，不是 DG4000 的 Vpp。DLL 参数以 0.25 dB 为编码单位，即 `powerlevel = dBm × 4`；但手册同时明确仪器实际功率分辨率为 0.5 dB，因此软件只允许 `.0` 或 `.5 dBm` 网格，并按连接设备报告的上下限校验。
- RF 开关与内/外参考源独立设置。
- 恢复软件参数只更新界面，不会自动打开 RF。点击“应用输出参数”才会按参考源、频率、功率和 RF 的顺序写入。

### 9.3 LMS/BLX 扫频与 Chirp

通用扫频参数包括起始频率、终止频率、步长、向上/向下、单次/重复、单向/双向以及内部/外部触发。LMS 型号使用总扫频时间；BLX 型号使用每点驻留时间和重复空闲时间，界面会依据型号启用相应控件。“启动扫频”和“停止”调用设备端扫频引擎，不依赖 NI 软件逐点下发。

支持 Chirp 的型号还可设置启用状态、Chirp 长度、重复周期和外部触发。Chirp 与普通扫频共用启动/停止入口以及外部扫频触发配置，切换模式前应先停止当前运行。

### 9.4 脉冲调制

快速脉冲页设置 RF 开启时间、重复周期、内部快速脉冲启用和外部脉冲调制输入。开启时间范围为 100 ns 至 1000 s，周期必须不小于开启时间。未安装内部脉冲选件的型号会禁用内部时间和开关，但仍允许单独尝试外部脉冲输入；若该硬件配置也不支持外部输入，DLL 会返回明确错误。

### 9.5 BLX 设备端序列

BLX 可编辑最多 50 项序列。每项包含频率、绝对功率，以及“是否同时控制功率”；未勾选时该项只改变频率。还可设置起始索引、每项驻留和重复空闲，并执行运行一次、重复运行、暂停、继续和停止。点击“写入全部序列”先校验行数、频率、功率的 0.5 dB 网格和起始索引，再按索引写入设备端。

设备端 BLX 序列适合使用仪器自身定时执行；下一节的 NI 联动则在每个 NI 边沿后通过 USB 下发点表，两者不要同时运行。

### 9.6 NI 触发频率/功率扫描

Vaunix 的专用联动页选择一个已经连接的 NI 设备、`ctr`、PFI、上升/下降沿和扫描方式。频率轴与功率轴可以分别启用：

- 同步联动：两个轴都启用时点数必须相同，第 i 个频率与第 i 个功率组成 Pi。
- 组合扫描：生成全部频率/功率笛卡尔积，功率轴变化最快。
- 单轴扫描：关闭另一个轴后，只下发启用轴的值，未参与的硬件参数保持原值。

功率扫描起点、步长、自动生成点和手工修改点均必须是 0.5 dB 的整数倍。界面按钮步长设为 0.5 dB；若手工键入 0.25 dB 网格值，生成或启动任务时会明确拒绝，不依赖仪器自行取整。

点表生成后仍可手工输入小数。任务启动不会预先改变输出；第一个累计边沿下发并保持 P0，第二个边沿下发 P1，末点后回到 P0 永久循环。系统不设置最小触发间隔，计数跳变会形成有序积压并逐点补发；当触发速率高于 USB 参数下发吞吐时，物理生效会滞后但顺序不会主动丢弃。

启动时 Vaunix 与 NI 都会取得设备租约，避免与设备端序列、独立计数或模拟采集任务争用。停止、错误和关闭窗口都会释放租约。

### 9.7 状态、软件参数与设备存储

“状态与存储”可刷新全部回读参数和状态位。每个 Vaunix 设备窗口的频率、功率、单位、扫频、脉冲、Chirp、BLX 序列表和 NI 联动点表都按稳定设备 ID 自动保存在 `device_parameters.json`；重开窗口只恢复界面，不自动下发或启动。

“保存当前设置到设备”调用 SDK 的非易失存储接口，可能改变下次设备上电状态，因此必须单独确认。软件自动参数保存与设备非易失保存是两个独立动作。

## 10. DG4000 触发步进详细说明

### 10.1 五类步进目标

| 目标 | SCPI 模板 | 常用单位 |
|---|---|---|
| 输出频率 | `:SOUR<n>:FREQ <value>` | Hz、kHz、MHz |
| 输出幅度 | `:SOUR<n>:VOLT <value>` | Vpp、mVpp |
| 输出相位 | `:SOUR<n>:PHAS <value>` | 度、rad |
| PSK 调制相位 | `:SOUR<n>:MOD:PSK:PHAS <value>` | 度、rad |
| FSK 跳跃频率 | `:SOUR<n>:MOD:FSK:FREQ <value>` | Hz、kHz、MHz |

### 10.2 单位、小数与基准值

界面中的单位只改变输入和显示方式，不改变发送到仪器的物理量。例如 `0.2 kHz` 会在点表中显示为 `0.2`，下发时转换为 `200 Hz`；`750 mVpp` 转换为 `0.75 Vpp`；`3.141592654 rad` 约等于 `180 度`。单位切换时软件先保存基准值再换算新显示值，因此从 `1 kHz` 改为 MHz 后显示 `0.001 MHz`，不会把频率误改为 `1 MHz`。

常用单位包括：

| 物理量 | 可选单位 | SCPI 基准单位 |
|---|---|---|
| 频率 | Hz、kHz、MHz、GHz | Hz |
| 幅度 | Vpp、mVpp | Vpp |
| 电压偏置 | V、mV | V |
| 角度 | 度、rad | 度 |
| 时间 | s、ms、us | s |

数值编辑器保留最多 9 位小数，表格用 12 位有效数字显示。实际可用范围仍由具体 DG4000 型号、波形、负载和固件决定。

### 10.3 扫描轴与联动方式

每个扫描轴独立包含参数、DG4000 通道、显示单位、扫描起点、扫描步长和扫描点数。轴可增加、删除、上移和下移；同一 `通道 + 参数` 不能重复出现。最多 10 个轴，联合点表最多 10000 行。

- 同步联动：各轴必须具有相同点数，第 `i` 个值组合成联合点 `Pi`。适合频率和幅度同时递增、频率和相位同步变化等实验。
- 组合扫描：生成所有轴的笛卡尔积，总点数是各轴点数乘积。轴 1 是慢轴，最后一个轴是快轴；使用上下移动按钮可改变嵌套顺序。

生成前的“点表预检”会显示联合点总数和每触发 SCPI 条数，并阻止点数不匹配、重复目标或总点数超限。修改轴配置后必须重新生成点表；任务运行期间轴、单位和表格会锁定。

### 10.4 自动生成联合点表

每个轴提供三个扫描参数：

- 扫描起点：第一个触发下发的参数值。
- 扫描步长：相邻点的差值；正数为递增扫描，负数为递减扫描，零表示重复同一个值。
- 扫描点数：该轴生成的数值数量，范围为 1 至 10000。

单个轴的第 `i` 个值按下式计算，其中 `i` 从 0 开始：

```text
point[i] = start + step * i
```

软件用十进制运算生成点位，避免小数步长出现连续累加尾数。例如起点 `0.1`、步长 `0.1`、点数 `4` 会生成 `0.1, 0.2, 0.3, 0.4`。生成后表格仍可逐格修改，也可用“添加联合点”和“删除选中”制作非等间隔序列；再次生成会替换当前表格。

### 10.5 首触发与循环

对于序列 `P0, P1, P2`：

| 累计触发序号 | 下发点 | 说明 |
|---|---|---|
| 任务刚启动 | 不下发 | 等待第一个触发 |
| 1 | P0 | 按轴顺序批量下发并保持联合起始点 |
| 2 | P1 | 第一次推进 |
| 3 | P2 | 到达末点 |
| 4 | P0 | 回到起始点 |
| 5 | P1 | 继续循环 |

通用公式为：

```text
index = (trigger_number - 1) mod point_count
```

### 10.6 为什么不设置最小触发间隔

NI 计数器在硬件中累计边沿。假设软件上一次读到 100，下一次读到 108，说明期间出现了 8 个触发。控制器不会只处理最后一个，也不会认为它们同时发生，而是生成 101 至 108 八个连续序号并按顺序下发。

软件读取周期只影响界面何时得知最新累计值，不构成输入死区。真正的速度瓶颈通常是：

- USB/LAN/VISA 往返时间。
- DG4000 命令解析与参数生效时间。
- 操作系统线程调度。
- 同一 VISA 会话上的其他命令。

### 10.7 积压含义

```text
backlog = received_count - applied_count
```

- 积压为 0：写入线程已经追平。
- 积压增长：触发产生速度高于 SCPI 下发速度。
- 积压下降：触发停止或变慢，写入线程正在追赶。
- 积压不会自动提高仪器吞吐，也不能保证参数在原始触发时刻生效。

### 10.8 开始和停止

开始任务前检查：DG4000 已连接、NI 设备存在、计数器和 PFI 正确、联合点表已重新生成、PSK/FSK 模式已配置。停止任务会停止监视和写入线程并释放计数器，未完成积压不再发送。

## 11. 跨设备联动任务中心

### 11.1 扫描目标和点表

跨设备扫描轴的唯一目标是 `设备 ID + 通道 + 参数`。因此两台 DG 的 CH1 频率是两个独立目标，同一台 DG 的 CH1 频率和 CH2 频率也是两个目标；完全相同的目标不能重复添加。每个轴继续支持小数、单位换算、同步联动和笛卡尔组合，联合点总数上限为 10000。

任务保存到 `linkage_tasks.json`，内容包括 NI 触发源、计数器、PFI、边沿、组合方式、设备下发方式、全部扫描轴以及当前表格中的显式联合点。加载时若引用设备已经被删除，预检会阻止启动，不会把轴静默绑定到其他设备。

### 11.2 启动预检和设备占用

启动前软件检查：点表没有过期、NI 和所有参与 DG 均已连接、任务引用的设备仍存在，并原子占用全部参与设备。任一资源已被单设备触发、NI 独立计数、NI 模拟采集或另一个跨设备任务占用时，本任务不会取得部分资源，而是整体启动失败。停止、出错或关闭窗口后会释放占用。

### 11.3 严格顺序和完成屏障

当前 0.6.0 的首页跨设备任务中心只开放 DG4000 “严格顺序下发”：按扫描轴中设备首次出现的顺序执行，每台设备内部的参数作为一个受锁 SCPI 批次。协调器在所有设备完成前不会把本触发记为已应用，也不会开始下一个积压触发。Vaunix 与 NI 的频率/功率扫描位于 Vaunix 专用设置窗口。

```text
NI 累计触发 N
-> 选择联合点 P[(N-1) mod 点数]
-> DG-A 参数批次
-> DG-B 参数批次
-> ...
-> 全部完成
-> applied_count = N
```

“完成偏差”是本联合点各设备批次完成时间最大值与最小值之差，只用于软件时序诊断，不能解释为输出边沿之间的精确电气偏差。

### 11.4 部分下发失败

如果 DG-A 成功而 DG-B 失败，界面显示“部分下发失败”，任务立即停止，失败点不增加 `applied_count`。运行 CSV 保留已成功设备、失败设备、各自耗时和错误。由于已经成功的设备不能由 VISA 事务自动撤销，排除故障后应核对全部仪器实际状态，并从 P0 重新启动任务。

### 11.5 运行日志

日志自动保存在软件配置目录的 `run_logs` 子目录，CSV 使用 UTF-8 BOM，字段包括触发序号、点序号、UTC 下发时间、完成时间、总耗时、设备完成偏差、状态、各设备耗时和错误。任务定义与运行日志分开保存，删除任务不会删除历史运行日志。

## 12. 实机联调步骤

1. 在 NI MAX 中测试 DG4000 `*IDN?`。
2. 在 NI MAX 中确认 NI 设备和 PFI 端子。
3. 首页添加 DG4000、NI；如使用 Vaunix，再通过 DLL 自动搜索添加并连接，核对序列号和型号能力。
4. 关闭 DG4000 输出，设置基本波形并查询回读值。
5. 用 NI 独立计数页面验证外部边沿。
6. 先设置单轴两点低速序列，再增加第二轴验证联合下发。
7. 单步产生触发，核对第一个触发为第一个点。
8. 验证末点后循环。
9. 逐步提高触发速率并监视积压。
10. 在 NI MAX 中先验证模拟输入通道、端接方式、量程和采样率，再用软件选择连续记录路径并进行短时采集；运行期间确认文本文件大小和“已写入文本”计数持续增加。
11. 当前版本通过设备占用锁禁止同一 NI 同时运行计数/联动与模拟输入任务；请先停止当前任务，再启动另一条任务路径。
12. Vaunix 先关闭 RF 验证频率、绝对功率、扫频/选件能力回读，再用 NI 单步验证频率/功率点表的首触发 P0 和循环。
13. 确认安全后再开启输出并接入实验电路。

## 13. 故障排查

| 现象 | 可能原因 | 处理方法 |
|---|---|---|
| 搜不到 DG4000 | 未安装 PyVISA/VISA Backend、USB/LAN 未连接 | 安装驱动，在 NI MAX 中确认资源，或手动输入地址 |
| 搜不到 NI | 未安装 NI-DAQmx Python 或设备别名不同 | 安装依赖，按 NI MAX 中名称填写 `Dev1` |
| 搜不到 Vaunix | DLL 不存在、位数不匹配、USB 未连接或设备被其他程序占用 | 使用 SDK 的 `x64\Release\vnx_fmsynth.dll`，设置 `VAUNIX_LMS_DLL`，关闭厂商示例程序后重新搜索 |
| Vaunix 序列号找不到 | 保存的设备已拔出、插入了另一台设备或资源手工输入错误 | 重新搜索并核对 `VAUNIX::LMS::<序列号>`，不要改用临时设备句柄 |
| Vaunix 功率与预期不符 | 把绝对 dBm 当成相对衰减、误把 0.25 dB 编码当成实际分辨率、型号量程不同或外部链路损耗 | 使用 0.5 dB 网格的绝对 dBm；查看总览实际范围并独立校准外部链路 |
| Vaunix 功能按钮不可用 | 当前型号不报告快速脉冲、Chirp 或 BLX 序列能力 | 以连接后的能力读取为准；不可用功能不会强制下发 |
| 连接失败 | 地址错误、设备被占用、网络不可达 | 刷新、断开其他程序、执行 `*IDN?` 测试 |
| 触发数一直为 0 | PFI/边沿/地线错误、计数器未启动 | 检查接线和有效边沿，先用独立计数页面验证 |
| 收到数增加但下发不增加 | DG4000 断开、SCPI 错误、写线程停止 | 查看状态栏和错误队列，停止后重新连接 |
| 积压持续增长 | 触发快于 SCPI 吞吐 | 降低触发速度或接受延迟，不能靠软件消除物理瓶颈 |
| PSK/FSK 没有效果 | 调制模式未启用或目标通道错误 | 先配置载波、调制类型和通道，再启动步进 |
| 资源被占用 | NI MAX 或其他程序占用计数器/VISA | 关闭测试面板和其他会话，重新连接 |
| 没有模拟通道 | 设备不带 AI、驱动未识别或设备名错误 | 在 NI MAX 查看物理通道；以驱动枚举结果为准 |
| 模拟采集启动失败 | 端接方式/量程/采样率不受支持，或通道被占用 | 改用设备默认端接，降低采样率，检查量程并关闭其他任务 |
| 波形削顶 | 信号超过设置量程 | 停止采集，扩大输入量程并确认不超过硬件绝对最大额定值 |
| 丢弃点数增长 | 内存绘图缓存已满 | 这是正常的长时间采集行为；确认“已写入文本”仍增长，磁盘连续文件不会随缓存丢弃而截断 |
| 已写入文本不增长 | 未启用连续记录、磁盘不可写/已满，或采集任务出错 | 检查勾选项、保存路径、剩余空间和状态栏错误；修复后新建文件重新开始 |
| 中文显示方框 | Qt 未加载中文字体 | 软件会主动加载 Noto Sans SC/微软雅黑/黑体，检查 Windows 字体文件 |

## 17. 版本说明
