# DG4000 + SIGLENT SSG + Vaunix + Newport + NI 多设备联动控制软件使用说明

版本：0.7.26 本地修复候选（当前正式下载仍为 [v0.7.25](https://github.com/Rechoncy/Rigol_Generator_GUI/releases/tag/v0.7.25)）
更新日期：2026-10-29（DG4000 幅度单位空回复的只读兼容；验收与交付状态见[本版记录](../release/NOTES-0.7.26.md)）
适用范围：RIGOL DG4000 系列、鼎阳 SIGLENT SSG、Vaunix Lab Brick LMS/BLX、Newport、带模拟输入/边沿计数能力的 NI DAQ、内置虚拟实验室

本软件用于统一管理多台 DG4000、鼎阳 SSG、Vaunix LMS/BLX、Newport、NI DAQ 和通用 SCPI 仪器。NI 设备可以独立检测外部触发、累计计数和采集模拟电压，但不使用 AO 电压控制发生器。每次检测到新的累计触发后，软件通过 VISA/SCPI 向 DG4000、或通过 Vaunix USB DLL 向 LMS/BLX 下发下一组参数；模拟输入数据在采集过程中逐块写入 CSV/TXT 文本，实时曲线只用于监视。

## 1. 软件能力概览

免 Python 的安装程序 EXE、便携 ZIP 和独立 EXE 见[发行版说明](../release/README.md)。安装版将用户数据保存在独立的 `%LOCALAPPDATA%\RigolGeneratorControl\data`；便携格式默认使用 EXE 旁 `data/`，源码版继续使用 AppData。`--data-dir` 和 `RIGOL_GUI_DATA_DIR` 仍可显式覆盖；本文的源码安装步骤不适用于已经下载的编译版。

鼎阳 SSG 的完整操作见[详细使用说明](SIGLENT_SSG_CN.md)，以 SSG3021X 为主，包含连接、STEP/LIST、两级扫描触发、调制并用及脉冲 BUS 示例。鼎阳使用仪器自身的触发步进，不经过 NI 计数器或软件逐点下发；本章后续的首触发 P0、积压补发和多轴 NI 数据流不适用于鼎阳。停止扫描、关闭调制、RF 关闭及断开连接是独立操作，具体状态含义见该专篇。SSG 窗口在持有自身设备占用时，仍可完成首次连接及必要的停止恢复；这个恢复入口只属于当前记录，首页或同地址别名不能用它绕过运行扫描的占用。恢复后先确认实际状态，继续实验须按要求重新布防。

新增 Newport SMC100CC / PR50CC 循环旋转步进，详见 [Newport 操作说明](NEWPORT_ROTATION_CN.md)。旋转任务启动保持 P0、首触发 P1、末点下一触发回 P0；运动/稳定期间触发报错停止，不补跑积压。可由同一任务同时运行 NI counter 与连续 AI。本章下文的首触发 P0、积压补发及独立采集限制适用于原有 DG/Vaunix 任务，不适用于此旋转控制器。

0.7.20 完善 Newport 手动操作恢复。“寻机械原点”执行 `OR` 建立位置参考；已 READY 且只想回到 0° 时，用“绝对目标 0° → 绝对定位”。`DISABLE` 时可显式点击“恢复使能（电机励磁）”，软件按手册发送本地址 `MM1` 并确认 READY；该动作会重新给电机励磁，不能保证机械位置完全无微动。界面显示中文状态及 `0xXX`，有效的本地状态拒绝不再当作通信断线；停止未确认则保留占用，只能重试停止/清理。完整状态表和操作步骤见[Newport 状态与手动恢复](NEWPORT_ROTATION_CN.md#状态与手动恢复0720)。

扫描页可选择指定初始角度 P0 或使用启动时当前位置。指定角度后可离线预览点表，连接后通过“移动到 P0”准备起点；也可点击“使用当前位置”读取并填入。开始扫描只检查首点已稳定到位，不自动定位；起点参数随配置保存和导入。

- 多设备首页：添加、保存、编辑、删除、搜索、连接和断开设备。
- 软件更新：首页底部检查 GitHub 正式 Release，发现更高版本时后台下载并验证大小与 SHA-256；安装版还可在设备空闲后自动退出、保留数据并安装更新。检查、下载和安装偏好可分别关闭，离线仍可使用仪器功能。
- 独立设置窗口：点击设备后打开新窗口，多台设备可同时操作。
- 鼎阳 SSG 控制：固定射频、STEP/LIST、独立扫描/点触发、AM/FM/PM/单脉冲；SSG3021X/3032X 支持验证后启用的脉冲 BUS 和全局触发按钮，尚未实机验收。
- 鼎阳 SSG 与 Vaunix 支持手动回读频率、绝对功率和 RF 输出开关，结果与参数编辑框分开显示。
- DG4000 控制：双通道基本波形、频率/幅度/输出状态只读回读、输出负载阻抗、调制、扫频、脉冲串、系统命令和原始 SCPI 控制台。
- Vaunix 控制：频率、绝对输出功率、RF、参考源、LMS/BLX 扫频、外部触发、快速脉冲、Chirp、BLX 50 项频率/功率序列、状态与非易失设置保存。
- NI 控制：设备识别、PFI 端子、边沿方向、硬件累计计数器、模拟电压输入、实时绘图、数据保存和诊断。
- 单位切换：常用频率、电压、角度和时间输入可选择显示单位并输入小数，下发前自动换算为 SCPI 基准单位。
- 多轴触发步进：频率、幅度、输出相位、PSK 相位和 FSK 跳跃频率可组成一个联合扫描点。
- 跨设备任务中心：一个 NI 触发源可驱动多台 DG4000，每个扫描轴分别选择设备、通道、参数和单位。
- Vaunix 专用 NI 联动：频率和功率轴可以分别启用，并支持同步联动或笛卡尔组合扫描。
- 任务与证据：跨设备配置和手工点表可以保存、加载、删除；运行过程自动保存逐点 CSV 日志。
- 扫描方式：同步联动按相同序号组合各轴；组合扫描生成笛卡尔积。
- 循环规则：第一个触发应用联合点表第一个点，末点后回到第一个点持续循环。
- 无软件最小触发间隔：硬件累计触发数跳变时，所有缺失序号都会进入有序积压并逐项补发。
- 虚拟实验室：无 DG4000、Vaunix、NI 设备或厂商驱动时也可体验全部主要流程、设备联动和多通道模拟采集。

### 1.1 系统数据流

1. 外部信号或虚拟控制台产生触发。
2. NI 硬件计数器或虚拟计数器保存累计边沿数。
3. 监视线程读取累计数并更新 `received_count`。
4. 协调线程按序号选择联合点；DG4000 使用 VISA/SCPI 受锁批次，Vaunix 使用 `vnx_fmsynth.dll` 类型化调用。
5. 全部设备成功跨过点级完成屏障后才更新 `applied_count`，两者差值就是待处理积压。

### 1.2 重要边界

- 首个点不会在任务启动时预先发送，必须收到第一个触发后才发送。
- 不主动丢弃触发，不把多个触发合并成一次参数变化。
- 不设置固定等待时间，也不设置最小触发间隔。
- 同一联合点的多条命令不会被其他窗口命令插入，但 DG4000 仍按顺序解析，不承诺电气意义上的绝对同时生效。
- 多台 DG4000 的软件下发不承诺物理同步；当前严格顺序模式强调可复现性。微秒级同步需要预装载序列和公共硬件触发。
- 某台设备失败时任务会停止，失败联合点不会增加完成计数；此前成功设备可能已经改变输出，SCPI 无法提供真正事务回滚。
- 如果触发速度高于 DG4000 SCPI 或 Vaunix USB 命令的实际吞吐能力，物理生效时间会落后于触发时间。
- 停止任务后不再开始新的积压点；已经进入 VISA 的操作无法强制撤回，须等待其返回。跨设备途中停止不继续尚未下发的设备，未全部完成的联合点不增加完成计数。确认停止并释放占用后，重新启动才从 P0 和新计数开始。
- 模拟输入是独立采集任务，不会改变首触发和步进循环语义。当前版本用设备占用锁阻止模拟采集、独立计数和联动任务争用同一 NI。

### 1.3 各类设备的回读范围

| 项目设备 | 频率、幅度/功率和输出状态 | 其他说明 |
|---|---|---|
| RIGOL DG4000 | CH1/CH2 的 Hz、仪器实际 Vpp/Vrms/dBm 和各通道输出开关 | “通道与波形”页底部，详见第 7.2 节 |
| 鼎阳 SIGLENT SSG | 载波 Hz、绝对功率 dBm 和 RF 输出开关 | “连接与射频”页底部；原生扫描当前值预览单独保留，详见 [SSG 说明](SIGLENT_SSG_CN.md) |
| Vaunix LMS/BLX | 唯一射频通道的 Hz、绝对功率 dBm 和 RF 输出开关 | “射频输出”页底部，详见第 9.2 节 |
| NI DAQ | 本项目采集模拟输入电压和累计外部边沿 | 不实现 AO 信号发生器，不把采样率或触发数表示为源输出频率/幅度 |
| Newport SMC100CC / PR50CC | 已有角度、速度及运动状态回读 | 运动控制器不适用射频频率/幅度回读 |
| 通用 SCPI 设备 | 可按具体设备手册在控制台手动查询 | 未绑定型号和参数语义，不自动猜测频率/幅度命令 |

三类信号源的专用回读都是手动参数快照：频率/功率/RF 顺序读取，显示本机完成时间，不是同步采样或硬件触发时间戳。输出关闭时仍可读到保存的参数；扫频、脉冲或调制运行时，参数回读不能代替瞬时频率、峰值/包络、平均功率及稳定性的外部电气测量。回读不覆盖待应用编辑值，也不自动开 RF、启动扫描或切换单位。

## 2. 安全与使用前检查

### 2.1 实机电气连接

- 外部触发源接 NI 的 PFI 输入端子。
- NI 与外部触发源必须有可靠参考地。
- DG4000 通过 USB、LAN、GPIB 或串口 VISA 接收软件命令。
- Vaunix LMS/BLX 通过 USB 连接，软件直接调用 Windows `vnx_fmsynth.dll`，不使用 VISA 资源。
- 不要把 NI AO 接到 DG4000 参数控制端。
- 触发联动本身不需要把 DG4000 输出回接到 NI；如需使用新增的模拟采集功能，可将待测模拟信号接到所选 `ai` 通道。
- 确认 PFI 输入电平符合具体 NI 型号的电气规范。
- 确认模拟输入接法、端接方式和量程符合具体 NI 型号及信号源的电气规范。

### 2.2 软件安全

- 首次实机测试时关闭 DG4000 输出，只验证连接和参数读取。
- 首次 Vaunix 实机测试同样保持 RF 关闭，先核对型号能力、频率和绝对功率回读。
- 开启输出前检查幅度、偏置、负载和外部电路耐压。
- 编辑已连接设备的资源地址时，软件会先释放旧连接。
- 关闭程序时会停止虚拟连续触发并清理连接。DG/Vaunix NI 步进、跨设备任务或 NI 独立模拟采集的后台启动、读取、写入或清理尚未完成时，窗口会保留，需先完成停止；关闭请求不等于已经释放资源。

## 3. 安装与启动

### 3.1 基础环境

- Windows 10 或 Windows 11。
- Python 3.10 或更高版本。
- PyQt6。
- 仅使用虚拟实验室时，不需要 PyVISA、NI-VISA 或 NI-DAQmx。
- Vaunix 实机需要 Windows x64 `vnx_fmsynth.dll`；0.7.15 构建脚本内置 SDK 1.15，发行清单确认携带后无需另配路径。源码版可将 DLL 放在项目主目录；虚拟 Vaunix 不需要 DLL。

### 3.2 安装图形界面

```powershell
cd E:\Github_Project\Rigol_Generator_GUI
python -m pip install -e .
python -m rigol_control
```

也可以直接运行：

```powershell
.\run_app.cmd
```

### 3.3 安装实机依赖

先安装 NI-VISA 或兼容 VISA Backend，以及 NI-DAQmx 系统驱动。然后安装 Python 包：

```powershell
python -m pip install -e ".[instrument]"
```

在 NI MAX 中确认：

1. DG4000 VISA 资源可见，并能执行 `*IDN?`。
2. NI 设备名可见，例如 `Dev1`。
3. 计划使用的计数器、PFI 和模拟输入通道没有被其他任务占用。
4. 设备确实报告所需 `ai` 通道和采样率；软件不会仅凭型号名称猜测能力。

Vaunix SDK 不通过 NI MAX 管理。0.7.11 本地编译包直接加载内置 Windows x64 DLL：目录包在 `_internal/vendor/vaunix/vnx_fmsynth.dll`，单文件 EXE 启动时释放到临时运行目录，搬到其他电脑无需再放置此文件或设置变量。便携包必须完整解压并保留 `_internal/`。

运行时仍优先使用环境变量 `VAUNIX_LMS_DLL`，然后检查 EXE 旁 `vendor/vaunix/`，再检查包内 DLL；源码版也搜索主目录与 `lms-sdk-*\LMS_Windows_SDK_*\x64\Release\vnx_fmsynth.dll`。只有需要显式换用其他 Windows x64 SDK 时，才在 PowerShell 中指定：

```powershell
$env:VAUNIX_LMS_DLL = "C:\path\to\vnx_fmsynth.dll"
```

## 4. 设备中心

### 4.1 首页结构

- “刷新状态”只检测设备是否可用，不会保持连接。
- “虚拟实验室”创建并连接一套内置模拟设备。
- “添加设备”打开设备搜索和保存窗口。
- 每张卡片提供连接、断开、打开设置、编辑和删除。
- “可用”表示探测成功但没有保持会话；“已连接”表示会话已由连接管理器保留。

### 4.2 设备配置文件

设备名称、类型、资源地址和连接方式保存在本机 JSON 文件中，默认位置为：

```text
%APPDATA%\RigolGeneratorControl\devices.json
```

首页只显示“设备列表已自动保存在本机”，鼠标悬停时显示完整路径。该文件不是采集数据，也不包含 DG4000 输出波形。

### 4.3 连接生命周期

- 首页和设置窗口共享同一 VISA 会话。
- 关闭设置窗口不会断开设备。
- 断开、删除设备或退出软件前，必须先确认任务和后台操作结束。存在活动占用或正在连接/断开时，不会强行释放连接。
- 编辑或删除设备需要关闭其设置窗口；窗口因任务或后台操作拒绝关闭时，首页会保留记录和窗口，请完成停止后重试。
- 通用 SCPI 的后台原始查询/写入尚未返回时也会拒绝关闭，保留原任务。等待命令返回后再关闭，不要以关闭窗口代替取消或重复发送同一命令。
- 为避免启动后意外控制仪器，连接状态不会跨程序重启自动恢复。

### 4.4 联网检查软件更新

首页最下面的更新区显示当前软件版本，提供“启动后自动检查更新”“检查更新”和“打开发布页”。0.7.25 中，首次检查失败也提供固定发布页入口。“刷新状态”仍用于仪器探测，软件版本检查使用独立入口。

1. 自动检查默认开启。正常启动约 3 秒后发起一次后台检查，保持运行时每 6 小时再检查一次；同一时间只会有一个检查请求。取消勾选可关闭后续自动检查，仍可手动点击“检查更新”。
2. 检查项目 `Rechoncy/Rigol_Generator_GUI` 的最新正式 GitHub Release。只有版本号高于当前运行版本才显示更新提示，比较按数字进行（例如 `0.7.10` 高于 `0.7.9`）；开发分支提交、裸标签、草稿和预发布不作为正式更新。
3. 发现新版时，更新提示持续显示在首页底部，不弹出需要立即处理的模态窗口。“发现更新后自动下载”默认开启：有可验证的适用附件时，后台开始下载并显示进度；可取消或手动重试。取消自动下载勾选可只保留版本提示，由用户选择是否下载。点击“打开发布页”也可在浏览器阅读说明和下载附件。
4. 安装版提供默认开启的“下载后自动安装（空闲时）”。校验完成后先等待设备任务结束，再正常退出并由安装程序保留、备份和恢复用户数据；详见下一节。关闭自动安装后可点击“安装更新”。便携 ZIP 和独立 EXE 继续手动迁移：先导出配置、停止任务并退出旧程序，再将新版放到新目录，复制原 `data/` 或导入配置；下载完成不等于已经切换到新版本。
5. 0.7.25 在 GitHub API 限流时尝试本仓库官方发行清单；两种方式均无法确认时才报告检查未完成，不把失败当作“已经是最新版”。没有网络、代理不可达或回复异常时，仪器连接、扫描和本地配置继续使用；可通过“打开发布页”在浏览器查看正式版本。成功结果复用 60 秒，失败后冷却 30 秒，API 重试另遵守 GitHub 返回的等待时间；这些状态仅保存在本次进程内存中，不写数据文件，不需要反复点击。整个检查保持约 15 秒的时限，并限制回复大小。若提示“系统代理检测仍在进行”，等待系统原有代理查询返回后再重试；检查和关闭窗口不等待该原生查询结束。

联网通过 HTTPS 读取上述公开仓库的发布元数据及用户启用的更新附件，使用系统代理配置并验证服务器证书；无需 GitHub 登录或访问令牌，不上传仪器地址、参数、实验数据或配置。程序不会修改全局代理设置。自动检查、下载和安装偏好保存在当前数据目录的 `update_settings.json`，遵循 `--data-dir`、`RIGOL_GUI_DATA_DIR` 及当前发行格式的数据目录规则；这些本机偏好与设备配置包分开，迁移完整数据目录时可一起携带。偏好文件损坏或无法读取时暂停自动行为并显示原因，仍可手动检查或重新选择偏好。

**遇到“GitHub 暂时限制请求”：** GitHub 匿名 API 额度按出口 IP 共享，每小时 60 次，单位/校园网络或代理上的其他程序也可能消耗额度。普通 HTTP 403 也可能是代理或访问策略拒绝，不能只凭旧版这句提示认定具体原因。0.7.25 读取限流信息并尝试官方清单，仍不要求登录或访问令牌。v0.7.24 及更早程序没有这条备用通道；本次正式 v0.7.25 可被旧更新器检测，但已限流时仍需等待额度恢复，或从正式发布页手动下载 Setup，先停止任务并正常退出旧版，再安装并沿用原用户数据目录。旧程序不能在尚未安装修复时自动拥有新逻辑，不要因此删除配置或反复重装旧版。规则见 [GitHub API 限流说明](https://docs.github.com/en/rest/using-the-rest-api/rate-limits-for-the-rest-api)。

**下载文件与校验：** 安装版选择 `-setup.exe` 安装程序；独立 EXE 选择对应的独立 EXE，目录便携版和源码选择便携 ZIP，更新区显示当前选择。只使用本仓库该版本的 Windows x64 附件，保存到当前数据目录的 `updates/v版本号/`，完成后可点击“打开下载文件夹”查看。下载必须与已确认的 GitHub API 或官方发行清单中的字节数和 SHA-256 均一致才标为完成，自动安装前还会重新核对已下载文件；备用清单同样检查版本、附件名称和官方来源，不降低下载校验。缺少适用附件、有效校验值或元数据不匹配时，保留版本提示和发布页入口，不进行自动下载。下载器不覆盖旧包；同名包已存在时会重新校验，匹配后直接使用，内容不同则保留原文件并报错。

再次检查得到同一更新时，保留已经校验的 Setup 和正在等待设备空闲的安装，不重复下载。安装请求失败后，再次检查同一版本不会自动重试安装；确认问题已排除后可显式点击“安装更新”。

**下载异常：** 下载与仪器工作队列分开，网络慢时仍可操作设备。单次下载最多 10 分钟（含系统代理解析），网络无数据等待限制为 30 秒；取消或关闭后的迟到结果不能改成成功，也不等待后台网络退出。失败后可显式重试，本次失败不立即循环重试。取消或失败时尝试清理未完成的 `.part` 临时文件；若进程异常退出而留下 `.part`，该文件不算可用更新包，应重新下载。自动下载支持系统 HTTP 代理/PAC，会按实际附件地址和 GitHub 下载跳转分别解析代理；仅有 SOCKS 代理时显示不支持，可通过“打开发布页”在浏览器下载，版本检查本身仍支持 Qt 提供的代理类型。

只有普通交互启动自动安排联网检查。`--smoke-test`、单元测试及 `--bundle-self-test` 的默认验证流程不访问 GitHub；测试通过不等于目标实验电脑一定能访问 GitHub。

数据目录名称中的中文、空格、单引号和花括号按实际路径保存；例如 `{lab}` 不会被再次解释为安装器常量。首次安装、升级和重新打开后都应使用同一个所选目录；安装版不会改用程序旁的 `data/`，便携版仍保留其原有目录规则。

**后续自动升级：**

1. 安装版从 GitHub 正式 Release 下载适用的安装程序，核对大小与 SHA-256。安装选项与下载选项独立，默认开启；取消“下载后自动安装（空闲时）”可改为手动点击“安装更新”。便携版不会把独立 EXE 当安装程序执行，需先使用本版 Setup 安装才能使用安装版自动升级。
2. 有扫描、触发、模拟采集、后台通信、配置导入或未确认清理时，保留当前任务与窗口，等待空闲；关闭自动安装可取消等待。软件不会强制结束进程、重放仪器操作或把停止失败当作已经停止。手动安装遇到占用时，先完成停止，再点击安装重试。
3. 正常关闭被接受后，Windows 自带 PowerShell 交接程序等待旧进程完全退出，再启动已校验的安装程序。程序仍在运行或关闭被拒绝时，不应卸载旧版本。
4. 安装程序先备份当前数据目录，再卸载登记的旧安装版、安装新版，最后核对原文件并恢复缺失文件。备份包括该目录内的设备/参数/任务/更新偏好、日志、测量文件和空目录；下载缓存 `updates` 不作为用户数据备份。保存在数据目录外的采集文件不移动或删除，需要单独备份。
5. 原数据目录通常无需移动。已存在且内容一致的文件继续使用，缺失文件从备份恢复；同名文件内容不同、备份损坏或文件不可读时，保留数据和备份并报告失败，不静默覆盖冲突文件。安装后重新打开软件会加载原配置，但不会自动开启 RF、启动扫描或移动波片架。

如果已经提交安装交接，却因磁盘权限或空间问题无法确认撤回，软件会保持进程并阻止未确认的退出。保留窗口，排除保存错误后重试取消或关闭；不能把撤回写盘失败当成已取消安装。安装程序也会等待旧版卸载的临时工作进程清理完程序文件与登记项，再继续安装。

备份失败会阻止卸载。若安装程序、磁盘或权限错误导致安装中断，独立数据目录与备份仍保留；这不等于旧程序已经自动回滚，可保留日志、修复环境后重新运行安装程序。不要在升级过程中清理备份、更新下载目录或修改正在备份的文件。

**旧便携版首次迁移：** 先在旧软件导出配置并停止任务、退出，再运行安装程序。可在向导中选择原便携版的 `data/` 作为独立数据目录，也可使用默认目录后在安装版首页导入配置。若要迁移整个数据目录内的日志和测量文件，在新旧软件均退出时备份并复制原 `data/` 内容到安装版数据目录。配置导入只包含设备及任务配置，不包含采集文件，原程序和数据备份应保留。

## 5. 添加和搜索设备

<!-- SCREENSHOT: 02-add-device-discovery.png | 图 2 资源地址为可编辑下拉框，虚拟设备无需驱动即可发现 -->

### 5.1 自动搜索

- DG4000 和通用 SCPI 使用 VISA 资源管理器枚举资源。
- NI DAQ 使用 NI-DAQmx 枚举 `Dev1` 等设备名。
- Vaunix LMS/BLX 直接使用 `vnx_fmsynth.dll` 枚举 USB 设备，显示真实型号和序列号；保存资源为 `VAUNIX::LMS::<序列号>`，不会保存本次枚举的临时句柄。
- 软件根据资源前缀自动匹配 USB VISA、TCP/IP VISA、GPIB VISA 或串口 VISA。
- 下拉项可以显示产品说明，但保存时只写入真实资源名。
- “重新搜索”在设备插拔或 NI MAX 配置改变后重新枚举。

### 5.2 手动输入

资源框始终可编辑。驱动未安装、网络设备不支持自动发现或特殊 VISA Backend 未枚举时，可以手动输入：

```text
USB0::0x1AB1::...::INSTR
TCPIP0::192.168.1.88::INSTR
Dev1
VAUNIX::LMS::4030123
```

DG4000、鼎阳 SSG 与通用 SCPI 使用相同 VISA 地址时视为同一资源，不因设备名称或类型不同而允许重复保存或同时连接。已有旧列表仍能读取，但其中相同地址的记录互斥，不能从另一条记录插入手动命令或启动任务。资源比较会忽略大小写及首尾空白；不能据此推断同一实体仪器的 USB 和 LAN 两种不同地址也会自动识别为一个资源，实验中仍应为每台仪器保留一致的连接方式。

连接/断开期间，同资源暂不可由另一记录连接、手动操作或启动 NI 联动。请等待当前操作完成后重试，不要反复创建重复记录。

### 5.3 内置虚拟资源

```text
SIM::DG4000::1
SIM::DG4000::2
SIM::NI_DAQ::1
SIM::VAUNIX_LMS::1
```

它们不依赖厂商驱动，适合功能体验、界面开发、演示、回归测试和触发积压调试。

### 6.4 单次、批量和连续触发

- 单次：每次增加一个累计触发，适合核对首点和逐点顺序。
- 批量：一次增加多个累计触发，适合验证软件不会丢失两次读取之间的触发。
- 连续：按设定毫秒周期自动发送，适合长期运行和界面监视。
- “累计发送”是虚拟 NI 自创建以来的总数；触发任务只统计启动后的增量。

### 6.5 调试积压

虚拟 DG4000 的“模拟下发延迟”范围为 0 至 2000 ms。增大该值相当于降低 VISA/SCPI 吞吐速度。

1. 设置模拟延迟为 80 ms。
2. 启动触发任务。
3. 从虚拟 NI 批量发送 12 次触发。
4. 观察“收到 12、已下发较少、积压大于 0”。
5. 停止发送并等待，最终“已下发 12、积压 0”。

## 7. DG4000 设置窗口

### 7.1 总览

显示 VISA 资源、连接方式、`*IDN?` 身份信息、通道状态和虚拟实时状态。实机“连接设备”会建立并保留 VISA 会话，“执行自检”发送 `*TST?`。

连接后可点击“回读频率 / 幅度”，跳转到“通道与波形”页并执行一次参数回读，见下一节。

### 7.2 通道与波形

支持 CH1 和 CH2：

- 正弦波、方波、锯齿波、脉冲、噪声和任意波。
- 频率、幅度、直流偏置和初相位。
- 频率支持 Hz/kHz/MHz，幅度支持 Vpp/mVpp，偏置支持 V/mV，相位支持度/rad。
- 输出开启和关闭。

未连接时，频率编辑器保留 DG4000 全系列最高 200 MHz 的配置范围。连接后从 `*IDN?` 识别型号，使用该型号总频率上限，并在应用基本波形前进一步检查所选波形：

| 波形频率上限（MHz） | DG4062 | DG4102 | DG4162 | DG4202 |
|---|---:|---:|---:|---:|
| 正弦 SIN | 60 | 100 | 160 | 200 |
| 方波 SQU | 25 | 40 | 50 | 60 |
| 锯齿 RAMP | 1 | 3 | 4 | 5 |
| 脉冲 PULS | 15 | 25 | 40 | 50 |
| 任意波 USER | 15 | 25 | 40 | 50 |

上述周期波形的官方最小频率与频率分辨率均为 1 μHz，软件拒绝低于该最小频率的设置。例：DG4102 的正弦 80 MHz 在总上限内，但方波 80 MHz 超过其 40 MHz 限制，基本波应用会在写入前拒绝。噪声带宽不作为 `FREQ` 可设置范围；本表不为 NOIS/DC 或未知型号推断周期波形特性，未知型号不具备完整规格校验保证。具体幅度、负载及固件条件仍以仪器资料和实际回读为准，来源见[专项说明](DG4000_TRIGGER_AUDIT_CN.md)。

应用基本波形时，软件先检查参数，再在受锁批次中顺序下发；不隐式写入 `:OUTP<n>:LOAD`，因此修改频率或波形不会覆盖已经设置的负载阻抗。幅度按 Vpp/mVpp 输入，命令明确携带 `VPP` 后缀，例如 `:SOUR2:VOLT 2VPP`；即使仪器面板当前选择 VRMS 或 dBm，也按 2 Vpp 解释。此规则同样用于幅度触发步进和 ASK 键控幅度，不增加每点查询或额外设置。

#### 读取仪器当前值

1. 连接 DG4000，打开“通道与波形”，在页面底部找到“仪器频率与幅度回读 · 手动快照”。也可从“总览”的“回读频率 / 幅度”直接进入。
2. 点击“回读频率 / 幅度”，在后台一次读取 CH1、CH2 的频率、幅度、当前幅度单位与输出开关；完成后显示本机回读时间。频率以 Hz 显示，数值文本可选中复制。
3. 回读区和上方待应用的编辑值相互独立。回读不会把仪器值写入编辑框，也不会下发频率、幅度、单位、负载或输出开关设置。

正常单位回复时，幅度按仪器实际返回的 Vpp、Vrms 或 dBm 显示，不默认换算为 Vpp，也不根据假定的 50 Ω 负载换算。输出关闭时，频率和幅度仍是仪器保存的配置参数，不代表端口正在输出该信号。

0.7.26 候选增加单位查询空回复的兼容路径：只读同通道的高、低电平，前后各一组；数值有效且两组一致时，取高低差显示 Vpp，并标注“高低电平差；仪器当前幅度单位未知”。空白及成对引号中的空内容也按空值处理，不配对引号仍报无效。该差值以手册规定的 V 电平查询得到，不改变仪器面板单位，也不按负载或 RMS 假设换算。非空但未知的单位、超时或查询异常不采用此路径；高低电平前后不一致或任何字段无效仍使整组快照失效。

用户现场为 DG4162 + USB，截图中的 `:SOUR1:VOLT:UNIT?` 是手册合法短写，空串本身不能证明仪器不支持，也不足以确定传输或固件根因。使用候选后再次点击回读，留意是否显示上述兼容来源；若仍报错，请保留完整错误、`*IDN?` 中的型号/固件与连接方式后反馈。无需先改单位、重置仪器或应用参数；软件不会自动重连、清缓冲或下发设置。此兼容尚未在该实机验证，不把候选通过软件回归等同于实机问题已经解决。

频率来自仪器的载波/基本波参数查询。原生扫频、FSK 或其他调制运行时，它不等于扫频轨迹中某一瞬间的实际信号频率或包络幅度；需要电气实测时仍应使用相应测量仪器。CH1、CH2 在同一通信批次内顺序读取，也不承诺两个通道的电气同时采样。

此功能仅手动刷新，不自动轮询或在每个 NI 触发点追加查询。触发/联动任务运行期间可按需单次回读，查询与参数写入在共享会话中串行执行，会占用一次通信时段。回读失败不会自动重连或重放设置，以免改变运行任务的连接代次；失败或断连后回读值失效并显示未知，不继续把旧值视为当前状态。

如果读回过程中仪器幅度单位发生变化，整组结果会作废并提示重新回读，避免给幅度标上错误单位。请停止切换仪器单位后再点击回读。

从 0.7.19 起，即使共享连接在两次界面状态同步之间已断开并重新连接，之前完成的 CH1/CH2 回读快照及时间也会失效并显示未知。重新连接后点击回读即可取得新快照；新连接上已经开始的回读不会被随后的同代次状态同步误清除。这项缓存核对只读取本机连接代次，不新增仪器查询或自动刷新。

### 7.3 调制

提供 AM、FM、PM、ASK、FSK、PSK 和 PWM 页面，可选择 CH1/CH2、内部/外部调制源、内部波形、调制频率及对应参数。调制频率、频偏、键控幅度、调制相位和脉宽偏移使用与物理量匹配的单位选择器。

对于本项目的触发步进：

- PSK 相位目标写入 `:SOUR<n>:MOD:PSK:PHAS <value>`，与输出相位一样在换算为度后检查 0–360°（含端点），不会自动折返负角度或超范围值。
- FSK 频率目标写入 `:SOUR<n>:MOD:FSK:FREQ <value>`。
- 开始步进前应先配置载波并启用相应调制模式。

### 7.4 扫频和脉冲串

扫频支持线性、对数和步进间隔，设置起始频率、终止频率、时间和触发源。脉冲串支持 N 周期、无限和门控模式，设置周期数、内部周期和起始相位。频率、时间和角度均可切换单位。

### 7.5 存储、系统与 SCPI 控制台

本页集中管理 CH1/CH2 输出负载阻抗。两个通道的界面默认值均为 50 Ω，并支持高阻、75 Ω、600 Ω和 1 至 10000 Ω 自定义整数值；既可逐通道应用，也可一次应用两个通道。负载命令独立于波形命令，仅在点击对应应用按钮时下发。

根据项目内 DG4000 编程手册，负载命令为 `:OUTP<n>:LOAD <value>`，接受 `INFINITY` 或 1 至 10000 Ω 的整数。它用于告诉仪器外部实际负载，以校准显示和输出幅度；不等同于把输出级固有源阻抗物理改成任意值。连接实物前仍须核对终端方式、实际负载和幅度，仪器返回错误时应读取错误队列。

本页还提供保存状态、调用状态、恢复默认、读取错误队列和原始 SCPI 控制台。控制台不会限制命令集合，因此编程手册中的型号或固件特有命令仍然可达。原始命令按用户原文发送，不自动补上 VPP 后缀；使用原始幅度命令时应自行明确单位。

普通手动设置遇到通信错误允许原有的一次连接恢复，但如果重新读取的型号或序列号与原设备不同，会拒绝继续应用旧配置。请核对资源地址和仪器身份，通过重新读取身份或断开后重连确认当前设备，再重新应用设置。显式单通道 OFF 不依赖耦合查询，但同样不能在身份错配后自动发给另一台仪器；如需立即确认输出关闭，应查看实际仪器面板。

查询命令以 `?` 结尾，例如：

```text
*IDN?
:SYST:ERR?
:SOUR1:FREQ?
```

写命令示例：

```text
:SOUR1:FREQ 1000
:SOUR1:VOLT 2.0VPP
:OUTP1 ON
```

## 8. NI 设置窗口

### 8.1 连接含义

NI 设备不是 SCPI 仪器。“连接”表示 NI-DAQmx 能成功识别设备并读取产品类型、序列号和模拟输入物理通道，不代表已经持续占用计数器或 ADC。实际任务在点击“开始计数”、启动 DG4000 联动或点击“开始采集”时创建。

### 8.2 触发输入

- 选择 PFI 输入端子。
- 选择上升沿或下降沿。
- 可选 NI 硬件数字滤波。
- 软件不通过定时轮询单个脉冲，而是读取硬件累计边沿数。

### 8.3 计数器

选择 `ctr0` 至设备支持的最大计数器。独立计数页面可验证接线，联动任务会创建自己的累计计数器对象。若出现资源占用错误，关闭 NI MAX 测试面板和其他使用相同计数器的程序。

0.7.16 的独立计数在后台停止；如果 NI 任务关闭失败，保留原计数任务与设备占用，状态显示“停止未确认”。排除对应 NI 错误后再次点击停止，确认完成前不能重新计数、采集或关闭窗口。

如果错误为“原生清理未确认”，说明 NI-DAQmx 在关闭报错后已丢失原生任务句柄，软件无法继续证明资源释放；按第 8.7 节处理，不能以反复停止代替恢复。

### 8.4 路由和诊断

路由页面记录建议接线。诊断页面检查 Python 包、系统驱动、设备名和端子能力。最终可用计数器数量以 NI-DAQmx 对实际型号的报告为准。

### 8.5 模拟输入配置

“模拟输入”页连接后自动枚举 NI-DAQmx 报告的 `ai` 物理通道。配置项包括：

- 并行通道：“采集端口”是带复选框的可多选下拉列表。展开后逐路勾选，或使用“全选/清空”；收起后显示已选数量和端口摘要，下方显示“已勾选 N / 总数 路”。
- 采集方式：全部勾选通道加入同一个 NI-DAQmx 连续采集任务，共享同一硬件采样时钟和采样率；每次读取返回各通道同样数量的对齐样本。设备是同步采样还是多路复用采样取决于具体 NI 型号。
- 端接方式：设备默认、RSE、NRSE、DIFF 差分和伪差分。必须根据实际接线和设备手册选择。
- 采样率：界面支持 Hz/kHz/MHz，小数会在创建任务前换算为 Hz；若硬件将请求值校正到可实现时钟，时间轴和 CSV 使用 NI-DAQmx 回读的实际采样率。
- 输入量程：上下限可分别使用 V 或 mV；下限必须小于上限。
- 每次读取点数：一次从 NI-DAQmx 缓冲区读取的每通道样本数，会影响界面更新频率。
- 内存保留上限：范围为 1000 至 5000000 点/通道。达到上限后自动丢弃最早数据，并显示累计丢弃点数，避免无限占用内存。
- 连续文本记录：默认启用。可选择 `.csv` 或 `.txt` 路径；若文件已存在，软件自动增加序号，不覆盖历史记录。

采集任务使用 NI-DAQmx 硬件采样时钟和连续采样模式。软件上限不是设备能力承诺；可用通道、总采样率、量程、端接方式和与计数任务的并行能力，始终以实际硬件和 NI-DAQmx 错误报告为准。

### 8.6 实时绘图与连续文本记录

- 实时图最多显示最近 50000 点，通道使用不同颜色；数据多于横向像素时按像素保留最小值和最大值，避免窄脉冲在抽点中消失。
- 指标显示通道数、每通道累计点数、采集时长、保留/丢弃点数以及已经写入文本的点数；下方显示最近数据块的最小值、最大值和 RMS。累计点数表示软件已接收的样本，“已写入文本”仅在整块写入并成功刷新后增加，两者在写盘失败时可能不同。
- 点击“开始采集”前，软件打开连续记录文件。每读取一个 NI 数据块，就按样本顺序追加写入并刷新文件，因此运行期间文件会持续增长，异常退出前已刷新完成的数据仍可读取。
- 连续文件使用 UTF-8 BOM，包含格式版本、UTC 创建时间、实际采样率、首样本序号、连续记录标记，以及 `sample_index`、`elapsed_s` 和各通道电压列。
- 多通道文件中每个采样时刻占一行，每个勾选通道占一个独立电压列；列名使用 NI-DAQmx 物理通道名。实时图为各通道分配不同颜色并在图例中显示 `ai` 名称。
- 内存保留上限只约束实时绘图缓存。即使“丢弃点数”持续增加，磁盘文本仍保存从首点开始的完整连续序列；软件检测到样本序号跳变、通道变化或采样率变化时会停止并报告错误，避免静默生成伪连续文件。
- “导出缓存 CSV”是辅助功能，只保存当前仍在内存中的最近窗口。软件不保存波形图片；曲线用于实时查看，不替代原始文本。
- 触发联动和模拟输入相互独立；模拟输入不改变触发计数，也不会通过 AO 向 DG4000 写电压。

成功刷新表示 Python 文件缓冲区已经提交到操作系统，不是断电持久化保证。写入或刷新失败的数据块可能在文件尾部留下部分内容，不能仅凭可见行数认定该块完整；软件不会自动补写或重放这块数据。

### 8.7 停止、异常与恢复

1. 点击停止采集后，由后台等待读取线程退出并清理 NI 任务与文本文件。停止期间界面仍可响应，但不能重新开始采集或清空本次数据。
2. 读取、写入或刷新错误会显示错误状态，保留已接收点数、成功保存点数、路径与错误信息。文件关闭时即使刷新失败也会尝试关闭句柄，不把清理错误覆盖成正常停止。
3. 停止超时、NI 任务关闭失败或文件句柄尚未关闭时，软件保留控制器与设备占用，按钮显示“重试停止”。此时窗口不能关闭，首页也不能通过断开、编辑或删除释放该设备供另一任务使用。
4. 保留窗口和错误内容，待正在进行的读取或系统调用返回；检查 NI-DAQmx 报错、文件权限、磁盘空间与目标目录，再重试停止。只有读取及全部清理确认结束后，才允许启动新的独立计数、采集或联动任务。
5. 写盘失败后先核查原文件，必要时另存已有完整内容。新的采集使用新文件，不将缓存导出当作对失败连续文件的自动修补。

特殊情况：NI-DAQmx 的关闭操作可能在报错的同时丢失原生句柄。软件此时显示“原生清理未确认”，保留任务与占用，不把再次关闭的空操作当作成功，也不恢复旧句柄。当前进程内无法用普通停止重试确认这类清理；需结束本次实验，在 NI MAX/驱动层核对设备资源后重新启动软件。不要通过另一个记录或另开同卡任务绕过未知状态。

这类状态不会提供强制解除占用。请保留错误和记录文件，先确认硬件已停止；若因未确认占用无法正常退出，可在任务管理器中结束本软件进程后重启。记录文件可能含未完成的数据块，须单独核查，不能据保存点数推断文件尾部完整。

错误状态与资源是否已释放是两件事。即使已停止读取，仍可能需要完成 NI/文件关闭；停止按钮执行完毕或状态文字变化本身不足以证明底层资源已关闭。

## 9. Vaunix LMS/BLX 设置窗口

### 9.1 自动检测、连接与能力识别

添加设备时选择 `Vaunix LMS/BLX`。软件加载 Windows SDK 后调用设备枚举、型号、序列号和状态接口；列表中使用 `VAUNIX::LMS::<序列号>`，连接时再次按序列号匹配，因此即使 USB 插拔后临时设备句柄顺序改变，也不会误连其他设备。虚拟资源 `SIM::VAUNIX_LMS::1` 始终可选。

连接后总览读取并显示：型号、序列号、SDK 版本、最小/最大频率、最小/最大绝对功率、快速脉冲、Chirp、BLX 序列能力，以及连接、打开、PLL、扫频和选件状态位。不支持的快速脉冲、Chirp 或 BLX 序列操作会被禁用，驱动层仍会二次拒绝不合法调用。

### 9.2 射频输出

- 当前频率支持 Hz、kHz、MHz、GHz 小数输入，DLL 内部使用 10 Hz 单位。
- 功率输入是绝对 dBm，不是 DG4000 的 Vpp。DLL 参数以 0.25 dB 为编码单位，即 `powerlevel = dBm × 4`；但手册同时明确仪器实际功率分辨率为 0.5 dB，因此软件只允许 `.0` 或 `.5 dBm` 网格，并按连接设备报告的上下限校验。
- RF 开关与内/外参考源独立设置。
- 恢复软件参数只更新界面，不会自动打开 RF。点击“应用输出参数”会先完成整组数值和 SDK 编码检查，通过后再按参考源、频率、功率和 RF 的顺序写入；输入错误不会先改变参考源或其他参数。

页面底部的“仪器频率与幅度回读 · 手动快照”与这些编辑框分开。连接后点击“回读频率 / 幅度”，后台读取 Hz、绝对功率 dBm 和 RF 输出开关，完成后显示本机时间；也可从“总览”的同名按钮直接跳转并读取。RF 关闭显示“关闭（未输出）”，此时频率和功率仍是设备保存的设置。

SDK 的 `GetFrequencyEx` 返回值乘以 10 得 Hz，`GetAbsPowerLevel` 返回值乘以 0.25 得绝对 dBm；`GetPowerLevel` 是相对于最大功率的衰减值，不能作为绝对输出功率。手动回读使用前两者及 `GetRF_On`，不更改参考源、频率、功率或 RF。SDK 在扫频时报告的当前设置也不等于外部电气测量。

同一次请求的任一项无效或失败时整组显示未知；断连、连接更换或迟到的旧结果不能保留为当前值。没有自动回读或按触发查询，不自动重连。NI 触发任务运行时可使用此专用只读按钮，查询与 SDK 写入串行，可能增加通信等待；普通手动设置仍须先停止任务。

### 9.3 LMS/BLX 扫频与 Chirp

通用扫频参数包括起始频率、终止频率、步长、向上/向下、单次/重复、单向/双向以及内部/外部触发。LMS 型号使用总扫频时间；BLX 型号使用每点驻留时间和重复空闲时间，界面会依据型号启用相应控件。整组时间和频率先检查，包括按 SDK 10 Hz 分辨率转换后起止方向是否仍有效、步长是否变为 0；检查失败不发送任何设置。“启动扫频”和“停止”调用设备端扫频引擎，不依赖 NI 软件逐点下发。

支持 Chirp 的型号还可设置启用状态、Chirp 长度、重复周期和外部触发。Chirp 与普通扫频共用启动/停止入口以及外部扫频触发配置，切换模式前应先停止当前运行。

### 9.4 脉冲调制

快速脉冲页设置 RF 开启时间、重复周期、内部快速脉冲启用和外部脉冲调制输入。开启时间范围为 100 ns 至 1000 s，周期必须不小于开启时间。未安装内部脉冲选件的型号会禁用内部时间和开关，但仍允许单独尝试外部脉冲输入；若该硬件配置也不支持外部输入，DLL 会返回明确错误。

### 9.5 BLX 设备端序列

BLX 可编辑最多 50 项序列。每项包含频率、绝对功率，以及“是否同时控制功率”；未勾选时该项只改变频率。还可设置起始索引、每项驻留和重复空闲，并执行运行一次、重复运行、暂停、继续和停止。点击“写入全部序列”先检查全部行、频率/功率编码、0.5 dB 功率网格、起始索引与驻留/空闲时间，通过后才按索引写入设备端。最后一行或时间字段无效时，前面的行也不会提前写入。真实与虚拟设备采用相同输入检查。

整组预检只保证软件能发现的输入错误在写入前被拒绝。检查通过后若 USB/SDK 调用失败，已经接受的前面设置仍可能生效，不承诺回滚；应先核对仪器实际参数，不直接重放整组。

设备端 BLX 序列适合使用仪器自身定时执行；下一节的 NI 联动则在每个 NI 边沿后通过 USB 下发点表，两者不要同时运行。

### 9.6 NI 触发频率/功率扫描

Vaunix 的专用联动页选择一个已经连接的 NI 设备、`ctr`、PFI、上升/下降沿和扫描方式。频率轴与功率轴可以分别启用：

- 同步联动：两个轴都启用时点数必须相同，第 i 个频率与第 i 个功率组成 Pi。
- 组合扫描：生成全部频率/功率笛卡尔积，功率轴变化最快。
- 单轴扫描：关闭另一个轴后，只下发启用轴的值，未参与的硬件参数保持原值。

功率扫描起点、步长、自动生成点和手工修改点均必须是 0.5 dB 的整数倍。界面按钮步长设为 0.5 dB；若手工键入 0.25 dB 网格值，生成或启动任务时会明确拒绝，不依赖仪器自行取整。

点表生成后仍可手工输入小数。任务启动不会预先改变输出；第一个累计边沿下发并保持 P0，第二个边沿下发 P1，末点后回到 P0 永久循环。系统不设置最小触发间隔，计数跳变会形成有序积压并逐点补发；当触发速率高于 USB 参数下发吞吐时，物理生效会滞后但顺序不会主动丢弃。

启动时 Vaunix 与 NI 都会取得设备租约，避免与设备端序列、独立计数或模拟采集任务争用。后台启动、监视、写入及 NI 清理确认全部结束后才释放占用；超时或清理失败时显示“重试停止”，保留原任务，不允许重启或关闭窗口。具体恢复步骤与第 10.8 节一致。

运行期间先停止任务，再执行 Vaunix 手动设置；软件在按钮提交和后台实际执行时都检查占用，并串行保护整个操作，防止先排队的手动命令进入后来启动的任务。第 9.2 节专用只读回读按钮允许单次查询，仍与写入串行。连接状态栏读取的是软件缓存，不等待较长的 SDK 调用，也不代替实际硬件回读。

Vaunix 单个步进点仅接受其唯一射频通道（通道 1）的频率/功率，空点或通道 2 会在下发前拒绝；同一点所有参数先完成校验，再按序下发。任务写入器绑定布防时连接，断开或重连后旧任务不能继续发送，需停止并重新布防。触发点设置失败只调用一次，不重发该点；如果前一个参数已接受，软件不会回滚，须核对仪器实际状态。

### 9.7 状态、软件参数与设备存储

“状态与存储”可刷新全部回读参数和状态位。每个 Vaunix 设备窗口的频率、功率、单位、扫频、脉冲、Chirp、BLX 序列表和 NI 联动点表都按稳定设备 ID 自动保存在 `device_parameters.json`；重开窗口只恢复界面，不自动下发或启动。

“保存当前设置到设备”调用 SDK 的非易失存储接口，可能改变下次设备上电状态，因此必须单独确认。软件自动参数保存与设备非易失保存是两个独立动作。

开始扫频、非 STOP 的序列控制及保存设备设置只调用一次，SDK 报错后不自动重试，因为操作可能已经被接受。普通幂等参数设置和 STOP 保留原有的短暂 USB 错误重试。报错后先读取/核对实际状态，不把失败弹窗当作设备完全没有动作的保证。

## 10. DG4000 触发步进详细说明

### 10.1 五类步进目标

| 目标 | SCPI 模板 | 常用单位 |
|---|---|---|
| 输出频率 | `:SOUR<n>:FREQ <value>` | Hz、kHz、MHz |
| 输出幅度 | `:SOUR<n>:VOLT <value>VPP` | Vpp、mVpp |
| 输出相位 | `:SOUR<n>:PHAS <value>` | 度、rad |
| PSK 调制相位 | `:SOUR<n>:MOD:PSK:PHAS <value>` | 度、rad |
| FSK 跳跃频率 | `:SOUR<n>:MOD:FSK:FREQ <value>` | Hz、kHz、MHz |

### 10.2 单位、小数与基准值

界面中的单位只改变输入和显示方式，不改变发送到仪器的物理量。例如 `0.2 kHz` 会在点表中显示为 `0.2`，下发时转换为 `200 Hz`；`750 mVpp` 转换为 `0.75 Vpp`；`3.141592654 rad` 约等于 `180 度`。单位切换时软件先保存基准值再换算新显示值，因此从 `1 kHz` 改为 MHz 后显示 `0.001 MHz`，不会把频率误改为 `1 MHz`。

常用单位包括：

| 物理量 | 可选单位 | SCPI 基准单位 |
|---|---|---|
| 频率 | Hz、kHz、MHz、GHz | Hz |
| 幅度 | Vpp、mVpp | Vpp |
| 电压偏置 | V、mV | V |
| 角度 | 度、rad | 度 |
| 时间 | s、ms、us | s |

0.7.10 起，数值输入框和收起状态的单位/参数下拉框不会随鼠标滚轮改变内容，已有焦点时也不改值。鼠标位于输入框上时，滚轮用于滚动所在页面或表格；展开下拉列表后可用滚轮浏览选项。修改数值请直接键盘输入、使用键盘方向键或点击数值框增减按钮。

数值编辑器保留最多 9 位小数；DG、跨设备及 Vaunix 可编辑点表使用能往返还原原浮点值的最短格式，不再固定为 12 位有效数字。例如在 Hz 单位下，`100000000.000001` 和 `100000000.000002` 两个点在表格显示、重新读取和 DG 数值命令中保持不同。保存 JSON 原来已保留原始浮点值，本次修复显示/编辑及 DG 命令序列化路径。软件仍使用浮点数，不提供任意精度计算；实际仪器分辨率和可用范围按型号与波形决定。Vaunix 仍按 SDK 的 10 Hz 频率单位和仪器 0.5 dB 功率网格编码，表格保留数字不会提高硬件分辨率。

### 10.3 扫描轴与联动方式

每个扫描轴独立包含参数、DG4000 通道、显示单位、扫描起点、扫描步长和扫描点数。轴可增加、删除、上移和下移；同一 `通道 + 参数` 不能重复出现。最多 10 个轴，联合点表最多 10000 行。

- 同步联动：各轴必须具有相同点数，第 `i` 个值组合成联合点 `Pi`。适合频率和幅度同时递增、频率和相位同步变化等实验。
- 组合扫描：生成所有轴的笛卡尔积，总点数是各轴点数乘积。轴 1 是慢轴，最后一个轴是快轴；使用上下移动按钮可改变嵌套顺序。

生成前的“点表预检”会显示联合点总数和每触发 SCPI 条数，并阻止点数不匹配、重复目标或总点数超限。修改轴配置后必须重新生成点表；任务运行期间轴、单位和表格会锁定。

### 10.4 自动生成联合点表

每个轴提供三个扫描参数：

- 扫描起点：第一个触发下发的参数值。
- 扫描步长：相邻点的差值；正数为递增扫描，负数为递减扫描，零表示重复同一个值。
- 扫描点数：该轴生成的数值数量，范围为 1 至 10000。

单个轴的第 `i` 个值按下式计算，其中 `i` 从 0 开始：

```text
point[i] = start + step * i
```

软件用十进制运算生成点位，避免小数步长出现连续累加尾数。例如起点 `0.1`、步长 `0.1`、点数 `4` 会生成 `0.1, 0.2, 0.3, 0.4`。生成后表格仍可逐格修改，也可用“添加联合点”和“删除选中”制作非等间隔序列；再次生成会替换当前表格。

### 10.5 首触发与循环

对于序列 `P0, P1, P2`：

| 累计触发序号 | 下发点 | 说明 |
|---|---|---|
| 任务刚启动 | 不下发 | 等待第一个触发 |
| 1 | P0 | 按轴顺序批量下发并保持联合起始点 |
| 2 | P1 | 第一次推进 |
| 3 | P2 | 到达末点 |
| 4 | P0 | 回到起始点 |
| 5 | P1 | 继续循环 |

通用公式为：

```text
index = (trigger_number - 1) mod point_count
```

### 10.6 为什么不设置最小触发间隔

NI 计数器在硬件中累计边沿。假设软件上一次读到 100，下一次读到 108，说明期间出现了 8 个触发。控制器不会只处理最后一个，也不会认为它们同时发生，而是生成 101 至 108 八个连续序号并按顺序下发。

软件读取周期只影响界面何时得知最新累计值，不构成输入死区。真正的速度瓶颈通常是：

- USB/LAN/VISA 往返时间。
- DG4000 命令解析与参数生效时间。
- 操作系统线程调度。
- 同一 VISA 会话上的其他命令。

### 10.7 积压含义

```text
backlog = received_count - applied_count
```

- 积压为 0：写入线程已经追平。
- 积压增长：触发产生速度高于 SCPI 下发速度。
- 积压下降：触发停止或变慢，写入线程正在追赶。
- 积压不会自动提高仪器吞吐，也不能保证参数在原始触发时刻生效。

### 10.8 开始和停止

开始任务前检查：DG4000 已连接、NI 设备存在、计数器和 PFI 正确、联合点表已重新生成、PSK/FSK 模式已配置，并确认仪器频率/相位/幅度耦合已关闭。每次布防在 NI 计数开始前查询一次耦合，并对 CH1/CH2 各读取一次 `FUNC?` 实际波形。后续输出频率点按型号和这份波形快照检查上限；每点零查询、一次 SCPI 写入，也不预先下发 P0。运行中不要从面板或其他应用更换波形或耦合；外部改动后应先停止、核对状态并重新布防。

点击“停止”后，软件先通知取消，再在后台等待启动预检查、计数监视、参数写入和 NI 计数任务清理完成。若启动调用仍在线程池排队或处于“启动中”，点击停止先保留取消请求，等对应启动调用及回调结束后再派发停止清理，不会接着开启写线程。回调只作用于提交时的那一个任务，不会清除后来新任务的控制器或占用。界面仍可响应；已经提交给 VISA/厂商驱动的调用不能被软件强制撤回。

若等待超时或 NI 计数任务未能确认关闭，启动按钮保持“等待停止”，停止按钮改为“重试停止”。此时控制器及设备占用仍保留，不能启动另一任务、执行手动命令或关闭窗口。等待原调用返回，排除报告的 NI 清理问题后，再点击“重试停止”；确认停止完成后才能继续。不要根据收到数停止增长或界面显示错误判断资源已经释放。

后台线程池若拒绝派发启动任务，软件会撤销该次启动占用并恢复可操作状态。若拒绝派发停止任务，则保留控制器及占用供“重试停止”；这类错误不会自动重发仪器命令。

停止不会自动关闭 DG 输出，也不回滚可能已接受的参数。若 DG 连接在任务期间断开或重建，旧任务的耦合检查与波形快照随之失效，软件会拒绝继续用它写入；确认停止、重新连接并核对仪器状态后重新布防，不恢复旧触发积压。

## 11. 跨设备联动任务中心

### 11.1 扫描目标和点表

跨设备扫描轴的唯一目标是 `设备 ID + 通道 + 参数`。因此两台 DG 的 CH1 频率是两个独立目标，同一台 DG 的 CH1 频率和 CH2 频率也是两个目标；完全相同的目标不能重复添加。每个轴继续支持小数、单位换算、同步联动和笛卡尔组合，联合点总数上限为 10000。

任务保存到 `linkage_tasks.json`，内容包括 NI 触发源、计数器、PFI、边沿、组合方式、设备下发方式、全部扫描轴以及当前表格中的显式联合点。加载时若引用设备已经被删除，预检会阻止启动，不会把轴静默绑定到其他设备。

### 11.2 启动预检和设备占用

启动前软件检查：点表没有过期、NI 和所有参与 DG 均已连接、任务引用的设备仍存在，并原子占用全部参与设备。任一资源已被单设备触发、NI 独立计数、NI 模拟采集或另一个跨设备任务占用时，本任务不会取得部分资源，而是整体启动失败。只有启动与工作线程全部结束、NI 清理确认完成后才释放占用。停止超时或清理失败时保留任务及设备，点击“重试停止”完成清理后再启动或关闭；正在启动时也可提交取消。

### 11.3 严格顺序和完成屏障

当前首页跨设备任务中心只开放 DG4000 “严格顺序下发”：按扫描轴中设备首次出现的顺序执行，每台设备内部的参数作为一个受锁 SCPI 批次。协调器在所有设备完成前不会把本触发记为已应用，也不会开始下一个积压触发。Vaunix 与 NI 的频率/功率扫描位于 Vaunix 专用设置窗口。

```text
NI 累计触发 N
-> 选择联合点 P[(N-1) mod 点数]
-> DG-A 参数批次
-> DG-B 参数批次
-> ...
-> 全部完成
-> applied_count = N
```

“完成偏差”是本联合点各设备批次完成时间最大值与最小值之差，只用于软件时序诊断，不能解释为输出边沿之间的精确电气偏差。

### 11.4 部分下发失败和途中停止

如果 DG-A 成功而 DG-B 失败，界面显示“部分下发失败”，任务停止推进，失败点不增加 `applied_count`。运行 CSV 以 `partial_error` 保留已成功设备、失败设备、各自耗时和错误。

如果用户在 DG-A 写入期间点击停止，须先等 DG-A 的当前调用返回；停止请求不会再启动尚未下发的 DG-B 等设备。未完成全部设备的点以 `partial_stopped` 写入 CSV，保留已执行部分，不增加 `applied_count`。若本点所有设备实际已经成功返回，则可正常计为完成；停止后的其他积压不再启动。

已经接受的参数无法由 VISA 自动撤销。排除故障或停止完成后，核对全部仪器的实际状态，再从 P0 重新启动。停止按钮不承担关闭 RF/通道输出的功能。

### 11.5 运行日志

日志自动保存在软件配置目录的 `run_logs` 子目录，CSV 使用 UTF-8 BOM，字段包括触发序号、点序号、UTC 下发时间、完成时间、总耗时、设备完成偏差、状态、各设备耗时和错误。已有空文件在首次写入时补齐列头。任务定义与运行日志分开保存，删除任务不会删除历史运行日志。

本点设备操作返回后，软件先保留真实设备结果；只有全部设备成功才增加完成计数，然后写 CSV。如果磁盘满、目录权限或其他文件错误导致 CSV 失败，任务停止后续点，保留界面中的本点完成/部分执行情况及原始设备错误。此时 CSV 可能没有最后一条记录，“完成计数”不等于日志已经落盘。不要因日志缺行而自动重放本点，应先记录界面错误和设备实际状态，修复保存路径后重新准备实验。

## 12. 实机联调步骤

0.7.15 的 DG4000 + NI 触发、CH2 通道隔离、单位/波形范围、重连身份及停止边界见[专项说明](DG4000_TRIGGER_AUDIT_CN.md)。启动步进前须关闭仪器频率/相位/幅度耦合；软件仅检查，不自动关闭。扫频和脉冲串现在分别选择 CH1/CH2，不能根据其他页面当前通道推断目标。运行时先停止任务，再执行手动设置或原始命令；0.7.17 专用的频率/幅度只读回读按钮可按第 7.2 节进行单次查询。

1. 在 NI MAX 中测试 DG4000 `*IDN?`。
2. 在 NI MAX 中确认 NI 设备和 PFI 端子。
3. 首页添加 DG4000、NI；如使用 Vaunix，再通过 DLL 自动搜索添加并连接，核对序列号和型号能力。
4. 关闭 DG4000 输出，设置基本波形并查询回读值。
5. 用 NI 独立计数页面验证外部边沿。
6. 先设置单轴两点低速序列，再增加第二轴验证联合下发。
7. 单步产生触发，核对第一个触发为第一个点。
8. 验证末点后循环。
9. 逐步提高触发速率并监视积压。
10. 在 NI MAX 中先验证模拟输入通道、端接方式、量程和采样率，再用软件选择连续记录路径并进行短时采集；运行期间确认文本文件大小和“已写入文本”计数持续增加。
11. 当前版本通过设备占用锁禁止同一 NI 同时运行计数/联动与模拟输入任务；请先停止当前任务，再启动另一条任务路径。
12. Vaunix 先关闭 RF 验证频率、绝对功率、扫频/选件能力回读，再用 NI 单步验证频率/功率点表的首触发 P0 和循环。
13. 确认安全后再开启输出并接入实验电路。

## 13. 故障排查

| 现象 | 可能原因 | 处理方法 |
|---|---|---|
| 搜不到 DG4000 | 未安装 PyVISA/VISA Backend、USB/LAN 未连接 | 安装驱动，在 NI MAX 中确认资源，或手动输入地址 |
| 搜不到 NI | 未安装 NI-DAQmx Python 或设备别名不同 | 安装依赖，按 NI MAX 中名称填写 `Dev1` |
| 搜不到 Vaunix | DLL 不存在、位数不匹配、USB 未连接或设备被其他程序占用 | 使用 SDK 的 `x64\Release\vnx_fmsynth.dll`，设置 `VAUNIX_LMS_DLL`，关闭厂商示例程序后重新搜索 |
| Vaunix 序列号找不到 | 保存的设备已拔出、插入了另一台设备或资源手工输入错误 | 重新搜索并核对 `VAUNIX::LMS::<序列号>`，不要改用临时设备句柄 |
| Vaunix 功率与预期不符 | 把绝对 dBm 当成相对衰减、误把 0.25 dB 编码当成实际分辨率、型号量程不同或外部链路损耗 | 使用 0.5 dB 网格的绝对 dBm；查看总览实际范围并独立校准外部链路 |
| Vaunix 功能按钮不可用 | 当前型号不报告快速脉冲、Chirp 或 BLX 序列能力 | 以连接后的能力读取为准；不可用功能不会强制下发 |
| 连接失败 | 地址错误、设备被占用、网络不可达 | 刷新、断开其他程序、执行 `*IDN?` 测试 |
| 触发数一直为 0 | PFI/边沿/地线错误、计数器未启动 | 检查接线和有效边沿，先用独立计数页面验证 |
| 收到数增加但下发不增加 | DG4000 断开、SCPI 错误、写线程停止 | 查看状态栏和错误队列，确认停止完成后重新连接并布防 |
| 按停止后显示“等待停止 / 重试停止” | 启动、VISA 写入尚未返回，或 NI 清理失败 | 保留窗口和占用，等待后台返回并排除 NI 错误，再点击“重试停止” |
| 连接恢复后旧任务拒绝写入 | 任务布防时的连接、耦合检查和波形快照已失效 | 完成停止，核对仪器状态后重新布防，不重放旧积压 |
| 积压持续增长 | 触发快于 SCPI 吞吐 | 降低触发速度或接受延迟，不能靠软件消除物理瓶颈 |
| 同资源记录无法连接或编辑/删除被拒绝 | 另一记录已连接、后台连接/断开中，或设置窗口仍占用设备 | 保留当前窗口，完成停止并断开后重试，勿新增同地址别名 |
| 完成计数已增加，但 CSV 报错或缺末行 | 仪器下发成功，随后日志写入失败 | 保留实际完成状态，修复磁盘/权限，不自动重放本点 |
| PSK/FSK 没有效果 | 调制模式未启用或目标通道错误 | 先配置载波、调制类型和通道，再启动步进 |
| 资源被占用 | NI MAX 或其他程序占用计数器/VISA | 关闭测试面板和其他会话，重新连接 |
| 没有模拟通道 | 设备不带 AI、驱动未识别或设备名错误 | 在 NI MAX 查看物理通道；以驱动枚举结果为准 |
| 模拟采集启动失败 | 端接方式/量程/采样率不受支持，或通道被占用 | 改用设备默认端接，降低采样率，检查量程并关闭其他任务 |
| 模拟采集报错且窗口不能关闭 | 读取线程、NI 任务或文件清理仍未完成 | 保留窗口和错误，待后台返回、排除对应原因后重试停止；不要另开同卡任务 |
| 原生清理未确认，重试停止仍失败 | NI-DAQmx 关闭报错后丢失原生句柄，当前进程无法确认释放 | 结束本次实验，在 NI MAX/驱动层核对资源后重新启动软件；不恢复旧句柄或另开任务 |
| 已接收点数大于已写入文本点数 | 某块写入或刷新未确认成功 | 保留原文件检查尾部，不重放失败块；完成停止后选择新文件重新采集 |
| 波形削顶 | 信号超过设置量程 | 停止采集，扩大输入量程并确认不超过硬件绝对最大额定值 |
| DG 方波/脉冲频率低于型号总上限仍被拒绝 | 所选波形有更低的频率上限 | 对照第 7.2 节按型号和波形设置，不按正弦最高频率推断 |
| DG 重连后提示身份变化 | 资源连接到不同型号或序列号 | 完成停止，核对地址和身份，重新读取身份或断开重连，再重新应用或布防 |
| 后台启动/停止派发失败 | 线程池未接受本次任务 | 读取报错；未启动的任务不会自动重发，已有任务仍按停止未完成状态保留并允许重试 |
| 丢弃点数增长 | 内存绘图缓存已满 | 这是正常的长时间采集行为；确认“已写入文本”仍增长，磁盘连续文件不会随缓存丢弃而截断 |
| 已写入文本不增长 | 未启用连续记录、磁盘不可写/已满，或采集任务出错 | 检查勾选项、保存路径、剩余空间和状态栏错误；修复后新建文件重新开始 |
| 中文显示方框 | Qt 未加载中文字体 | 软件会主动加载 Noto Sans SC/微软雅黑/黑体，检查 Windows 字体文件 |
