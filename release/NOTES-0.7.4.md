# Lab Control Center 0.7.4 发行说明

日期：2026-09-28；平台：Windows 10/11 x64。

## SSG3021X USB 调制状态查询超时

用户截图确认连接后的状态读取在 `:OUTPut:MODulation?` 上发生 `VI_ERROR_TMO (-1073807339)`。身份识别及此前的 RF 查询已执行，但软件把这次调制查询当作连接的必要步骤，超时后关闭会话且没有显示已识别身份。截图不是参数下发失败，也不能据此判断 USB 硬件损坏或仪器不支持调制。

普通 SSG3000X 编程手册 C01A 第 3.4.7.1 节、印刷页 54 / PDF 第 58 页，将 `:MODulation?` 列为主命令和示例，把 `:OUTPut:MODulation[:STATe]?` 列为等效命令。0.7.4 按主命令接入普通型号；没有断言等效命令在所有固件上都不支持。

- SSG3021X / SSG3032X 调制总开关的设置、校验、状态读取和脉冲 BUS 前置检查统一使用 `:MODulation` / `:MODulation?`。其他已接入型号的命令分支保留。
- 连接、常规刷新、RF 操作和扫描轮询读取基础 RF/扫描状态，不自动查询调制、脉冲、IQ/ARB 状态。
- 调制页增加“读取调制状态”；应用调制及显式详细读取仍查询调制。未读取时显示“尚未读取”，读取后显示时间和“需手动刷新”，不把未知值显示为关闭。
- 已识别的型号、序列号和固件独立显示；后续通信失败时仍保留最近身份并标明当前未连接。
- 显式调制查询若仍超时，继续记录具体命令并关闭会话，避免迟到回复错配；不会自动改命令、重发配置或触发。可重新点击基础连接，再核对诊断报告。
- 保留 0.7.3 的回调异常隔离、原始回复和 traceback、原生崩溃日志，以及 dBm / mV / mVpp。

## 验证与使用

全量 **247 项源码回归通过**；新增 5 项覆盖主命令读写/BUS、全部调制查询失败时基础读取、真实连接按钮/RF/扫描轮询、独立调制按钮不应用编辑，以及显式超时后的错误与基础重连。独立普通型号后端现在拒绝超时的等效查询，避免仅凭宽松虚拟解析器判断兼容。

目录包、单文件和 ZIP 二次解压自检新增 SSG3021X 身份、等效命令超时模拟、基础连接隔离和主命令显式读取；构建清单记录结果。没有访问真实 USB 仪器，主命令在用户固件上的实际回复待现场验证。

完整解压 `Lab-Control-Center-0.7.4-windows-x64-portable.zip` 后启动 `Lab Control Center.exe`。关闭旧版后将旧 `data/` 复制到新版 EXE 同级，保留旧目录，不混用 `_internal/`。内置 Python/Qt，真实 USB 仍需系统 VISA 驱动。

先点“连接 / 读取身份”，确认基本频率、幅度、RF 和扫描状态；需要调制回读时到“模拟调制”页点“读取调制状态”。若仍超时，取 `data/diagnostics/siglent-*.json`，核对失败命令是否已经变为 `:MODulation?` 及软件版本是否为 0.7.4。
