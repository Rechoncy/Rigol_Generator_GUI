## 发现更新后自动下载

延续 0.7.21 的 GitHub 正式版后台检查，增加默认开启的“发现更新后自动下载”。发现更高版本且存在可验证的适用附件时，后台下载对应 Windows x64 ZIP 或 EXE，在首页底部显示进度；支持取消、手动重试和打开文件夹。自动检查与自动下载可分别关闭，网络异常只显示更新状态，仪器功能继续离线使用。

单文件 EXE 运行时选择相应版本的独立 EXE；目录便携版和源码选择便携 ZIP，更新区显示当前格式。只接受本仓库该版本的规范附件来源，保存到当前数据目录的 `updates/v版本号/`。GitHub API 的字节数和 SHA-256 必须有效，实际下载必须两者均匹配才标为完成；没有适用附件、缺少校验信息或元数据不一致时，保留版本提示和“打开发布页”，不进行自动下载。同名现有包先校验，匹配则复用，内容不同则保留原文件并报错。

下载与仪器工作队列独立，采用有界单工作者、30 秒网络等待限制和含系统代理解析的 10 分钟总期限。取消、超时或关闭后丢弃迟到结果，不等待原生网络结束，也不在原工作者仍存活时无限创建线程。使用 HTTPS 证书验证与系统 HTTP 代理/PAC，按实际附件 URL 及允许的 GitHub 重定向分别解析系统代理，不把 API 域名的代理结果套用于下载域名，也不修改全局代理；自动下载暂不支持 SOCKS，可用发布页转到浏览器下载，版本检查自身仍使用 Qt 的代理支持。无需登录或访问令牌，不上传设备、参数或实验数据。

程序不自动解压、安装、执行下载文件或覆盖运行中的程序和旧包。完成后可点击“打开下载文件夹”；由用户先导出配置、停止任务并退出旧版，再将新 ZIP 解压到新目录或放置新 EXE，复制原 `data/` 或导入配置。下载完成不等于已经更新运行版本，重新打开后核对窗口标题。取消或失败会尝试清理 `.part` 临时文件；进程异常退出可能留下未完成文件，该文件不会作为可用更新显示。完整操作见[使用说明](../docs/USER_MANUAL_CN.md#44-联网检查软件更新)。

自动检查/下载偏好保存在当前数据目录的 `update_settings.json`，保留原自动检查偏好；该本机文件与下载附件不随设备配置包导入导出。修复深层 JSON 偏好文件可能触发 `RecursionError` 而中断启动的问题：读取异常时暂停自动检查/下载并显示错误，仍可手动操作更新功能。完整复制 `data/` 时可携带已下载的包及偏好。
