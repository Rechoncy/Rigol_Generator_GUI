# Lab Control Center 0.7.3 发行说明

日期：2026-09-26；平台：Windows 10/11 x64。

## SSG 连接完成后闪退修复

用户报告点击“连接 / 读取身份”后闪退。已在虚拟连接中复现一条确定的崩溃路径：幅度回复不能转换为数值时，界面完成回调抛出未捕获异常，冻结入口随后退出整个程序；同时忙状态和临时占用未清理。这条缺陷可以解释相同症状，但本地没有用户本次闪退日志，不能据此断言实机一定返回了异常幅度。

- 隔离连接、刷新和其他 SSG 操作的结果处理回调异常，显示错误并保存完整 traceback，避免异常逃出 Qt 回调而退出程序。
- 状态显示前保存原始回复；诊断报告保留导致格式转换失败的 `:POWer?` 回复，包括空值、非数字、NaN/Infinity 和无法换算的幅度。
- 完成回调始终清理忙状态；没有扫描运行证据时释放临时占用。实际扫描已启用时仍保留占用，成功回读 OFF 后释放。
- 回调失败后仍执行排队的停止 / RF 关闭；排队操作开始前不能关闭窗口。
- 交互式 EXE 增加 `logs/runtime-fault.log`，由 Python faulthandler 记录可捕获的原生崩溃线程栈。目录不可写时回退到 `%LOCALAPPDATA%/RigolGeneratorControl/logs/`。它提供诊断，不宣称修复系统 VISA DLL。
- 便携包自检实际点击 SSG 连接按钮，注入异常回复、核对诊断保存与占用释放，恢复正常回读并确认 RF 仍关闭。此前仅打开虚拟窗口的检查没有覆盖这条异常路径。
- 保留 0.7.2 的 dBm / mV / mVpp 和 0.01 dB 幅度回读校验。

## 使用与诊断

完整解压 `Lab-Control-Center-0.7.3-windows-x64-portable.zip`，启动 `Lab Control Center.exe`。内置 Python/Qt，不依赖外部 Python；真实 USB 仪器继续使用系统 VISA 驱动。

升级时关闭旧版，将旧 `data/` 复制到新 EXE 同级，不混用两版 `_internal/`。保留旧目录供对比。

若窗口显示错误但程序仍运行，查看 `data/diagnostics/siglent-*.json`。若程序仍退出，保留 EXE 同级 `logs/startup-error.log` 和 `logs/runtime-fault.log`（存在的文件）；记录软件版本、USB/LAN、设备型号及 Windows 错误事件。空的线程栈日志只有启动时间，不能当作已经确认底层崩溃。
