# 0.7.30：多台 VISA 设备的连接隔离

日期：2026-11-09。状态：源码修复与本地候选，当前公开正式版仍为 [v0.7.29](https://github.com/Rechoncy/Rigol_Generator_GUI/releases/tag/v0.7.29)。本次未创建标签或 GitHub Release；候选的构建、验证和本地交付以本轮实际记录及同组 `release-manifest.json` 为准。

## 用户现象与可确认的问题

用户使用 0.7.29 连续运行十几天后，连接 RIGOL 时出现 `SCPI 查询失败 [*IDN?]：VI_ERROR_TMO (-1073807339)`。错误表示身份查询在超时前未获得有效回复。截图不足以确定实际 USB、驱动或仪器端的直接原因，也不能由此断言软件存在固定十几天的失效周期。其他设备卡片显示“可用”只是此前探测结果，不能代替当前通信验证；GitHub 更新检查的网络失败是独立问题。

源码审查和共享资源管理器替身确认一个连接隔离缺陷：同一 PyVISA 库的 `ResourceManager()` 可复用共享管理器，其 `close()` 会关闭其他调用者打开的资源。原软件在断开一台 VISA 仪器、打开失败清理、搜索资源结束和临时探测结束时直接关闭 manager，可能使其他持久连接失效。无需等待十几天即可用两台模拟仪器复现这一软件问题；该复现仍不能证明用户此次实机超时唯一由它引起。

依据为 PyVISA 官方 [ResourceManager API](https://pyvisa.readthedocs.io/en/stable/api/resourcemanager.html) 对共享会话关闭行为的说明及本地已安装库源码。

## 本版改动

- 所有应用内 VISA 入口统一租用资源管理器，按共享对象维护使用计数，只有最后一个使用者释放后才关闭管理器。
- 断开一台只关闭该仪器资源，其他活跃连接继续持有管理器；资源搜索、临时探测及各失败清理路径也遵循相同规则。重复清理不重复释放；并发获取与最后释放串行保护，仪器查询不持有全局生命周期锁。
- DG4000、SSG 和通用 SCPI 的 VISA 路径适用。Vaunix SDK、NI-DAQmx 和 Newport 串口路径保持各自生命周期。
- 保留现有回复同步、自动回读暂停、Vpp/mVpp 跟随与原生 dBm/Vrms 规则，以及 DG/Vaunix 首触发 P0、有序计数、CH2 隔离、停止失败保留占用、SSG 原生扫描与恢复流程。

本版不加入定时重连、复位、清缓冲、额外身份轮询或未知结果命令重放，不根据截图猜测协议或延长查询超时。

## 当前故障的恢复步骤

1. 先停止涉及的 NI 步进/联动或仪器扫描，等待后台通信和清理完成。若停止未确认，保留窗口与占用，按原有“重试停止”处理。
2. 确认收尾后显式断开受影响设备，再连接并手动回读。核对频率、幅度和输出状态后重新布防；软件不补发旧任务积压或未知接受结果的参数。
3. 仍超时时，只在实验空闲且程序能够正常退出后重启应用。若仍失败，检查 USB 连接、系统 VISA 中的资源识别，并保留完整错误、仪器型号和固件信息。运行中的实验不以拔线或强制退出代替停止确认。

候选修复不能恢复当前已失效的旧进程会话；换用新版前仍需要正常完成任务收尾并保留原数据。总操作见[连接生命周期](../docs/USER_MANUAL_CN.md#43-连接生命周期)。
