# Lab Control Center 0.7.24

日期：2026-10-28；平台：Windows 10/11 x64。
发行目标：[v0.7.24 GitHub Release](https://github.com/Rechoncy/Rigol_Generator_GUI/releases/tag/v0.7.24)。本次按用户授权完成补丁、检查并发布，构建与上传结果以实际工作流和发布页为准。正式附件本地副本目录为 `dist/published/v0.7.24/`；已发布的 v0.7.23 及其本地正式附件、开发包和历史版本全部保留，不覆盖。

## 修复保存的虚拟设备重新启动时的探测

设备中心重新打开已有配置时，会后台探测未连接的设备。此前 SIM DG4000 被送入真实 `pyvisa.ResourceManager`，SIM NI 被送入真实 `nidaqmx.system.System.local`，可能加载目标电脑的 VISA/DAQ 驱动，并使虚拟设备显示错误的离线状态。

本版将内置虚拟设备的启动探测保持在虚拟实现中，不加载上述真实驱动入口。修复不更改真实仪器的协议、触发顺序、CH1/CH2 下发或扫描配置，也不通过启动恢复仪器连接、开启 RF 或启动任务。

## 旧版如何升级

| 当前版本/格式 | 可用更新方式 | 首次改用安装版 |
|---|---|---|
| 0.7.20 | 没有联网更新入口，手动打开 GitHub 发布页 | 下载并手动运行 Setup，选择旧数据目录 |
| 0.7.21 | 检查并提示新版，打开发布页下载 | 下载并手动运行 Setup，选择旧数据目录 |
| 0.7.22 便携 ZIP/独立 EXE | 可自动下载并校验 ZIP/独立 EXE；仍需手动迁移 | 另外下载并手动运行 Setup，选择旧数据目录 |
| 0.7.23 及后续安装版 | 可下载、校验并在设备空闲且正常退出后安装更高的正式版 | 已是安装版，沿用当前实际数据目录 |

旧便携版的实际数据目录通常是 EXE 旁的 `data/`；如果曾用 `--data-dir` 或 `RIGOL_GUI_DATA_DIR`，应选择当时的实际目录。先停止任务并退出旧程序，再运行 Setup。未登记的旧便携程序不会被当作已安装旧版卸载，不要删除其包含用户数据的父目录；确认迁移完成前保留原包。程序与数据目录应分开。

旧版 schema 1 的 `update_settings.json` 没有 `automatic_install` 字段时，新版保留原有检查/下载选择，并为安装选项采用默认值；正常读取不会重写旧设置文件。安装版后续更新仍先备份数据，保留原文件，核对并恢复缺失文件，冲突则报告并保留现场。

## 已确认的复现与验证边界

- 使用真实 0.7.22 源码快照的更新界面，检测并自动下载了正式 v0.7.23 便携 ZIP，32.764 秒，57,201,473 字节；原有配置字节不变。该记录证明旧版的下载流程，不能称为旧版已自动安装。
- 使用正式 v0.7.23 发布载荷、单独测试 AppId 重新封装安装器，实测首次选择上述旧数据目录。原设备、DG 双通道参数、更新偏好、测量文件、下载 ZIP 及目录均保留，文件 SHA-256 不变，安装标记沿用原目录。这是便携版首次迁移，不是历史 0.7.22 安装器升级。
- 随后的 v0.7.23 `--smoke-test` 在 180 秒内未退出，因此该轮完整启动/重装验收没有通过。独立复现以正式源码和私有数据副本替换两个真实驱动入口：立即返回时正常退出；各延迟 4 秒时界面心跳正常，探测结束后再次关闭可正常退出。结果指向启动探测占用使唯一一次定时关闭被拒绝，不能据此声称界面主线程死锁或数据丢失。
- 本次修复的源码回归、保存 SIM 配置后重新启动、自检和冻结/安装验证使用 0.7.24 自身的记录，不用上述 0.7.23 结果替代。新记录保存在 `dist/verification/0.7.24/`；本版的具体测试结果、构建源提交和附件校验值以实际日志及正式 `release-manifest.json` 为准，当前说明不预写未来通过结果。
- 新回归先复现了 9 处失败，修复后连同现有探测/连接测试共 12 项通过。完整源码回归执行 669 项，80.314 秒，结果 OK，其中 1 项符号链接测试因本机权限跳过。源码虚拟自检新增“保存六台 SIM 后重新打开设备中心”检查，确认全部可用、不自动连接、不调用真实后端、原配置字节不变且正常关闭。同一份旧数据以修正后的源码在原生 Windows 界面完成启动自检，1.280 秒退出，七个原有文件的 SHA-256 全部保持不变。
- 新增手动触发的 `Published installed automatic upgrade` 工作流，只允许在全新 GitHub 托管 Windows 临时环境运行真实生产安装器，本机执行会拒绝。其目标是从已发布的真实 v0.7.23 安装版正常启动，经实际 GitHub 更新下载、安装、数据恢复与重启升级到最新正式目标版本；该额外端到端结果以工作流及其证据附件为准，不能以静态检查替代。

旧版迁移复查与受控诊断保存在 `dist/verification/0.7.23-upgrade-recheck/`。测试只使用 SIM 配置、私有副本和隔离安装身份，不自动操作真实仪器。保留 DG/Vaunix 首触发 P0、有序累计计数、CH2 隔离、停止失败保留占用、未知接受结果不自动重放，以及 SSG 原生扫描和恢复规则。
