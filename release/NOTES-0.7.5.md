# Lab Control Center 0.7.5 发行说明

日期：2026-09-28；平台：Windows 10/11 x64。

## 运行版本与程序来源核对

用户确认完整解压 v0.7.4 后仍遇到 `:OUTPut:MODulation?` 超时。重新执行本地 v0.7.4 EXE 自检、比对 ZIP 内 EXE，并检查内置 PYZ 字节码，均确认普通型号主命令、基础读取隔离及失败时保留身份已打入该本地文件。现场实际 EXE 和诊断报告尚不可见，因此不能断言用户启动了旧版，也不能认定仪器固件或 USB 驱动是根因。

本轮发现并修复了版本辨认问题：主界面此前将 v0.6.0 写死，无法用于核对实际版本。

- 主窗口、所有设备设置窗口标题和主界面页脚统一显示当前实际版本 `v0.7.5`。
- SSG“状态与诊断”页显示可复制的软件版本、运行程序和加载模块路径；初始化日志同步记录。
- 错误诊断 JSON 增加 `executable`、`module_path`、`frozen`，保留原有 `software_version`、型号、固件、失败命令和回读。
- 保留 v0.7.4 的 SCPI 修正：SSG3021X / SSG3032X 总调制使用 `:MODulation?`；基础连接、RF 操作和扫描轮询不查询调制。没有根据相同截图再次猜测命令。

## 验证与现场使用

全量 247 项回归通过。目录包、单文件和 ZIP 二次解压自检除原有模拟 USB 超时、连接按钮和回调异常用例外，还检查 7 个窗口的版本标题及诊断报告中的运行身份。打包程序使用内置 Python/Qt；真实 USB 仍需系统 VISA 驱动。没有连接真实仪器，现场问题仍需实际运行信息确认。

建议直接运行独立文件 `Lab-Control-Center-0.7.5-windows-x64.exe`，或把便携 ZIP 完整解压到一个新文件夹。关闭旧进程后启动，确认设备窗口标题包含 `v0.7.5`；保留旧目录，需要配置时只复制旧 `data/` 到新 EXE 同级。

先点击“连接 / 读取身份”。若仍失败，在“状态与诊断”页保存报告，提供新 EXE 同级 `data/diagnostics/siglent-*.json`。报告同时包含错误和实际程序位置，后续应据此定位；不要仅凭压缩包名称判断正在运行的模块。
