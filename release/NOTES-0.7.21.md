## GitHub 正式版更新提示

首页底部增加独立的软件更新区，显示当前运行版本、检查状态和自动检查偏好。正常启动约 3 秒后异步检查项目 `Rechoncy/Rigol_Generator_GUI` 的最新正式 Release，保持运行时每 6 小时检查一次；用户可关闭“启动后自动检查更新”，或随时手动点击“检查更新”。同一时间只发送一个检查请求。

版本按数字比较，只在正式发布版本高于当前运行版本时提示。预发布、草稿、开发分支提交和裸标签不触发正式更新；本地开发版高于 GitHub 正式版时不会提示降级。新版提示保留在首页，点击“打开发布页”才打开相应 GitHub 页面，不弹出阻塞仪器操作的模态窗口。

检查使用 HTTPS、系统代理和服务器证书验证，读取公开发布元数据，无需登录或访问令牌；不上传仪器地址、参数、采集数据和配置，也不修改全局代理。异步请求限制回复大小，最长约 15 秒；离线、网络异常、限流及无效回复以更新区状态呈现，原有仪器功能继续工作。自动偏好保存在当前数据目录的 `update_settings.json`，与设备配置包分开。

软件不自动下载、安装或覆盖运行文件。升级时停止任务并退出旧版，将新版解压至新目录，再复制 `data/` 或导入已导出的配置，保留旧程序与数据备份。详细操作见[使用说明](../docs/USER_MANUAL_CN.md#44-联网检查软件更新)。

## 实现与验证范围

源码、目录便携包和单文件 EXE 共用同一检查实现。仅普通交互启动自动联网，默认单元测试、`--smoke-test` 和冻结自检不访问 GitHub；回归使用受控网络替身验证版本判断、超时、错误及界面生命周期，不以测试结果代替目标电脑网络可达性。

核对 Qt 6.11.2 实现后，修复了两个实际检查路径的问题：Qt 异步 HTTP 的首次系统代理查询仍可能在界面线程同步执行 Windows PAC/WPAD，导致界面定时器及超时处理一起延迟；现在把代理解析放入独立守护线程，使用界面侧总期限和代次检查丢弃迟到结果，已超时的原生解析未结束时不再增加线程。真实 HTTPS 验证还发现 PyQt 在回复 EOF 时的 `read()` 可返回 `None`，原先按字节直接转换会抛异常；现按无新增数据处理，并加入回归。两处修复均不占用仪器工作队列、不绕过 TLS 或更改系统代理。依据为 Qt 官方的[HTTP 回复实现](https://raw.githubusercontent.com/qt/qtbase/v6.11.2/src/network/access/qnetworkreplyhttpimpl.cpp)和[Windows 代理实现](https://raw.githubusercontent.com/qt/qtbase/v6.11.2/src/network/kernel/qnetworkproxy_win.cpp)。
