# Lab Control Center 0.7.13 发行说明

日期：2026-10-23；平台：Windows 10/11 x64。

本版完善 DG4000/Vaunix 的 NI 触发步进及跨设备任务在停止、启动取消和连接恢复时的处理。保留 0.7.12 的触发发现优化、CH2 通道隔离、累计边沿顺序和首触发 P0 规则。

## 停止结果与设备占用

- 后台启动检查、计数监视、参数写入和 NI 计数任务清理全部结束，才判定任务已结束并释放设备占用。
- 停止等待超时或 NI 清理失败时保留原控制器和设备租约。界面显示“等待停止 / 重试停止”，阻止重新启动和关闭窗口；原调用结束或清理条件恢复后，可点击“重试停止”完成剩余清理。
- 启动预检查或 NI 打开期间点击停止会提交取消，在后台等待当前调用返回，清理部分打开的计数任务，不继续创建写线程。修正 Qt 线程池对应 Python `_DummyThread` 不能 join 的情况，使用启动完成标志等待。
- 已送入 VISA/厂商驱动的当前操作无法强制撤回；停止任务不自动关闭仪器输出，也不回滚可能已经接受的参数。

## 连接恢复和状态显示

- DG 布防写入器绑定当时的连接代次。断开或连接恢复后，原耦合检查失效，旧写入器会在发送点命令前拒绝继续下发，要求停止并重新布防。
- 任务不自动重放旧触发积压。正常逐点路径不新增耦合查询、重连或重发。
- 控制器快照增加创建次序，UI 同时检查任务会话、revision 和累计计数，防止迟到状态覆盖新错误或让计数倒退。显示仍可合并，执行与 CSV 逐点记录不被合并。

## 跨设备中途停止

严格顺序下发在启动下一设备操作前检查停止请求。例如 DG-A 正在执行而 DG-B 尚未开始，点击停止后会等待 DG-A 当前调用返回，不再启动 DG-B。

未完成全部设备的点记录为 `partial_stopped`，保留已执行设备的结果和耗时，不增加 `applied_count`；通信错误仍记录为 `partial_error`。若所有设备实际已经成功返回，本点可正常计为完成。停止后的其他积压点不再执行，恢复实验前应核对各设备的实际状态。

同时拒绝非有限或非正的轮询周期，以及空、重复或与参与设备不一致的执行顺序，避免无效等待或漏发/重复执行。

## 验证范围

本地全量回归和 0.7.13 源码自检通过，新增覆盖停止超时、NI 清理失败后重试、启动期间取消、Qt 线程池启动等待、连接恢复后旧写入器拒绝、乱序状态与跨设备停止后的部分结果。

自检加入 `quiescent_after_stop`、`ordered_snapshot_revisions` 和 `reconnected_writer_blocked_without_io`，源码运行均通过；发行包实际运行证据由 `release-manifest.json` 保存。源码检查、冻结产物检查与实机验收分别记录。

本版未连接或操作实体仪器，也未重新测量硬件触发延迟、仪器吞吐或输出稳定时间。专项说明保留的 0.7.12 模拟基准属于历史结果，不能当作本版实机性能保证。

## 升级与使用

确认旧任务已停止并退出旧程序，再完整解压新 ZIP，复制原 `data/` 或导入配置，核对主窗口和设备窗口标题为 `v0.7.13`。继续提供内置 Python/Qt 和 Vaunix x64 SDK DLL 的目录包与单文件 EXE；VISA、NI-DAQmx 等系统驱动仍按硬件安装。

出现“重试停止”时先保留窗口并完成停止，随后才能迁移、重新连接或启动任务。详细操作见随包 `docs/USER_MANUAL_CN.md`、`docs/DG4000_TRIGGER_AUDIT_CN.md` 和[便携运行说明](README.md)。
