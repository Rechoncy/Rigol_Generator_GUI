# Lab Control Center 0.7.12 发行说明

日期：2026-10-23；平台：Windows 10/11 x64。

## DG4000 + NI 单参数触发提速

- 修正 Windows 下 2 ms 累计计数轮询等待实际接近 15 ms 的问题，内置 Python 3.13 使用高分辨率短等待；不修改系统全局时钟，不忙等。
- 触发状态界面约每 50 ms 显示最新值，避免逐触发 Qt 事件堆积；硬件计数、下发顺序和 CSV 逐点记录保持。
- 多参数联合点以一条包含绝对通道头的 SCPI 消息下发；单参数原本已是一条命令，其收益主要来自触发发现与 UI 减负。
- 每点写入失败立即报错并保持未完成，不自动重连或重发触发点。普通手动设置仍支持一次恢复，恢复后复核耦合。

## CH1/CH2 核对与修复

- 修复扫频/脉冲串页面硬编码 CH1，新增明确的独立通道选择、保存及异步目标固定。
- 布防前一次查询频率/相位/幅度耦合；开启或无法确认时拒绝启动。不会自动关闭全局耦合或重设 CH1。
- 任务期间拦截手动/原始/其他通道命令；先停止任务后再手动操作。每点不增加耦合查询。
- CH2 步进仅发送 SOUR2 目标参数；不复位、同步相位、切换输出或重下发 CH1 配置。

跨设备任务的启动预检查改到后台；启动中点击停止会取消布防，窗口关闭会等待后台返回，避免取消后任务重新启动。

## 验证和边界

全量 **307 项测试通过**。目录包、单文件 EXE 和 ZIP 二次解压检查验证 CH2 25 次触发后 CH1 全状态不变、无丢失累计边沿、耦合布防被拒绝及原有六台虚拟设备功能。

本机模拟每次 VISA write 5 ms、40 次单触发：触发至主机 write 返回均值约 **12.07→6.71 ms**；请求 2 ms 的计数等待实测约 **15.51→2.24 ms**。前者是模拟通信，后者是等待调用耗时，均不是实机触发延迟、RF 稳定时间或实时保证。源码 Python 3.10 保留原等待路径。

运行中勿通过仪器面板或其他软件更改耦合；布防前检查不能持续监控外部修改。首次使用应保持输出关闭，核对 CH1/CH2 后再测量实际输出。详细流程、基准和操作见 `docs/DG4000_TRIGGER_AUDIT_CN.md`。继续内置 Vaunix DLL 和独立 Python/Qt。

退出旧程序后完整解压新 ZIP，复制原 data 或导入配置，核对窗口标题为 v0.7.12。
