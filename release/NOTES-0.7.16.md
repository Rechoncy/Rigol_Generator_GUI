## NI 模拟采集写盘异常

持续检查复现了两条相连的错误路径：保存计数在文件刷新前增加；刷新报错后，错误处理中的再次关闭/刷新可能再次抛错，导致状态仍显示 RUNNING，文件句柄也可能未关闭。

- 连续文本的 saved_samples 只在整块写入并成功刷新后增加，已接收总点数和成功保存数分别保留。
- 写入或刷新失败明确发布 ERROR。文件关闭即使刷新失败也会尝试底层 close，保留原始写盘错误和后续清理错误。
- 底层关闭未确认完成时保留句柄，供显式停止继续清理。失败块可能在文件尾部留下部分内容，不自动补写或重放。

成功 flush 表示 Python 缓冲区已提交到操作系统，不代表断电持久化保证。原连续文件格式和缓存导出方式保持兼容；缓存导出不能修补未确认保存的完整连续数据。

## 停止、资源占用与重试

- 采集控制器区分错误状态和资源静止。启动、读取、清理及 NI/文件资源全部结束前，停止超时或清理失败不会被标成 STOPPED，不会丢弃原控制器。
- 尚未静止时禁止再次 start 或 clear，显式 stop 可以重试；NI 驱动的 Task.close 失败保留原 Task 供后续清理。
- NI 独立模拟采集在后台停止，未完成清理时保留窗口和设备租约，提供停止重试。旧任务迟到回调不能解除新任务占用或覆盖更新的状态。
- 独立 NI 计数停止失败时保留原任务与占用，再次点击停止可重试。Newport 联动在 counter 或 AI 清理失败时保留两个设备的租约，显示“重试停止 / 清理”，确认全部清理完成后再释放。
- Newport 运动 STOP 未确认或状态未知时也保留双方租约，显式重试只停止并核对状态，不重放定位。rotation.csv 的采集块观测写盘回调异常会明确停止采集，避免被普通观察者异常处理静默吞掉。
- Newport 原扫描线程已退出且断连时，使用“重连并停止 / 清理”恢复原任务拥有的连接，仅发送停止并核对状态；不重新归零、定位或恢复扫描，旧位置显示保持未知。
- 快照增加 revision 与 cleanup_pending，帮助界面区分待清理资源并过滤迟到状态。

NI-DAQmx 的特殊边界：实际 Task.close 可能在报错的同时丢失原生句柄，后续再关闭只会空操作。软件对此记录“原生清理未确认”并持续保留任务和占用，不把空操作认作恢复，也不恢复旧句柄。此时需结束实验，在 NI MAX/驱动层核对资源后重新启动软件；当前进程内普通停止重试无法确认释放。仍持有有效句柄的关闭失败继续支持显式重试。

停止失败时保留窗口和错误，待正在进行的读取/系统调用返回，检查 NI-DAQmx 报错、磁盘空间和文件权限后重试。完成停止后核查原文件，新的采集选择新文件。详见[使用说明第 8 节](../docs/USER_MANUAL_CN.md#87-停止异常与恢复)。

DG/Vaunix 首触发 P0、累计有序补发、CH2 隔离和 SSG 原生扫描规则保持；配置与任务 JSON 格式不变。本轮不新增仪器协议或实机性能结论。
